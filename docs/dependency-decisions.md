## Rust to browser contract

CONTRACT owns the public DTOs in `reviewq-protocol` and the generated declarations under `web/src/api/generated/`. Use `schemars` on the Serde wire DTOs to emit one deterministic JSON Schema artifact. Generate TypeScript declarations and executable validators from that artifact in the development build. Check regeneration for drift. Exercise actual serialized Rust bytes with the browser decoder, including a synthetic successful response, an additive field, an incompatible tag, absent versus null and a large identifier. A successful TypeScript compile only checks static callers. [Serde attributes](https://serde.rs/field-attrs.html) · [TypeScript's erased types](https://www.typescriptlang.org/docs/handbook/2/basic-types.html#erased-types)

| Decision | Candidate and tradeoff |
| --- | --- |
| Mechanically generate TypeScript declarations | Select `schemars` and build-only `json-schema-to-typescript` (both MIT). Schemars uses Serde attributes, and both browser outputs consume one schema. Pin the draft and generator options. `ts-rs` (MIT) can derive declarations directly from Rust with no browser runtime. Its output has no runtime validator, and a separate derive would duplicate mapping decisions for nulls, tags and wide integers. Keep one generator for committed declarations. [ts-rs Serde compatibility](https://docs.rs/ts-rs/latest/ts_rs/) · [Schemars](https://github.com/GREsau/schemars) · [Schema-to-TypeScript](https://github.com/bcherny/json-schema-to-typescript) |
| Validate data at runtime | Use the contract’s published schema draft and Ajv standalone (MIT) to generate operation-specific validators ahead of time. Avoid shipping a schema compiler, runtime code generation or a duplicate handwritten Zod/Valibot contract. An explicit small guard fits versioned browser preferences and local URL discriminants. Schema conformance covers shape. The operation still validates selected identities, revision, cursor order and byte limits. Check invalid responses and the actual size of each route's generated code. [Ajv standalone](https://ajv.js.org/standalone.html) · [Supported schema drafts](https://ajv.js.org/json-schema.html) |
| Validate native report handoff JSON | Use `jsonschema` 0.63 (MIT) with default features disabled. Compile the generated local Draft 7 schema once on first use. Its error iterator reports independent field errors. ReviewQ supplies the scope and stable-ID checks. Serde alone stops at the first decode error. Reusing Ajv would add a JavaScript process or runtime dependency to the installed native CLI. [jsonschema crate](https://docs.rs/jsonschema/0.63.0/jsonschema/) |

## Fit and maintenance

Checked upstream documentation and registry metadata on **17 November 2026**. Representative published versions were rusqlite 0.43.0 (declared Rust 1.89), axum 0.8.9 (1.80), Tokio 1.54.1 (1.85), reqwest 0.13.5 (1.85), rmcp 3.11.0 (1.88) and Struson 0.8.0 (1.91). These minima fit the pinned compiler. The registries reported over 29 million recent rmcp downloads and about 139,000 for Struson. The smaller reader earns its place through its streaming-string behavior. Radix dropdown 2.2.1 and React Virtual 3.14.26 declare React/React DOM 19 support with 74.7 million and 44.6 million downloads respectively during 10–16 November. Download counts include repeat builds and transitive use. They establish adoption, while fixture results establish ReviewQ fit. [rmcp registry metadata](https://crates.io/api/v1/crates/rmcp) · [Struson registry metadata](https://crates.io/api/v1/crates/struson) · [Radix package metadata](https://registry.npmjs.org/@radix-ui/react-dropdown-menu/2.2.1) · [Virtual package metadata](https://registry.npmjs.org/@tanstack/react-virtual/3.14.26) · [Radix download snapshot](https://api.npmjs.org/downloads/point/2026-11-10:2026-11-16/@radix-ui/react-dropdown-menu) · [Virtual download snapshot](https://api.npmjs.org/downloads/point/2026-11-10:2026-11-16/@tanstack/react-virtual)

At first use the integration owner selects a compatible release, records direct features and commits the appropriate lockfile. Inspect `cargo tree -e features`, duplicate versions, native/link requirements, transitive licenses and the actual production JS chunks. Review advisories and upstream maintenance, including stable packages whose last release predates this check. Re-run the affected client/host fixture after an upgrade. The release owner includes applicable notices with the built bundle. Measure Rust compile/RSS costs separately from browser transfer, renderer memory and interaction latency. The [browser qualification](plans/06-release/browser-qualification.md) and [packaging brief](plans/06-release/packaging.md) specify those handoffs.
