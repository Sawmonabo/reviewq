# Wire and application contracts

All local product JSON routes use `/api/v1`. One authenticated `/mcp` implements the native Streamable HTTP protocol for ordinary agent chats. CLI helpers and browser HTTP handlers translate to the same application operations. A browser route verifies its own authority even if its URL contains every identifier needed to find a record. [ENTRY and tool catalog](../plans/02-sessions/entrypoints.md) · [Shared MCP service](../plans/02-sessions/entrypoints.md#shared-mcp-service)

## Identity and representation

| Wire field | Meaning |
| --- | --- |
| `reviewId` | Path-safe opaque service ID for one canonical GitLab origin + positive numeric project ID + positive MR IID. Resolve by unique triple. A title, short URL, repo nickname, ticket key or IID alone cannot select between two reviews. Public tooling may resolve a canonical MR key or URL to this ID. |
| `runId`, `sessionKey` | A registered run belongs to one review. A session belongs to exactly one run and verified native identity/profile. A confirmed lead is the target for ordinary messages. Children may have separately addressable native questions. Resolve both IDs at the service. |
| `submissionId`, `actionId`, `receiptId` | A client supplies one opaque submission ID per user intent and reuses it after transport failure. The service/native-proof path identifies actions and receipts; they have distinct types. A report receipt is separate from its content hash. |
| `sourceSha`, `sha256`, `revision` | Git object names are full 40- or 64-character hex, hashed content uses 64 lowercase hex SHA-256. A report with unknown reviewed revision carries an explicit reason. A patch `revision` is an opaque identifier for a review-bound base/start/head triple. A logical resource revision (`settingsRevision`, `decisionRevision`, `expectedRevision`) is a canonical unsigned decimal **string** in 0…9223372036854775807. |
| `cursor`, `nextCursor`, `generation` | The outer `cursor` is the decimal-string durable global event head. A listing's `nextCursor` is an opaque keyset token or null. Native history continuations use a separate opaque generation/locator. None can substitute for another. |
| Times, IDs, sizes | Emit RFC 3339 UTC with millisecond precision and `Z`. Emit unknown optional timestamps as null. Service and provider IDs in browser resources are strings. Canonical positive decimal strings represent numeric upstream keys such as GitLab `projectId`/`iid`, Jira board/sprint IDs and note IDs. Decode the provider’s native representation in its adapter. Preserve the specified host/MCP native input and signed declaration encoding at those external boundaries. Bounded counts and byte/scalar offsets are nonnegative safe JSON integers; reject an out-of-range value before serialization. |

Use UTF-8, lowerCamelCase object fields, snake_case wire enums/discriminants, named tagged unions and explicitly documented nulls. A missing optional preference means retain its previous value only where the operation allows a patch. A null checkout deliberately disables local chat for that repo. Reject unknown fields on privileged mutation **requests**. Accept additive fields in known **responses**; ignore unknown fields only after validating the known fields and identity. An incompatible response tag or missing required field fails that individual read and retains the last known data. Reject unbounded inputs before allocation. Never put credentials, native filesystem locators or tokens into public event payloads, errors or log lines.

## JSON and ownership

A processed JSON operation returns `{data:T,cursor:EventCursor}`. A rejected one returns `{error:{code,message,retryable},cursor:EventCursor|null}`. `cursor` is null on errors when no authorized snapshot is available. An operation that durably admitted asynchronous work uses HTTP 202 and a typed ID/status. The same accepted submission can be looked up after a lost reply. Standard routes return JSON at `application/json`, UTF-8. Binary/text downloads, 304, both SSE feeds, browser assets and MCP use their own media/protocol. Send private runtime data with `Cache-Control: no-store`. The explicit active document cache honors a pinned identity and application-issued conditional requests.

```json
{"data":{"submissionId":"send_42","runId":"run_active","sessionKey":"codex:active","state":"queued","createdAt":"2026-11-01T00:00:00.000Z","updatedAt":"2026-11-01T00:00:00.000Z"},"cursor":"9007199254740993"}
```

```json
{"error":{"code":"stale_revision","message":"The source revision changed. Refresh this review.","retryable":false},"cursor":"38"}
```

| Status | Stable codes and client action |
| --- | --- |
| 400, 401, 403, 404 | `invalid_request`, `unauthorized`, `forbidden`, `not_found`. Malformed values never reach a provider. Authenticate or resolve the exact authorized resource as appropriate. |
| 409 | `conflict`, `stale_revision`, `idempotency_conflict`, `cursor_expired`. Refresh the named scope. A changed payload under a used ID requires a new user decision. |
| 412, 413, 416 | `precondition_failed` for mismatched If-Match, `payload_too_large` for a request/representation above its supported budget, `range_not_satisfiable` for an unavailable byte range; include standard size headers where applicable. Reload the index/metadata to select a supported representation. |
| 429, 503, 500 | `busy` for local queue saturation; `unavailable` for an unavailable dependency/service, with bounded `Retry-After` when known. `internal` gives a safe correlation message. Retry only an idempotent read or an identified/reconciled command. A provider's uncertain outcome is a durable operation state. |

Authenticated scoped reads obtain durable data and the event head in one SQLite snapshot. For provider-backed projections capture the local watermark and binding **before** the upstream read, then recheck target/revision/generation afterward. Return that initial watermark so updates during I/O are replayable. If the source cannot produce the requested immutable identity, return its defined stale/unavailable result. Do not label remote bytes with an unrelated newer head. Each data resource has its own freshness/revision.

Writes carrying `submissionId` validate current authority and look up (stable actor scope,operation,submissionId) before evaluating expiring handles. Digest the typed, normalized request including the target and semantic preconditions. Exclude transport credentials and ephemeral correlation headers. Use an unambiguous canonical encoding per operation and schema version. Identical retries return the original stable receipt and current known delivery status. A changed target or body under that key returns `idempotency_conflict`. A successful network call alone supplies no native completion evidence. At admission give each outbox row its own service-generated delivery UUID. Use that UUID for worker wake-up, claims, native input correlation and reconciliation. Client IDs remain scoped replay keys. On a message or launch receipt lookup constrain the query by the authenticated stable actor, operation, client ID and URL target. Different actors can reuse one client ID, including at the same lead. Other authorized surfaces can show the run’s observed delivery history under its normal read permissions.

## Browser launch and service readiness

ENTRY owns the following exchange for both exact loopback listeners. The service writes its current instance ID, build identity, canonical endpoints and a fresh local control key into an owner-only runtime descriptor. PACK verifies the descriptor’s path, ownership, mode and active profile before attempting readiness. The bridge credential, checkout bearer, browser cookie and service control key have separate purposes. Never send the raw control key to a process merely because it listens on the expected port.

1. The CLI draws a fresh 32-byte nonce. To verify the listener, send authenticated `GET /api/v1/status` with the nonce, expected instance and a short-lived control authenticator. Use HMAC-SHA256 keyed by that private control key over a versioned, length-delimited tuple (direction, instance ID, method, exact path/query, body digest, nonce and issued UTC instant). Response proof uses the distinct response direction, the same nonce/instance, HTTP status and SHA-256 of the exact returned bytes. Verify in constant time before trusting status or sending other private payloads. Reject expired, replayed or wrong-instance control requests. The authenticated status body identifies the installation/profile, build digest, store application ID/schema, readiness and queue/sync summary. Activation compares them to its own recorded manifest and candidate.
2. `reviewq open` uses that verified control flow to `POST /api/v1/session` with `{"mode":"launch"}`. Return a private one-time random ticket valid for 60 s, bound to this installation and browser origin. Open the desired local browser URL with its original query parameters and ticket in the fragment. Short-lived tickets are excluded from logs, copied dashboard URLs and printed status output. The browser consumes/removes the fragment with history replacement, then posts `{"mode":"redeem","ticket":"…"}` to this same route with exact browser Origin. Only the control credential can mint tickets.
3. Atomically consume the ticket, set an installation-named host-only HttpOnly SameSite=Strict browser session cookie and return the session CSRF token. Browser GET `/api/v1/session` with the cookie reopens/refreshes CSRF for that session. Mutating browser operations require the cookie, exact Origin and `X-ReviewQ-CSRF`; EventSource uses the same authorized cookie. Cookies are scoped to API resources. Keep token and authority out of localStorage and durable URLs. Preserve the original MR/run/tab/bookmark query across bootstrap. If a browser session expired, guide the user through the launcher on this profile and resume the preserved target. Rotate session authority on transfer/restore or installation replacement. An already authorized bookmarked page can reopen without a new launch ticket.
4. A duplicate launch-ticket redemption, foreign Host/Origin/cookie, modified readiness body or stale control proof fails before reaching a workflow. Limit outstanding tickets and nonces by expiry/time and bounded active work; overload has the normal busy outcome. A service restart revokes previous-process control proofs. ## Resolving selected work

A bookmark, notification or MCP dashboard URL can supply `?view=runs&mr=https%3A%2F%2Fforge.example%2311%2141&run=codex%3Aactive&tab=activity`. After browser session bootstrap, SHELL requests `GET /api/v1/reviews/resolve?mr=https%3A%2F%2Fforge.example%2311%2141&run=codex%3Aactive`. The same operation accepts a public `reviewId` and, optionally, a public `runId`. Parse the canonical external MR key using the complete origin/project/IID. For a native run selector use the indexed exact registered lead session key. An explicit lead/run must belong to this review within the active authority. Never enumerate queue pages to find a link. A selector with multiple valid meanings is a conflict, a missing/mismatched/cross-scope selection gets `not_found` without revealing another review's data. Preserve the URL target and let the user select an available run. Only an omitted run may default to the most recently started registered lead (descending start then stable ID). When the review has no registered lead, return the review with null run/session. The successful body is `{reviewId,runId,leadSessionKey}` inside the common envelope. An MR with the same IID in project 22 cannot match project 11.

A launch can lose its HTTP response after the host starts a conversation and before ReviewQ knows the new run ID. Before calling the host, persist the actor, selected review, immutable launch request digest, submission ID, attempt state and nullable native/run handle. Lookup by the authenticated actor, launch operation, review and submission returns `{reviewId,submissionId,state,runId,nativeId,createdAt,updatedAt}`, with unknown handles null. Keep this lookup read-only, including for an uncertain attempt. A mismatched review cannot retrieve it and a missing receipt supplies no proof that the host started. Use the same submission ID for an authorized replay of the same intent. A second conversation requires a distinct explicit launch intent. [Session workflow](../plans/02-sessions/hosts.md)

## Bounded projections

- **Queue and runs.** List envelopes contain `{items,nextCursor,…facets}`. Use deterministic keysets with a unique final tie breaker. The continuation binds the query/filter, authorization, snapshot/generation, direction and sort key. Reject a changed or expired context and refetch page one. Cap normal list limits at 100 rows unless the resource defines a smaller limit. A compact queue row includes `reviewId`, project/IID, source status, title, observed SHA and user-stage summary. Overview adds its decision/settings revision, checkpoint and available runs. Selected run detail includes `runId,reviewId,leadSessionKey` and a bounded page of safe session summaries. Accidental select-all joins against entire histories fail the busy fixture. [Queue contracts](queue-and-settings.md)
- **File index and raw patch.** A files page returns `{revision,baseSha,startSha,headSha,items,nextCursor}`. Each entry binds `fileId,oldPath,newPath`, change flags, completeness, `byteLength,lineCount,maxLineBytes` and nullable `patchETag`. Unknown measurements are null. A known `patchETag` is the strong quoted ETag for the complete file bytes. GET `patch?fileId=…&revision=…` serves immutable UTF-8 unified diff bytes at `text/plain; charset=utf-8`. Include a strong quoted SHA-256 ETag of the complete bytes and `X-ReviewQ-Review-Id`, `X-ReviewQ-File-Id`, `X-ReviewQ-Patch-Revision`. A matching If-None-Match returns 304. For a known complete immutable source support a single standard byte Range, If-Match, 206 and Content-Range, 412 on mismatched identity and 416 with `Content-Range: bytes */length` when out of range. Use the index’s strong `patchETag` for the first ranged If-Match when available. When null, request just the first range unconditionally on that exact immutable review/revision/file URL, require 206 and verify all three response identities, Content-Range and the returned strong full-content ETag before displaying any bytes. Pin that ETag on subsequent ranges. If a source cannot return those proofs, expose its limited state. On 412 or conflicting IDs/size discard the partial document and reload the file index. Key DOM ownership and thread attachment by (reviewId,revision,fileId), even when two revisions have identical patch bytes and ETag. Disable representation-changing compression on range responses. `download=1` supplies an attachment. A provider-limited/incomplete/binary/missing file declares its availability; offer only verified bytes and ranges. Never fabricate a complete file or substitute another revision.
- **Large selected document.** Rich patch budgets are 2 MiB, 20,000 physical lines and 16 KiB per physical line, including hunk/meta lines. If any metric exceeds its budget or is unknown, start in a bounded viewer (64 KiB byte windows, up to three carry bytes to decode UTF-8), with honest source availability and download. Line count is LF count plus one if nonempty data does not end in LF. For maxLineBytes exclude the LF or CRLF delimiter. A CR outside a CRLF pair counts as content. Byte length, digest and ranges always use the original bytes. Empty bytes have zero lines and maximum line length zero. Ordinary selected documents keep native Find/selection throughout their full loaded file. [Browser experience](browser-experience.md)
- **Transcript.** Return `items,nextCursor,previousCursor,generation,availability`; default tail with at most 100 entries and 256 KiB encoded page, individual content chunks up to 64 KiB. A cursor binds native source, confirmed run/session, direction, generation and range. Return historical unknown timestamps as null. A changed/truncated source produces a generation reset. A scoped live delta carries transient data only for its active session and generation; clients recover by authoritative page reads. [History reader](../plans/02-sessions/history.md)
- **Reports.** Current and version GETs default to `view=summary` with receipt, hash, revision evidence, delivery, coverage, semantic index state, counts and size metrics. Fetch finding/section metadata by receipt and collection using [bounded context pages](review-workflow.md#semantic-indexing-budget). `view=markdown` is available through all three limits of 1 MiB, 10,000 physical lines and 16 KiB per physical line. Section reads use Unicode scalar offsets and at most 12,000 scalars. Full downloads use the immutable version's `/source?download=1`, bound to receipt and content hash. Reply feedback carries its displayed receipt, hash and exact quote range. Capture can retain a full accepted report beyond the rich-view budget. [Report contract](review-workflow.md)

## Global event stream

Open `GET /api/v1/events?after=<outer snapshot cursor>`. Reconnection uses `Last-Event-ID` when present, taking precedence over the original query. New subscriptions without either cursor start at the current head for future hints. A browser first loads the mounted authoritative state, records its per-resource watermark, then subscribes from the earliest watermark that still requires replay. A slow resource load at A must not be discarded just because another response already saw B.

```text
id: 39
event: invalidate
data: {"resources":[{"kind":"run","id":"run_active"},{"kind":"queue"}]}

event: reset
data: {"reason":"cursor_expired"}

```

Emit `text/event-stream` with keepalive comments every 15 s, no buffering cache, fixed-size resource descriptors, no code/report/history body. Resource kinds are `queue,review,run,session,history,changes,discussions,report,action,followup,ticket,notification,settings`. Specific IDs identify the resource of that kind; omitted ID invalidates that family. For changes/discussions use review ID, for report/action use run ID, for native history use session key, for followup use review ID. Map preference changes to settings/followup. Emit dependency keys explicitly when summary facets also change. Each received global event advances the subscription cursor, even when its keys are outside the mounted view.

Subscribe to a shared postcommit wake-up before the first DB replay read. Drain journal entries strictly above the supplied cursor in ascending batches of at most 128, then await a wake-up **or** periodic recheck. Across wake-up loss/overflow re-read SQLite from the last delivered cursor. Duplicates after reconnect are idempotent; compare cursors numerically with BigInt. Keep at most 4,096 retained rows. A supplied cursor below the floor, above the head, or a client too slow to catch the available range gets `reset` with `cursor_expired`, `cursor_ahead` or `stream_lag` and the stream closes. Reset has no event ID. The client closes EventSource, fetches the necessary snapshots and opens a new subscription from the resulting cursor. On profile replacement/restore rotate browser-session authority and require fresh bootstrap/snapshots. This invalidates old cursors even where the restored head coincides.
