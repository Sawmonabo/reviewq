# Review queue, archive, notifications and settings

ReviewQ opens on **Review queue**. It shows the team's eligible Jira work, one card per matching GitLab MR, and eligible tickets that have no matched MR. **Review runs** follows work the operator registered, across sprint changes. **Notifications** collects observed updates across those reviews. An approval, a local decision, a saved report, a notification receipt and a native agent's execution state are independent records. [Browser experience](browser-experience.md) · [Run workflow](review-workflow.md)

## How a review enters the workspace

| Entry | Evidence and resulting ownership |
| --- | --- |
| Automatic discovery | Read tickets through each enabled Jira board with its configured review status IDs, optional project keys and optional saved team filter. Read open MRs in each of that board's allowed GitLab projects. Match only a complete known ticket key, case-insensitively, in title or source branch with non-alphanumeric boundaries. `RQ-41` must not match `RQ-410`. If no open match exists for a ticket, match unresolved keys against the title and source branch of closed/merged MRs in its eligible projects, then verify candidates with the same exact association. A partial history scan cannot establish an unmatched ticket. Deduplicate by normalized GitLab origin, numeric project ID and IID. |
| Scoped association | Keep `{scopeId, boardId, ticketKey, projectId, sprintIds, currentOrFutureSprintIds, membership}` together. A row qualifies when a single association satisfies board, repository **and** sprint. For a ticket-only row evaluate the ticket's eligible board/repository associations, then emit the ticket once. If Alpha board allows project 11 and Beta board allows project 22, evidence for an Alpha-only ticket in project 22 is insufficient. Two valid links still produce one MR. |
| Explicit tracking | **New review → Review MR → Track MR by URL** validates the configured GitLab origin and exact project/IID, verifies candidate ticket keys, then stores a personal tracking marker. Show the MR in the picker even without a board match. Starting a run, creating a checkout and enabling discovery for its repository each require their own action. |
| Carry-over | A registered lead, explicit tracking, local review/checkpoint, published review history or a notification receipt retains the MR and its references across status changes, removal of a board/repo, disconnect and restart. An authoritative full successful refresh may expire a discovery-only row that has left scope. Targeted, stale, partial or failed reads cannot expire it. Fresh discoveries and first collection establish an observation baseline. Existing owned work continues comparing against its last successful observation. |

**Freshness.** One running full refresh per active settings revision. Stage network reads outside SQLite writes. Commit complete, revision-checked observations, scope and synchronization receipts together. On failure retain the last successful snapshot with a visible time and error. On settings activation immediately remove invalid scope matches, show loading for newly eligible scope and discard previous-revision results. Retained runs, notifications, tickets and decisions remain available locally. A refresh request, a background job or a successful connection test alone cannot certify a complete source read.

## Queue, archive and decisions

| Control | Rule |
| --- | --- |
| Board / Sprint / Repo | Default to enabled boards and their configured projects. Active sprint means a confirmed active Scrum sprint on the selected board. Any means any matching scoped ticket. No sprint requires confirmed absence of active **and future** membership. Unknown never matches No sprint. Specific choices OR board-qualified sprint pairs and intersect the other filters. Kanban-only boards use Any with disabled sprint selection. Mixed Active/specific excludes Kanban. Changing boards drops impossible sprint pairs and restores Active when the last selection disappears. Reflect rollover from fresh board metadata. |
| Ownership / Author / State | Initial view is other people's MRs, Anyone, Needs review. Own means the verified GitLab user or a configured additional reviewer ID authored the MR. Select authors by provider ID, display handle. State includes All open, Needs review, Needs re-review, Waiting on author, Reviewed awaiting merge and Archive. Queue Archive still requires a current scoped ticket/MR match. Review runs → Archived covers retained registered work. |
| Queue state | First matching row rule wins. Closed/merged → `archive`. Open with active personal approval → `reviewed`. Changed code since handoff, withdrawn personal approval or pending unhandled observation → `followup`. Recorded completed review → `reviewed`. Waiting disposition or published personal comment → `waiting_author`. Otherwise `needs_review`. Use exact saved SHA for local decisions and verified diff-version time for provider-timestamp handoffs. An aggregate approval, mutable thread anchor or a run's starting SHA cannot prove personal review coverage. |
| Baseline Needs review exclusions | Exclude any registered lead even after a new SHA, failed run, missing report or clearing a decision. Also exclude recorded review history, working/input-pending agents, and completed eligible lead reports covering the current full MR. A thread-only report cannot confer whole-MR coverage. All open includes scoped open MRs of any queue state subject to the selected exclusions. Run stage/reason is the separate shared classifier in the workflow spec. |
| Search / Hide / Sort / Clear | Case-insensitive search covers MR title, ticket key/title, project and author. Ticket-only search covers key, summary, status, priority and assignee. Show unmatched tickets only for All open/Needs review, no specific author, ownership All/others. Hide reviewed (history or eligible current full-MR report) and Being reviewed (working/awaiting input) have independent counts before Hide. Sort MR rows by recent/oldest update or folded author, then stable identity. Ticket sort uses natural key order across both row kinds. Other sorts put unmatched tickets last in natural key order. Clear chooses All open, all ownership, Anyone, default scope, recent first, empty search and no hides. Counts use the same snapshot and filters as the rows. |
| Bulk preparation | Queue and Runs offer **Review MR**, **Select MRs** and **Register run**. Select all shown targets displayed open MRs. Changing filters or live eligibility drops hidden/closed selections. Jira-only and unloaded items remain unselectable. Prepare shows exact selected projects, IIDs, heads and checkouts. Intersect models/efforts and unambiguous skills across selected providers' target catalogs. Expand `{ticket}` per target, retain its specific context and preserve one submission/receipt per MR. Dispatch individually in displayed order. Partial success exposes Started/Not confirmed and untouched targets. Reconcile an uncertain start before any retry. Bulk monitoring uses independent per-MR selections and results. [Native sessions](agent-sessions.md) · [QUEUEUI](../plans/05-browser/queue-view.md) |
| Local decisions | **Review complete** and **Waiting on author** record the observed SHA, time, disposition and the displayed checkpoint. **Clear local review record** clears local coverage/time and preserves registration. **Follow-up handled** advances only the displayed checkpoint. A terminal decision without a displayed checkpoint leaves the previous handled frontier intact. Validate the MR is still open at the exact head via GitLab, then compare local decision/settings revisions inside a short write transaction. Checkpoint covers the prior GitLab observation frontier and per-session semantic report/attention receipts. A later reply, genuine new question or materially revised report remains pending. An update that changes no active finding, blocking value or verdict retains the original attention lineage. |
| Archived | All registered runs under a merged/closed MR appear on one card. Date = saved review work across its runs (published initial or new review, recorded local decision, completed selected-thread check with or without a new version, or historical report's retained timestamp). An update that keeps its parent's attention lineage does not supply a new date. Combine text, optional inclusive local review date range and OR of selected board/sprint pairs. Date presets are All time, This week (Monday), Last 7/30 days, This month and Custom. Date match can come from an older run. Sort by latest **matching** date desc, null last, then stable review ID. Keep full archive count and filtered total. Use archive membership reads across configured boards and archived ticket keys without the current review-status filter. Missing data cannot satisfy a positive restriction. Show unavailable boards while retaining positively known matches on other boards. |

## Local API

All paths below sit under `/api/v1`. JSON successes use `{data,cursor}`. Errors use `{error:{code,message,retryable},cursor}`. `reviewId` is a service-issued path-safe ID for one origin/project/IID. Treat database identities, public provider IDs, revisions and event cursors as strings on the wire. Timestamps are UTC RFC 3339. Page continuations are opaque and bound to their operation, principal, scope, filter and ordering. Expired or conflicting continuations require restarting that query. Use the [transport contract](data-contracts.md) for common authentication, status and projection/event behavior.

| Method and resource | Input and result |
| --- | --- |
| GET /queue | Optional repeated `boardId`, `projectId`, `sprintPair=boardId:sprintId`, `sprint=active,any,none,selected` (choose one), `ownership=others,mine,all`, `authorId`, `state`, `hideReviewed`, `hideInProgress`, `q`, `sort=recent,oldest,author,ticket`, `limit`, `cursor`. `scope=none` represents an explicitly empty board/project selection. Omission uses defaults. Return `{items,nextCursor,totalRows,totalMrs,facets,sync,settingsRevision}`. `facets` includes available scope/author choices and Hide counts. `sync` includes mode, last attempt/success, active/stale and a sanitized error. Items consist solely of compact display/selection fields. |
| POST /queue/refresh | Request one full read under the active settings revision. `202 {refreshId,state}` with a coalesced ID for duplicate outstanding requests. The CLI waits for that ID's result through `GET /queue/refresh/{refreshId}` → `{refreshId,state,settingsRevision,finishedAt,error}`. States queued, running, succeeded, failed, superseded. Publish the terminal result before advertising a newer successful generation. |
| GET /queue/sync | Read the current `sync` object without reading queue rows. A `queue_sync` invalidation refreshes status and leaves loaded rows and continuations intact. A `queue` invalidation refreshes the row projection. |
| POST /queue/sprints | `{expectedRevision,pairs:[{boardId,sprintId}]}` loads requested explicit sprints against enabled Scrum boards. Return `{settingsRevision,loadedPairs}` after the full read. Coalesce concurrent loads across tabs, max 32 distinct loaded pairs per settings context. Surface invalid/deleted sprint or load failure and keep the previous filter/scope. A selection never starts a review. |
| POST /tracking | `{expectedRevision,url}` → `{reviewId,projectId,iid,sourceSha}` on a completed verified attachment. Repeating the same attachment returns one association. A different site, missing project or unverifiable key gives an actionable error. |
| GET /tickets/{key} | Open a current scoped or retained referenced issue. Return the ticket metadata, nullable estimate, warnings, description, Jira link and first comment page. Return `commentScope` even for a ticket with no further pages. A missing field is unknown and zero points is a valid estimate. |
| GET /tickets/{key}?view=comments | Supply `scope=<commentScope>` and the optional `cursor` for this page. Return only `{key,commentScope,items,nextCursor,commentCount,fetchedAt}`. Recheck current Jira access and verify the issue's canonical key, project and numeric ID with a project-only read. The service-issued scope binds the issue and active settings revision. The cursor also binds sort, limit and the exact preceding comment. Omit the cursor to sort or return to page one with the same scope. Both ticket views accept `order=newest\|oldest` (newest by default) and a bounded `limit` (20 by default, 25 max). The count and comment links use Jira's visible comments. |
| POST /reviews/{reviewId}/decisions and /checkpoint | Decision body `{submissionId,expectedRevision,expectedSettingsRevision,sourceSha,checkpointId,disposition}`. The checkpoint operation uses the same body without disposition. `expectedRevision` identifies the current **decision** revision from the review projection. Disposition values are `reviewed,waiting_author,needs_review`. For a CLI decision, omit checkpointId and leave all previous handled evidence intact. The dedicated checkpoint operation requires a displayed checkpointId. Both return `{reviewId,decisionRevision,disposition,reviewedSha,reviewedAt,checkpointId}`. Reuse of an identical submission returns the original result. Changed head, closed MR, expired checkpoint or concurrent decision requires refresh. Unread events do not participate in this decision. |
| GET /reviews/resolve | Direct indexed lookup with opaque `reviewId` and optional `runId`. Return `{reviewId,runId,leadSessionKey}` under the active authority. A review without a registered lead has null run/session when runId is omitted. Reject an explicit foreign or missing run and never substitute a different one. |
| GET /runs | `stage=needs_input,working,waiting,archived`, optional `reasonKind,hasAgentQuestions,q,limit,cursor`. Return `{items,nextCursor,stageCounts,totalMatching}`. Cards include review ID, lead run IDs, focused session, reason and separate coverage/approval. Sort by latest registered activity desc then review ID asc. A current question may remain visible while the lead is working. A Claude session's stage shows the state its companion last reported while the companion is live or unknown, and drops it once the companion is gone, including when its process is proven dead, as the review workflow's settling rules define those states. Archive selection uses the next resource for review-date/sprint restrictions. |
| GET /archive | `q`, optional RFC 3339 `fromInclusive,untilExclusive` converted from the user's local day boundaries, repeated `sprintPair`, `cursor,limit`. Return `{items,nextCursor,totalArchived,totalMatching,boards}`. Rows include `reviewId,runIds,latestMatchingReviewAt,dateSource,sprintPairs,membership`, MR title/project/IID and run labels. Metadata may be partial. Fetch only when Archived is active. |
| GET /notifications | `view=unread,all`, `limit,cursor`. Return flat page `{items,nextCursor,unreadEventCount,unreadMrCount}` with public event IDs, source, kind, selected review/run/session identity, label, occurrence/read time and link target. Sort by occurrence time desc, source asc, identity desc. Merge pages by event ID, group by MR, newest group first with review ID as tie breaker. |
| GET /notifications/{notificationId} | Look up one retained occurrence by its exact ID under browser authority. Return `{item,reviewContext,dismissed}` without reading earlier pages or changing its state. A dismissed occurrence remains available through its exact link. |
| POST /notifications/state | `{action:read\|unread\|dismiss,ids:[notificationId,…]}`. Capture **only displayed event IDs** at selection, up to 2,000 per request. Verify caller scope for every ID before a single local commit. Return `{affectedIds,unreadEventCount,unreadMrCount}`. Retrying a state assignment is safe. Dismissed rows stay dismissed. |
| GET /settings, PUT /settings | GET → `{settingsRevision,mode,connections,boards,repositories,additionalReviewerIds,chatSetup}`. PUT accepts the whole desired draft with `expectedRevision` and explicit `tokens` changes. Returns the same sanitized view after commit. [Fields and coordination](../plans/03-workspace/preferences.md) |
| GET, PUT /settings/agents/recovery | Return `{revision,autoResumeCodexReviews}`. Update just the owned preference with `{expectedRevision,autoResumeCodexReviews}`, then signal HOST to wake or cancel eligible pending recovery. This revision is separate from connection settings. |
| POST /settings/test, /settings/catalog, /settings/disconnect | Test one structured provider draft and return its verified display identity. Catalog accepts provider, structured connection/credential operation, kind, optional board/view, search and cursor. Returns a bounded typed page of choices. Disconnect accepts `{expectedRevision,provider}`, revokes that stored connection and returns Settings. Reading and testing settings leaves saved configuration unchanged. |

## Settings and notifications

A fresh installation has one private workspace, no boards/projects selected and `setup` status. **Settings** edits GitLab origin/token, Jira Cloud site/email/token type/token, board/repository bindings, additional reviewers and optional local checkouts/default skills. Both connections must validate before activation. A configured connection can serve retained reviews with no enabled boards. **Agents** has independent controls for Codex recovery, automatic follow-ups and maximum concurrent follow-ups. Keep unsaved form controls independent. Save validates the draft directly. Discard clears transient token inputs and canceled lookups, then restores the invoking view and draft. [Preferences UI](../plans/05-browser/preferences-view.md)

Credentials stay in per-user private storage. Never include a stored secret in a response, URL, browser persistence, diagnostic, prompt or release. A typed token is held only in the current form/request and cleared after save, cancel or dismissal. Credential replacement and bindings commit together. Keep is bound to the same provider origin and auth identity. History pins the workspace origin and verified account. Disconnect stops future remote checks and preserves local history. A configured checkout grant authenticates an ordinary management chat and can access the workspace’s configured projects through the named MCP operations. The checkout validates the caller, while the selected target must separately be a configured project. Removing the issuing checkout revokes all calls under its grant even offline. Private host configuration projection is a separate, revision-fenced local operation. [Entrypoints](../plans/02-sessions/entrypoints.md)

Notifications combine GitLab thread/code transitions with registered native events and accepted-report attention. Opening a card, expanding a thread or reading history leaves it unread. Read, unread and dismiss update the selected inbox receipts alone. Dismiss retains the occurrence identity to prevent replay. ReviewQ dismisses a report-failure notification itself once the failure no longer needs the reviewer: a publish on that run or on a later run of the same review, a closing call on such a run that ReviewQ answers with the current version, **Review complete** or **Waiting on author** saved while a later run is the review's newest, or the merge request being merged or closed. The newest run's own failure outranks every local decision in the review's stage, so its notification stays until a publish or the merge request's end. The rail counts **MRs** with unread updates. Cards expose their event totals and individual actions in the expanded group. Bulk actions freeze the displayed IDs, including older pages actually loaded. A desktop link opens Notifications and focuses the exact occurrence shown in the toast, including an older, read or dismissed occurrence. Its open action selects the associated MR, run and tab. A missing occurrence leaves the inbox available and shows an unavailable message.

The first successful observation establishes a baseline. Subsequent new replies by other people in discussions containing our comments, edits and resolution/reopen transitions, and a proved new head after review create deduplicated occurrences. Own replies, unrelated threads and first observations stay quiet. Personal approval can change the run's next-action stage while its associated observations stay in the inbox. Native and report producers use stable source receipts. Desktop delivery uses the same retained IDs. One Codex quota episode can have several per-MR events and only one desktop toast. Explicit read/dismiss suppresses future delivery of selected items. Failed notification delivery leaves inbox history and displays a safe delivery error. [Queue implementation](../plans/03-workspace/queue.md)
