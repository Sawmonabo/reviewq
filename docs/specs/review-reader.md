# Reading reviews in the browser

The reader spans Changes, Agent and Findings in the existing review drawer. ReviewQ owns review decisions, findings and accepted report bytes. GitLab owns changes and discussions, Jira owns tickets, and the chosen native provider owns conversation records. One Rust service serves all tabs. React owns the active reading position, the selection and keyboard focus. Use the [delivery graph](../plans/05-browser/reader.md) for implementation order and the [browser specification](browser-experience.md) for surrounding interactions.

## Changes and navigation

Use one continuous file stream with the current syntax colors, line numbers, addition/removal markers, wrapped text, hunk labels, inline threads, replies and resolution state at ordinary and oversized file sizes. Keep the existing compact basename, position and caret, participant/status filters, conversations view and responsive layout. A provider-omitted or binary patch identifies what is available and links to its source. An exceptionally long line offers a continuation at its actual source position.

Use the existing revision-bound patch lease and strong validator. Rust locates physical rows from sparse source checkpoints. Represent a range by project/review, base/start/head revision, file identity, hunk, physical row and original half-open UTF-8 offsets. Include the old/new side and logical line when one exists. Preserve CRLF, prefixes, unterminated last lines, Unicode and separate occurrences on one line. Return the next actual row or byte cursor even when the byte limit cuts a request short. Never represent provider-truncated code as a complete file. Preserve exact source download.

Prepare visible and near-visible rows first, with a small reverse reserve and extra lookahead proportional to observed velocity and read latency. Start with 128 physical rows per group, 128 KiB per response and three outstanding reads per active pane. Cap decoded bytes, measured row metadata, requests and mounted decorations independently. Retain at most the budgets in the browser specification. Reuse compact native text for browser Find within ordinary admitted files. For files beyond its envelope, pane Find covers all available source independently of mounting. Keep line numbers, threads and controls out of copied code. Store selection endpoints against the revision, and read intervening source in bounded chunks on an explicit copy.

One scroll owner preserves the first readable source anchor and its inset across resizing, font settlement, new threads and page arrival. Keep current content on screen until an explicit destination is ready. A later gesture or a different review cancels the request and invalidates its authority to change scroll or focus. Route ordinary wheel and touch over a diagram to the surrounding reader. Keep intentional pan, modifier zoom, Fit, keyboard controls and source.

## Search as you type

Immediate local path filtering and a 60 ms quiet period for remote code and discussion matches share one Changes picker. Typing from the first character updates suggestions while the reading position stays fixed. Arrow keys choose, click/tap or Enter jumps to the exact occurrence, and Escape returns focus to the invoker. The original spelling and matching range are visible. Preserve filename abbreviations, filters and multiple occurrences per line. Show partial results while Rust scans. Distinguish empty, incomplete, provider-unavailable, and stale data. Scope draft notes to the current authenticated upstream account.

Serve current inline notes, resolved replies, unpositioned and outdated discussions and the current user's available GitLab drafts with one account/revision-scoped discussion projection. Reuse it across typing refinements, line rendering and conversations pagination. Search additional pages independent of the open conversation page. Selecting a current thread opens the exact note at its verified side/line. Outdated/general notes open by ID in All conversations. A draft is labelled and opens its actual draft destination. Never submit or publish a note from Find.

An MR head can stay fixed while notes are edited, deleted, resolved or published. Bind discussion cursors and cache entries to a short-lived observation of the upstream account, effective permissions and note list. Invalidate on the existing discussion event and on credential changes; verify the exact note, original occurrence and current visibility before committing a jump. A vanished result disappears without redirecting the reader. Scope author-only drafts to the authenticated GitLab principal independently of reviewer aliases. Exercise same-head edits and draft publication while the previous page is in flight.

Agent Find searches the selected native conversation, including older offscreen text and actual tool content. Preserve the separate prompt rail. Use the existing history-around operation to open a hit, expand its part as necessary, highlight the exact displayed occurrence and allow next/previous traversal. Escape restores the invoking focus without closing the drawer. Search displayed Markdown text across emphasis/links and exclude hidden destinations. Match canonical Unicode equivalents and case folds, mapping highlights back to the original graphemes and UTF-16 DOM ranges. Use a bounded result page with a generation-bound continuation, snippet and offset witness. Reverify before presenting a jump. Cancellation must release obsolete work when the user types again, switches runs or closes the reader.

Start a cold search with a bounded scan of the actual Claude/Codex records. Stream matches progressively, including large records, escaped strings, tool output and appended data. For repeated searches of a large session, build a disposable, contentless SQLite FTS5 trigram index of candidates and source locators in the background. Bound its disk and construction concurrency outside the review-state writer. Exact verification against the source is mandatory. Handle short queries and uncovered tails by scanning. Extend only a witnessed append. A replaced or truncated file invalidates affected locators and derivatives, including same-length replacements. A broad query must yield a continuation without buffering every match. A ranked search across all reviews would be a separate product scope.

The indexing input is the same displayed, sanitized text that the exact matcher folds. Its coverage records the source generation, projection, Unicode folding, tokenizer versions and certified intervals. Include carry across source chunks and inline Markdown joins. A candidate set must contain every exact match. Scan any uncertified interval, short folded literal or unsupported construct directly. Merge scan and indexed results in source order, including multiple occurrences, and deduplicate overlapping intervals before cursoring. A warm index must return the same ordered witnesses and continuations as a cold scan for emphasis joins, repeated text, composed/decomposed accents, case expansion and chunk boundaries.

## Documents and drawings

Keep the pinned Sätteri block cutter, canonical GFM parser, sanitizer and theme. Use cheap direct rendering for small texts. For expensive completed Markdown, Rust supplies the verified opening range and nearby structure. An accepted report uses its receipt, digest and representation version. A completed message uses provider/session, source generation, record/part identity and native checkpoints mapping decoded text back to source. React reads those boundaries once and prepares content near the viewport. Scope work to one active document and cancel on change. Preserve source coordinates, verified quotes and full-source access.

Publish live events immediately. Reuse the settled prefix for confirmed appends and parse the provisional tail. Seal complete table rows independently in eligible GFM tables. Reconcile at completion with the canonical parser. Changes to global link definitions, footnotes, authored HTML, container structure or earlier bytes require canonical reprocessing within the aggregate document limits. Preserve selection, follow-tail state, tool-group identity and horizontal scroll. Keep limits for the entire document across individual blocks, including a single very large fence or table.

For eligible expensive finished tables send a bounded, validated packet of semantic cells, alignment and source ranges with the source window. Mount the complete admitted native table. Charge the packet, source, transient decode and DOM together. Verify the native accessible row/header/link counts, offscreen browser Find, exact plain and HTML clipboard across distant rows, verified quote, column widths, borders and wrapping, including a widest value in the last row. Decline unsupported constructs and fall back to canonical GFM. Use bounded ranges with preserved headers and source navigation for inputs already beyond the native document budget.

Use the official Mermaid renderer and existing styling for all supported diagram families. Keep the latest valid drawing visible and selectable source accessible while a live drawing changes. Coalesce updates and prepare a replacement near view. Swap a valid result in place preserving the reading line, reserved size and zoom. On a first incomplete diagram show readable source. For completed drawings cache the validated official SVG under source digest, renderer/config, theme and font identity. Advertise known availability with the document to avoid speculative cold misses. Coalesce generation with one active producer; release idle resources. Reuse up to four recent immutable drawings under a 192 KiB decoded string budget in the browser. Validate SVG at the trust boundary, isolate IDs/styles per mount and block external resources. Keep diagram-label Find, source, pan/zoom and exact styling in a half-width and narrow drawer.

An installed service uses its pinned web assets and a configured, locally available headless Chromium for optional precomputation. One isolated producer uses a private ephemeral profile, a fixed internal page, a narrowly scoped, one-use job capability and blocked outbound requests. It reads only the service-selected immutable source. Use a matching font fingerprint and theme; publish only sanitized, size-limited output for the same authorized document after rechecking its digest. Readback requires the current receipt or session-part authorization. A digest alone grants no access. Do not install Node or a browser at runtime. When a producer is absent, busy, incompatible, fails, or an advertised asset was evicted, render official Mermaid in the active client promptly. Coalesce local renders and keep a small scoped warm cache. Never accept arbitrary browser SVG as a shared authoritative derivative. For an invalid *final* revision, identify the previous picture as the last valid preview beside the actual final source.

## Navigation, retention and verification

Selecting a different run while reading Agent keeps Agent open. Initial opening retains its normal default. Bind the session picker, transcript, tasks, composer, draft and drawing to the newly confirmed identity. Never show old content or send to the previous lead under the new header. Prioritize foreground reads over background indexing and prompt-rail preparation.

Stream GitLab pages and discard unrelated patch text. Use the existing disk-backed shared lease for large selected files with a 32 MiB per-file and 128 MiB aggregate reservation, expiration and release of active handles. A failed lease uses bounded reads or refetches. Never archive a full MR or use tmpfs for large scratch. Jira description and comments remain scoped, on-demand reads. Keep the authorized description in place when loading further comments. Release on project, account, issue or authorization change. Use separate disposable storage for rebuildable search and drawing derivatives with bounded admission, atomic publication, expiry and service restart cleanup.

Check identical fixture content at the same widths, theme, zoom and viewport against accepted screens. Compare each rich state before and after the change, including hover, keyboard, touch, focus, wrapped code, inline discussions, tool groups, diagram labels and table quotes. Check actual paint during forward/reverse flings and interrupted jumps; the settled source line stays within one CSS pixel through late completions. Record first populated paint, first matching suggestion, confirmed highlight, peak and settled renderer memory, whole-browser memory, service memory and scratch high-water separately. Report cold and warm reads independently. Use fresh headless profiles and real native-format data for both providers. Exercise switching, idle and active reading over two hours. Compare equivalent rich workloads and retain the existing [acceptance budgets](acceptance.md). Any loss of available interaction, content fidelity, or visible richness requires correction before release.

For matched canonical workloads target 20% less private renderer working set where the same rich content and operations are available, with no material regression on other rich views. The raw-only large-file baseline and the replacement with working inline comments describe different experiences. Report both, plus a rich-to-rich comparison. On the 60 Hz reference machine compare against the matched 16.8 ms p95; also report p99, worst presented hold and blank regions during the gesture. Collect separate first-open, refinement and confirmed-jump times. On two-hour idle, active and alternating-session runs keep the same browser processes alive, use normal GC and include the peak and closing half-hour trend. No universal tab RAM ceiling has been established. Preserve candidate revision and evidence of any actual hardware interaction still awaiting verification.
