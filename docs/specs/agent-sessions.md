# Native review sessions

An operator can start a review in their usual Claude Code or Codex terminal, link it to an MR, close the dashboard, and reopen the same conversation in either place. A review launched from the dashboard has the same native identity and capabilities. Native terminal sessions retain their provider login, workspace, tools, skills, permissions, and ownership of the conversation. ReviewQ runs one local service. Every authorized Claude or Codex chat uses the same MCP endpoint. A new chat reuses the service and tool catalog without starting a daemon or watcher. Concurrent work is bounded and the number of successive chats is unrestricted. Browser and MCP clients share the same run, delivery receipts and history reader. [Shared MCP service](../plans/02-sessions/entrypoints.md#shared-mcp-service)

## Start, register and return

| Operator action | Result visible to the operator |
| --- | --- |
| In a normal terminal run `reviewq`, or invoke the Codex `$reviewq` skill without a target | Open the dashboard. Claude's bare `/reviewq` instead displays connection, dashboard URL, exact native session and registration information in that conversation. |
| In the conversation run `/reviewq ABC-123` (Claude) or `$reviewq ABC-123` (Codex) | Codex validates its in-host identity, starts or reuses the owned ReviewQ service, verifies readiness and links the conversation without opening a browser. Claude links via its native companion. A configured MR URL or exact MR key also works. Resolve a unique open MR for a ticket, or the unique historical match if none is open. Ambiguity returns the matching URLs. A repeated link returns the existing run. A linked native identity remains bound to that MR. To review another MR, begin or link a separate native conversation. Reopening the first retrieves its original history. |
| Select **Register run** | Show the provider-native instruction first. Advanced manual entry accepts an exact provider plus native ID and shows its target before confirming. An unknown or inaccessible session has a clear status. Merely finding a process, a transcript, a similar cwd or a matching branch never registers it. |
| Select **New run → Prepare review** or prepare an unstarted MR | Show MR, full revision, configured launch checkout, provider, available skills/source and arguments or editable custom prompt, additional context, catalog model and supported effort. Preserve draft when fixing missing checkout in Settings. Defaults defer to the provider. Preview has no turn or registration side effect. |
| Select **Start session** | Recheck the selected MR head, checkout, catalog and saved request identity. Register the lead and record requested revision, invocation and native acknowledgement. Show an uncertain launch with a way to inspect the exact target after a lost reply. Batch launch retains a separate identity and receipt per MR. All launch paths append native report handoff instructions after the original invocation and user context. Inspect an uncertain attempt by review and submission ID even before its native ID is known. A manually linked conversation starts with unknown reviewed revision. |
| Select **Runs**, open **Agent**, select a child, follow its breadcrumb | Keep one MR workspace with its run picker. Show lead conversation and tasks/plan, exact selected child conversation/assignment/result, provider, actual cwd, requested settings, latest reported settings, timestamps and availability. Missing settings show “Not reported yet.” Child findings remain visible on that child. |
| In the drawer menu select **Open in terminal** or **Copy terminal command** | Resolve the currently selected native identity and its recorded cwd. Claude background jobs use `claude attach <job-id>`, saved/stopped sessions `claude --resume <session-id>`. Active foreground Claude shows “Run /bg in the existing terminal, then refresh.” Codex uses `codex resume <thread-id>`. Opening uses Windows Terminal in the recorded WSL distribution when available. Provide the exact shell-quoted command when a launcher is unavailable. A resumed terminal can continue interacting if ReviewQ exits. |

Keep the configured review checkout, canonical Git common directory, actual session cwd, provider configuration root, native session ID, Claude job ID, run ID and MR identity as distinct fields. A terminal-started lead can legitimately work in a different checkout from its MR. Its parent/child relationship requires native evidence. Preserve the recorded binding across restart, linked worktrees and repository moves. An unavailable executable, changed root, untrusted workspace or vanished working directory produces a named recovery action. Never silently attach a similarly named conversation.

## Interaction in both directions

| Surface | Contract |
| --- | --- |
| Native terminal → Agent | A real terminal prompt, steer, response, displayed tool, question, approval wait and native resolution appear under the correct lead/child with their native order. Show only user-visible content. Coalesce repeated observations by native ID. Two equal prompts with different IDs remain two prompts. Keep displayed timestamps sourced from provider evidence and mark unavailable timing. |
| Dashboard/MCP → terminal | An explicit message or finding quotation captures the **selected lead** and stable submission ID when sent. The native session receives the same user text through its supported API. Draft remains scoped to that run and session. Show the stored delivery result (queued, dispatching, started, rejected or uncertain). Replace the placeholder when the scoped receipt's confirmed turn and entry IDs match visible native history for that submission. Equal text in different native inputs stays distinct. Preserve older report receipt/hash on quoted feedback and its originating child. |
| Codex clarification | Display all native questions, descriptions, options, supported free text and secret flags. Use one exact request/turn/item and submission identity. Answer a live native request through its original response channel. Its blocking flag controls whether the form occupies the composer. A nonblocking request stays accessible while the agent works, including before the provider supplies its position in history. File-observed async questions route a correlated answer through the outbox. A confirmed answer from any source closes the same form. Preserve a recorded outcome when the transcript is unavailable. After a change in file identity, verify the session and matching saved opening, request, timestamp and line digest before displaying the question details. A historical match alone cannot authorize delivery. Offer terminal handoff for a request that still needs native interaction. Secret async answers belong in the terminal. Keep secrets out of client persistence and logs. |
| Claude clarification | Display a native `AskUserQuestion` in the same form and the same transcript position as a Codex clarification. Preserve the question, ordered choices, descriptions, previews and single- or multiple-choice mode. For a registered session with a waiting question, use the original native callback. Keep the terminal available. Reconcile the linked native result whether the operator answers in ReviewQ or in Claude. Reopening history allows inspection of the original questions and confirmed public answers. A lead can answer through its own live callback. Claude normally removes the question tool from subagents. Reading a child’s saved question does not grant the lead permission to answer for it. [Claude subagent tools](https://code.claude.com/docs/en/sub-agents#tools-subagents-can-use) |
| Native permissions and unsupported forms | Show provider, waiting state, reason and **Open in terminal**. The native CLI handles permission, trust and unsupported elicitation. | Claude terminal footer | Registered sessions append `ReviewQ · ABC-123 · !42` to the existing terminal hint line. Preserve native shortcuts, existing tail, narrow-width clipping and custom status lines. Mark Offline after 30 seconds without a successful registered heartbeat and clear on reconnect or native session switch. Ordinary development chats retain their usual UI. Status and registration are available on demand. |
| Interrupt or recover | Offer native interrupt for a managed job or active managed Codex turn, confirm exact target and show outcome. Externally started agents offer exact terminal handoff. Dashboard closure, marking notifications read, archiving and reading history leave the native process running. Explicitly enabled interruption recovery is a separate, eligibility-checked Codex continuation of the same thread. |
| Management from ordinary chat | A configured checkout and its linked Git worktrees discover the shared `reviewq-manage` skill and authenticated `/mcp`. Asking what is awaiting input reads the configured workspace. Asking to start, send or answer is a distinct explicit action. This management conversation keeps its own identity unless separately registered. |

The same input model serves the browser and MCP. MCP exposes the seven management tools listed in [ENTRY](../plans/02-sessions/entrypoints.md). Claude's registered-lead native tools `report_handoff` and `review_action` live inside the companion. Codex has native command helpers for the corresponding report and action flows. A submitted handoff carries its receipt. The accepted report also carries the verified source hash and reviewed revision. Only the accepted receipt establishes that the lead report is available.

## Reading live and historical output

Open **Agent** at the saved native entry and pixel offset, or at the live tail if that was the last reading mode. Initial layout waits for the anchored visible bodies. Load older/newer windows on demand. Keep native order, selection, keyboard focus and scroll position when output arrives during reading. Show a return-to-live control. A run/child switch cancels the previous source requests and live stream. Reopen uses the same bounded reader and preserves the last draft per target.

Use native landmarks for confirmed operator prompts. Hover, focus or touch reveals the right-edge navigator. Select a group, preview a prompt, jump to that exact entry. Earlier prompts stay reachable. Consecutive tool activity shares one compact expandable heading with distinct-call count, running/failed state, and partial marker when boundaries are missing. User/agent prose, questions, plan cards and reports stay in order. Mixed Claude messages preserve their ordered blocks. A matched call/result counts once. An unmatched result keeps its own native identity and known status. Use the established PascalCase headings for known tools, including qualified MCP tools and collaboration events. Expand to actual command, arguments and readable output in place. Code stays selectable and copyable. Unknown operations retain native names when available. Expand large bodies in bounded chunks through the same outer scrolling surface.

Native files or the provider's exact read-only API own conversations, tasks and native results. Persist registration, workflow state, ReviewQ-submitted messages, accepted reports and bounded indexing metadata. On disconnect preserve readable rows and the entered draft, show reconnecting, then reconcile by source generation and native ID. Missing, denied and unsupported sources get distinct states. A historical read never starts, resumes or forks a provider. Cancelled sends and uncertain receipts survive restart for inspection. Size, authorization, cursor and rotation contracts are in [HISTORY](../plans/02-sessions/history.md). Provider handshakes, terminal argv and native bundles are in [HOST](../plans/02-sessions/hosts.md).

## Native tool presentation

| Native evidence | Display |
| --- | --- |
| Claude Bash/PowerShell or Codex commandExecution/exec_command | CommandExecution with the bounded command summary. A shell command remains a command even when it happens to search or read a file. |
| Claude Read, Glob, Grep, Edit/Write or Codex fileChange/apply_patch | FileRead, FileSearch, ContentSearch or FileEdit as applicable. Show the structured path, change kind, native argument/result and completion state when known. |
| Native web, image or code-mode item | WebSearch/WebFetch/WebFind, ImageView/ImageGeneration or CodeExecution from its structured operation. Keep an independently identified code-mode wrapper and its structured child operations. |
| Native collaboration verb | AgentSpawn, AgentMessage, AgentFollowup, AgentWait, AgentInterrupt, AgentResume or AgentClose as applicable. Display a child link only for a proven registered descendant. |
| Plan, task, question, report or connector tool | Show a first-class PlanUpdate, task state, UserQuestion or ReportHandoff where proven. For McpToolCall preserve native namespace, server and callable name, including Markdown or code in its result. |
| Unknown or unmatched | ToolCall with available native name or ToolResult with known native result ID. Do not infer a tool or success from prose, a missing result, or the end of a record. |

Pair Claude blocks by native message/tool-use IDs and Codex events by turn/item/call ID and namespace. Preserve native heading and ordered text/tool parts on expansion.
