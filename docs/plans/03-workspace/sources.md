# SOURCES · Read GitLab and Jira Cloud

**Start the full SOURCES brief after [SLICE](../01-foundation/first-review.md) has been accepted.** CONTRACT defines the identities and SLICE delivers the first-use GitLab identity, index, patch and discussion reads against the loopback fixture. Take ownership of those files in place. Extend them with the full provider reads needed by [QUEUE](queue.md), [PREFS](preferences.md), Findings and follow-up reconciliation. These operations use provider GET requests. Native launch, Jira changes, GitLab publication, approval and thread resolution have no entry point on this adapter.

## Files and boundaries

The app owns separate GitLab and Jira read ports. Their methods below return typed results asynchronously. Use the production HTTP adapter for fixture runs. FIXTURE serves provider-shaped pages and scheduled errors over loopback, so verification exercises the same decoding, pagination and retry paths. Return typed errors for denied, missing, malformed, rate-limited with retry time, unavailable, revision changed, and incomplete reads. Distinguish valid zero/empty from unproven data.

## Build the reads

Persist ReviewQ’s reports, findings, run/session identities, decisions, follow-ups and the normalized MR/ticket facts needed to reopen them. Normal browsing reads Jira descriptions and comments and GitLab discussion bodies on demand. Keep the visible ticket description while paging comments for the same authorized issue. A continuation reads and transmits just the next comment page, verifies its cursor and rechecks access. Refreshing the ticket or changing its identity or settings invalidates the retained detail. Confirm with two pages that an ordinary page turn issues zero additional description requests and sends zero description bytes. A failed or stale continuation must never combine two tickets’ data.

- [ ] Apply one shared four-request semaphore across setup, sync and detail. Use a 30-second request deadline, at most two retries on transport failures, HTTP 408/429/5xx and jittered delay, checking the per-origin cooldown before acquiring and after waiting. Honor Retry-After (seconds or date) and valid reset metadata, release the permit before sleeping. A delay over 30 seconds yields an error with a retry time. Bound each decoded upstream body to 32 MiB **while reading**. Limit list pages to 100 entries and fail a scan that exceeds 2,000 pages or repeats an ID/continuation without progress. Return partial/limited status for source-enforced diff omissions. Never convert a cap or a malformed final page to successful exhaustion.
- [ ] Build `collect_scope`. Verify board metadata and all selected status/filter IDs. For each enabled board read eligible tickets and all current/future sprint memberships via board-qualified endpoints. Load specifically requested historical sprints using current ticket status. Intersect that board's repository set with verified ticket keys from MR title/branch. Read each project once per collection, deduplicate associations and MRs and retain unmatched ticket summaries. For owned MRs outside scope, read the exact open/closed MR identity as needed to observe state/reopening. Keep merged history available. Populate story-point candidates from each board override/estimate field. A disagreement yields null and a precise warning until resolved.
- [ ] Resolve remaining tickets in one pass per eligible project. GitLab MR search covers title and description; a ticket can occur only inside a source branch. Build a compact local index of closed and merged MR identity, title, source branch and update time by paging the project list with `scope=all`. Apply the same complete-key boundary predicate to both title and branch. Persist a completed per-project scan and watermark scoped to the connection and access generation. On later scans apply ordered updates for all states using inclusive `updated_after` with overlap and IID deduplication, refresh exact candidate matches before publishing, and remove stale associations. Rebuild when authority changes or continuity cannot be established. A page cap, access error or interrupted scan leaves the previous snapshot visible and the lookup incomplete. [GitLab project MR filters](https://docs.gitlab.com/api/merge_requests/#list-project-merge-requests)
- [ ] Implement archive metadata only for retained merged/closed registered reviews. Fetch enabled board catalogs including closed sprints on demand. Query archived keys in batches of ≤100, constrained by board, project and saved team filter, omitting review status. Confirm each sprint belongs to that board's catalog. Missing sprint fields require a scoped proof such as `sprint IS EMPTY` before declaring known-empty. Return verified associations plus per-board partial status, and distinguish unavailable from no sprint. Coalesce by settings revision and set of MR/ticket IDs, 5-minute complete or 30-second failed-result TTL.
- [ ] Bind every Changes index and patch to the exact origin/project/IID and base/start/head refs. Read metadata before and after paginating GitLab diffs. A head or ref mismatch discards that set. GitLab can return multiple file bodies in a single provider page. Feed incoming chunks to the incremental JSON decoder through a bounded buffer with backpressure. Keep a compact per-revision path/page index and only the admitted bytes below. Discard unrelated patch text after extracting its required metadata. Do not stage entire response pages or create a permanent local MR or patch archive.
- [ ] Coalesce concurrent requests for the same revision scan. Use an optional `preferredFileId` on the files query to restore a file already known for that review/revision. Otherwise select the first readable file in display order. Validate the hint before using it. Retain the selected file’s body from the in-flight scan in a bounded active lease (2 MiB in memory, larger selections streamed to one shared, private 0600 scratch file per large selected file/revision). Verify that its directory is on a disk-backed volume. Exclude tmpfs and ramfs. Reserve scratch bytes before writing against one hard total across tabs, requests and active leases. Hold the reservation until the last handle closes. When the volume or quota is unavailable, evict idle entries and use bounded streaming or rereads. Never fall back to buffering the large file in RAM. Reserve at most 128 MiB in total. Each live file reserves its maximum possible 32 MiB before the first disk write. Release that reservation with the last open handle. Four slow readers can therefore share the service with a fifth reader using bounded rereads. On cold index → first-patch navigation, a successfully admitted lease supplies the verified body without a second GitLab page read. End the lease on replacement, consumer cancellation, revision change or 30-second inactivity. Keep at most four active leases for this private profile, evict least recently used and unlink scratch on release or after an interrupted process. The same verified page may keep complete neighboring patches of up to 32 KiB each, with a combined 128 KiB allocation limit per page and up to four cached pages. A raw request checks the current refs before using these bytes. On eviction or a size miss, read just the indexed provider page, check refs and content identity, and emit only the requested original UTF-8 bytes. Measure provider page reads separately from selected raw browser requests during qualification. Keep a rename's old and new path with an opaque file ID. Never synthesize an empty patch for a collapsed, binary, oversized or unavailable file. Retain status and explicit GitLab link.
- [ ] Serve `GET /api/v1/reviews/{reviewId}/changes/{files,discussions,approvals}` independently. The files projection contains revision, exact refs and a page of lightweight entries. Exact file `byteLength,lineCount,maxLineBytes` include hunk/meta lines for the complete original UTF-8 patch. Count LF-delimited lines including a final unterminated line. For maxLineBytes exclude the LF or CRLF terminator. A standalone CR counts as line content. Preserve every original byte, including CRLF, in byteLength, the patch, ranges and its digest. Return null when unknown and `patchETag` with a strong quoted whole-body digest when known, else null. Include explicit binary/rename/create/delete/limit flags.
- [ ] Serve `GET …/changes/patch?revision=…&fileId=…` with selected `text/plain; charset=utf-8` bytes, a strong whole-patch ETag, `X-ReviewQ-Review-Id`, `X-ReviewQ-File-Id`, and `X-ReviewQ-Patch-Revision`. The normal reader is eligible up to 2 MiB UTF-8, 20,000 lines and longest line 16 KiB inclusive. Larger/unknown bodies use a 64 KiB byte window and tail lookup. Support ordinary, suffix and single bounded HTTP byte ranges on the immutable file/revision URL, `206 Content-Range`, unsatisfiable `416` with total size, and `If-Match` precondition `412` with revalidation. Serve the first range unconditionally when ETag is initially unknown, otherwise validate the index's quoted whole-patch ETag through If-Match. Disable representation-changing compression for ranged bytes. The client validates returned file/revision identity plus strong digest before display and supplies that ETag to request subsequent windows. `If-None-Match` can return 304 on the same identity. `download=1` streams a verified complete attachment with the trusted sanitized name only when the upstream representation is available. Render unavailable/limited evidence explicitly. A repeated digest at a new revision is a new document/anchor binding.
- [ ] Bind discussion and approval refreshes to their own metadata invalidations. Discussion-only invalidation fetches discussions only. Render earlier-version anchors distinctly. Coalesce identical in-flight reads. Cap retained file-index metadata at 16 MiB/5 revisions and provider metadata caches for tickets at 8 MiB/10 tickets, discussions at 8 MiB/5 MRs. Drop version-scoped entries on context change. Browser patch ownership follows [REVIEWUI](../05-browser/review-view.md).

For search within the current MR, reuse the reader’s authorized, revision-bound diff stream. Prioritize already available and visible files, share in-flight reads across query refinements, and stop superseded work. The first complete search may read every available diff page from GitLab. Return bounded pages of short snippets with file identity, old/new side, hunk/line and exact match offsets. Report partial coverage for unread, inaccessible or truncated files. Cap results for common prefixes and expose a continuation. The [browser search contract](../../specs/browser-experience.md#search-in-changes) defines navigation.
