# QUEUE · Project the review queue, runs, archive and inbox

**Needs** accepted SLICE, STORE and [SOURCES](sources.md). Use the already persisted settings revision, configured contexts and run registry. [PREFS](preferences.md) can build concurrently. **Delivers** the stable local read/mutation methods for browser Queue/Runs/Notifications, terminal refresh and repository-scoped MCP callers. Follow the [workspace contract](../../specs/queue-and-settings.md) and [workflow precedence](../../specs/review-workflow.md). Browser implementation belongs to [QUEUEUI](../05-browser/queue-view.md).

## Build and verify

- [ ] **Refresh and carry-over.** Use one active full scan per settings revision with a persisted refresh ID/result for the CLI. Stage complete board, issue, MR and reviewer observations first. Compare captured settings revision and synchronization generation on publish. A stale task finishes as superseded. Serialize targeted observations with full publication per MR (retry the stale read or reject it). In the same transaction refresh current association tuples, preserve coverage/decisions and owned rows, compute baselines and insert only new occurrences. Advance the projection cursor after commit. Coalesce concurrent historical sprint requests without replacing another tab's loaded pairs. A failed or interrupted scan reports failure/restart and leaves the prior version readable. Expose `GET /queue/refresh/{refreshId}` separately from a successful last-sync clock.
- [ ] **List projections.** Implement the scope/state/search/sort rules once. Take ownership of SLICE's indexed direct resolver for `GET /reviews/resolve?mr=…&run=…`. Scope canonical origin/project/IID or opaque ID, verify any requested lead belongs to that MR, and return the exact binding without enumerating any queue page. Default queue query limits 50, max 100. Use `limit+1`, stable final identity tie breaker and seek cursors. Bound queries to 200 characters and explicit historical pairs to 32. A continuation from another query/scope is rejected. Queue sorting by ticket compares case-folded project part and digit-run length/value (including large numeric suffixes), with stable row ID on ties. Anchor paging to a relevant projection revision. If underlying rows move between pages return a stale-cursor result and refresh preserving the selected review. Compute full result and Hide totals from the same scoped query/snapshot before pagination. Avoid one SQL lookup per row or deserializing personal detail blobs to answer a summary. Inspect the populated query plan and payload.
- [ ] **Run ownership and classification.** Group only registered leads by origin-qualified review ID. Sort lead runs by started time desc then run ID desc. Choose the focus from the newest applicable lead and children under the same MR/provider. Preserve missing MR as `needs_input/mr_unavailable` where scoped registration exists. An archived MR remains archived through host failure. A blocking native question takes priority over work. A nonblocking question can coexist with Working. `hasAgentQuestions` is separately filterable. Use workflow precedence for failed/saving/recovery/pending/approved states. `GET /runs` supplies stage counts from the same operator/checkout scope, card list ordered by most recent activity desc, review ID asc, and `totalMatching` before page cut. `waiting_on_us` addresses a broader stage than literal `reasonKind=agent_input`. Display report coverage and personal approval independently.
- [ ] **Archive, ticket and selected review.** Read compact accepted report lineage, accepted unchanged recheck completion, and deliberate local review timestamps across every run. Time-only amendments, host activity and GitLab merge time cannot replace missing dates. Use `max(at)` over matching history, not just the latest report per MR. Join selected board-qualified membership on demand. Preserve partial board results for authorized MRs. Fetch individual ticket details/comments through SOURCES only for current scoped or retained links. Keep nullable/zero estimate, identities and original comment text. The public changes routes from SLICE/SOURCES remain independent of this lightweight read path.
- [ ] **Local decisions.** The selected review projection returns `decisionRevision,sourceSha,settingsRevision,checkpointId`. The app resolves the opaque checkpoint to the exact displayed per-MR GitLab frontier, session attention sequence and semantic report IDs. Use a bounded (1,024 entries, 30-minute TTL) transient checkpoint lookup keyed by opaque random ID, MR, actor and settings revision. Return an actionable conflict on eviction/restart. Issuance must not consume the workflow's committed event sequence. The terminal `review KEY SHA disposition` command has no displayed checkpoint. It supplies the target/head, CAS revision and a submission ID without checkpointId. Preserve the stored frontier verbatim, including when a newer reply is visible to the service. An implicit CLI read cannot turn unseen evidence into handled work. `/checkpoint` always requires the operator's previously displayed handle. Look up a replayed durable submission **before** evaluating an expired transient handle. Refresh GitLab immediately before the local CAS, then recheck settings, local open/head and decision revision on write. Record a durable idempotency receipt for a new decision/handled checkpoint. Advance only captured frontiers monotonically per MR/session. New evidence stays actionable. Clear local review coverage preserves registered leads, upstream personal approval, published history and inbox receipts.
- [ ] **Notifications.** Accept `NotificationObservation{source,sourceIdentity,reviewId,runId?,sessionKey?,eventRef,kind,occurredAt,summary}` inside the transaction that observes a transition. Enforce uniqueness on source plus scoped occurrence identity. Detect new note, edit and reopen after a completed baseline. Repeated reads of identical source state are a no-op. Preserve separate reopen/resolve cycles by durable transition identity. Report corrections use semantic attention IDs. Native questions and failures use native event identity. Map a child back to a verified lead. Hide dismissed entries. Mark read toggles only captured rows. History uses a flat, stable global order. Default inbox limit 100, max 100. Compute both unread counts without truncation. At a fixed page watermark, page entries by time/source/ID in that same sort order. Late events arrive on the separate event subscription. Bulk selection carries exact loaded event IDs. Authorize all before applying. Confirm a read/dismiss cannot advance a checkpoint or clear a pending input.
- [ ] **Desktop and delivery.** Group newly eligible unread entries by MR. Prefer a reply deep link to Changes, a report to Findings, an agent event to its run/session. Desktop text quotes a bounded plain-text preview and a local trusted URI. Pass structured argv or encoded data to the OS notifier, never shell-interpolate provider text. Use PACK's WSL identity `Personal.ReviewQ` or local Linux notification service. A quota episode tracks a separate once-per-account/episode delivery receipt, with per-MR inbox entries. Claim before external call, record delivered only on confirmed OS acknowledgement. After a crash at the effect boundary retain an uncertain receipt and suppress uncertain automatic redelivery. Positive failure before send can retry boundedly on a later notification pass. Native notification failure, unsupported desktop and disabled toasts leave inbox and workflow intact.
