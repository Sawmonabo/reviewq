# ACTION · Declare requested review actions and verify GitLab outcomes

**Start after HOST, HISTORY and SOURCES.** A registered lead can declare a user's request for comments, approval, both or cancellation. ReviewQ verifies the result, holds incomplete work safely and returns the same evidence to the browser and managing chat. Read the [workflow contract](../../specs/review-workflow.md#verified-actions-and-dispatch), [HOST delivery contract](../02-sessions/hosts.md) and [native evidence reader](../02-sessions/history.md). ACTION implements the two native command adapters when first used. The integration Sol adds their commands and HTTP routes to the existing SLICE service. ENTRY later verifies the full public CLI and seven MCP tools.

## Deliverables and boundaries

| File | Owner and contract |
|---|---|
| `crates/domain/src/review_action.rs` | Define ActionIntent, ActionState, CommentTarget, Verification and PendingAuthorization. Expose pure target-matching and state transition functions. Use the existing domain IDs and keep this crate dependency-free. |
| `crates/app/src/workflow/actions.rs` | `declare(NativeActor, DeclareAction) -> ReviewAction`, `reconcile(NativeActor, NativeCall) -> Option<ReviewAction>`, `supersede(VerifiedUserInput) -> Option<ReviewAction>`, `check_action(ActionId) -> ReviewAction`, `guard_continuation(ClaimedDelivery) -> DispatchDecision`. Pass typed actor, expected action revision and probe evidence. HOST alone writes to a native conversation. |
| `crates/store/src/actions.rs` | Implement the app port for reading the latest action by registered run, compare-and-set declaration/verification, atomic continuation enqueue, exact cancellation and result receipt. Use store's private writer, event recorder and HOST's outbox helper. |
| `crates/reviewq/src/cli/action.rs` | Parse native declare/reconcile flags, bound the comment metadata file, resolve native identity and invoke SLICE’s guarded native client. The integration Sol registers this module in `crates/reviewq/src/cli.rs` and mounts the feature router in `crates/transport/src/entry.rs` on the same revision as ACTION. |
| `crates/protocol/src/actions.rs`, `crates/transport/src/http/actions.rs` | DTOs and route handlers for `POST /api/v1/native/actions/{declare,reconcile,input}` and `GET /api/v1/runs/{runId}/action`. Use the shared error and authority mapping. Return the route registration to the integration owner. |

Store the original native request entry/turn/call, action ID, explicit intent, reviewed head, authenticated actor, semantic report receipt if known, each comment target hash/optional discussion with verification/observed note ID, own approval verification, check time, retry count/next due, pending submission, last executed submission/turn and terminal reason. Enforce one current action per run, unique action and continuation IDs, monotonically guarded record revision and unique native declaration. Store immutable authority separately from changing results. Keep prior proofs addressable when superseded. A read through a different installation, run or target cannot resolve this authority.

## Implementation

- [ ] Map both real helper shapes into DeclareAction. Preserve `reviewq action declare --intent comments|approval|both|cancel --reviewed-sha SHA [--comments-file PATH]`, `reviewq action reconcile`, and Claude's `review_action`. The ACTION command reads at most 64 KiB of file metadata. The route caps declarations at 80 KiB. CLI reconcile takes no new intent or SHA. Compare Codex's call ID against native history. Bind Claude's latest user prompt to the authenticated companion's entry and turn. Keep requestEntryId in the declaration and preserve the companion hook's strict native context.
- [ ] Implement `verify_request` over the exact registered lead (provider/native ID, run, review, parent null) and HISTORY's latest complete actual input/current active call. Reject an outstanding newer manual send or unrelated automatic prompt. Resolve live open MR, head, all relevant discussion pages and authenticated GitLab user through SOURCES. Re-read local registration and latest native input after provider reads. Atomically bind the declaration only if its observed state still matches. A same-input/same-declaration replay retains the original action ID. Superseding declaration cancels only provably unstarted continuations. Carry an existing confirmed target only for its identical reviewed SHA, digest and discussion.
- [ ] Match exact UTF-8 comment digest and author ID, discussion when specified, and head on a positioned note. Distinguish incomplete provider reads, confirmed match and complete absence. Only explicit own approval satisfies an approval target. Expose confirmed notes even if the approval check fails. A report verdict, other reviewer, note on a different head or native claim of success cannot confirm it. Use the current-source API to refresh before the first check and immediately before any continuation.
- [ ] Persist the state machine and due times from the spec. Use an optimistic revision guard around read/verify/apply. Scope retries to the exact authorizing request. Save retry state and immutable outbox command in one transaction, then notify/wake HOST. Reuse HOST's `eligibility`, native submit and exact-ID reconciliation. Automatic sends start only an eligible idle lead using the known effective settings. A newer user message, stop, changed head, closed MR or changed binding revokes remaining authority before another attempt. Do not synthesize GitLab writes from the service.
- [ ] Bind an acknowledged continuation to its native turn and executed submission ID. Hold uncertain claims and native sends for readback. On restart scan due persisted actions, coalesce checks by action ID and skip terminal/cancelled work. Persist the bounded backoff/attempt limit and continue read-only verification for a halted needs_input action. Native turn/start cannot fence every unrelated terminal client between final evidence read and send. Preserve that uncertainty in the receipt.
- [ ] Expose the typed action stage evidence for QUEUE's `classify_review` and reason projection. Validate the action result against the decision table at ACTION, then integrate the aggregate card when QUEUE is present. Completed comments on an approve report wait on author. Explicitly confirmed approval waits on merge. A material correction, newer actual question or reply can reopen attention. Wire invalidations to refresh the selected review and run summaries at the same committed version. Exercise both registered handlers through the SLICE listener and compare the authenticated native input with the durable action receipt.
