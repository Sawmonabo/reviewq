# FOLLOW · Monitor published threads and run private selected checks

**Start after QUEUE, ACTION and REPORT.** Extend the existing registered lead with a private follow-up when another person updates a monitored GitLab discussion, or the reviewer explicitly requests a check. Keep the original finding identities, exact prior evidence and user dispositions. Use the [selected-thread contract](../../specs/review-workflow.md#selected-thread-scheduling), [native delivery](../02-sessions/hosts.md), [report acceptance](reports.md), [queue and Settings](../../specs/queue-and-settings.md) and [public entry points](../02-sessions/entrypoints.md).

## Deliverables and calls

| Files | Responsibility |
|---|---|
| `crates/reviewq-domain/src/followup.rs` | Selection, observation, eligibility, immutable frozen manifest, batch transition, assessment and due-time rules. Use domain IDs for review/run/lead, discussion, original note, batch, submission, receipt and exact Git SHAs. |
| `crates/reviewq-app/src/workflow/followups.rs` | `configure(Actor,MonitorEdit) -> Enrollment`, `set_preferences(Actor,PreferenceEdit) -> Preferences`, `pause/resume(Actor,MonitorCommand) -> Enrollment`, `review_now(Actor,MonitorCommand) -> BatchAdmission`, `tick(Clock) -> PassResult`, `binding(LeadTarget,NativeTurn) -> Option<FrozenScope>`. Supply the same read projections to browser/MCP. Produce dispatch eligibility from durable facts and HOST readiness. |
| `crates/reviewq-store/src/followups.rs` | Typed conditional writes on the common database. Provide crate-private `observe_snapshot(tx, AcceptedMrSnapshot, PriorSnapshot, ObservedAt)` to QUEUE during refresh, `freeze_and_enqueue(FrozenScope,OutboxIntent)` and `complete_batch(tx,VerifiedReportOutcome)` to REPORT during acceptance. Own reconciliation lineage, per-observation coverage and exact rendered-batch checkpoint. |
| `crates/reviewq-protocol/src/followups.rs`, `crates/reviewq-transport/src/http/followups.rs` | Mount the workflow spec's versioned preferences, per-review monitor, results, assessments, configure, pause, resume and review-now routes. The integration Sol mounts the feature router in SLICE’s existing `crates/reviewq-transport/src/entry.rs` on the FOLLOW revision. ENTRY later connects its `ConfigureFollowups` tool to these accepted use cases. REVIEWUI owns MR menu, Changes editor, bulk preview and Findings result display. |

Use one durable monitor per review, per-MR override, generation, assigned run, verified reviewer identities, selected/excluded original note IDs, existing/current discussion identities, versioned baselines, observations and immutable batch member links. A unique original published note cannot enroll two discussions for an MR. Read results and unseen assessments with cursors scoped to run, receipt, starting checkpoint and captured high-water mark. Index due batches by state/due time, memberships by observation and accepted outcomes by run/completion order. Unique in-flight reservation per MR combines with conditional per-transaction global capacity accounting. Do not use number of executing rows alone to measure active capacity. Integrate with STORE's schema owner and report/outbox foreign keys. A settings save persists the shared preference and schedules a fresh pass after commit.

## Implementation

- [ ] Implement enrollment from a complete configured open MR snapshot. Resolve the selected existing lead or deterministic first assignment (latest accepted report, else sole lead). Return a choice when ambiguous. Establish actual reviewer IDs and personal/configured approval facts from SOURCES. Use verified original note attribution for every candidate. Store an explicit per-MR override ahead of the global policy. Persist exclusions, including all-current-threads excluded, across new comments, restart and single-note promotion. Never replace the assigned native conversation when browsing or when a companion is unavailable.
- [ ] In QUEUE's successful snapshot transaction compare before/after evidence for each selected discussion. Deduplicate by source event/fingerprint/version, persist observation and link any adopted outstanding queue event. Partial pagination, deleted/missing originals or ambiguous promotion need an unavailable indicator and retain the previous evidence. Baseline existing history, avoid a fabricated resolution when first commenting on an already-resolved thread, and capture a later reply first seen in the same successful poll as a just-published original. Ignore own identified actions, system notes, timestamp-only edits, unrelated discussions and commit-only changes. A resolution records GitLab status, never a verified code fix.
- [ ] Implement the manual operations with exact role, target, generation and submission invariants. Configure validates original reviewer note IDs from a fresh complete read. Observe surviving selections before changing them. Rebind only unstarted eligible members after edits, retain executing bindings/uncertain claims. Pause/resume preserves pending work, with full revalidation on resume. Reopened archived MRs need explicit resume. Check Now issues observations of kind requested for all selected available concerns and makes them due immediately. An empty/unavailable set returns a recoverable reason; a retry of the same request cannot append more observations. Bulk loads per-MR enrollment and preview, then invokes normal configure/pause once per intended MR and keeps successful/failed/skipped results separate. Use the same typed command in ENTRY's MCP ConfigureFollowups. Require the caller's submissionId and expectedGeneration (null for first enrollment). Identical replay after a lost reply returns the same operation and any admitted batch.
- [ ] Implement first/last observed debounce and the coalesced scheduler from the spec. Order eligible work by due time and stable batch ID, avoid starving eligible reviews behind held rows. Allow at most one reserved/executing generation per MR and count active global slots atomically. A pending frozen dispatch, unknown/working native state, unfinished delivery or unproved candidate remains active. A proven idle question-blocked batch retains ownership without preventing unrelated due reviews from using its slot. Concurrent dispatchers recheck all SELECT predicates inside the writer transaction. Raising the 1–8 limit fills eligible slots immediately; lowering the limit leaves current turns intact. Stop cancels timers/subscriptions after recording durable outcomes.
- [ ] Before freeze refresh live MR and eligibility through SOURCES and HOST. Require connected allowed origin/repository, verified open/unapproved state, live assigned lead, capability (including active Claude companion), known native settings, idle/no current related question or user submission, no competing recovery and current report disposition version. Freeze a bounded private manifest: batchId, submissionId, generation, review/run/session, original/current discussion IDs, exact observation IDs/versions, original note/finding IDs, checked source and separately known target, baseline receipt/hash, disposition version, reconciliation parents, immutable prompt and expected native settings. Split excessive groups (start with up to 10 observations and a 12,000-character prompt, keep remainder in a successor). An oversized single concern stays pending with its reason. Commit scope and HOST outbox row atomically, then wake it after commit.
- A saved Codex lead can have a completed turn while its thread is unloaded. Check the saved turn, identity and settings during admission. Once this batch owns the dispatch claim, resume that exact thread and recheck the latest input, native idle state and dispatch authority before starting the private check. Opening the inbox or polling for work must never load idle threads on its own.
- [ ] Recheck guards at claim and immediately before native send, compare the actual current head and lead/turn, and leave hold reasons on unavailable facts. An automatic message cannot steer a working turn. Prompt preserves the same private review procedure, scope, model, effort and permissions. Queue original thread evidence links/IDs and instruct the lead to read full relevant discussions and code, retain unrelated evidence and produce exact assessments. Never automatically publish a note, change a discussion, approve, merge, answer questions or update Jira. On confirmed native start append the actual turn ID and set executing. Unknown acknowledgement reconciles the exact submission without resend. A proven pre-start reject/changed head can return still-selected observations to a successor. Capture intervening observations in separate unfrozen work.
- [ ] Bind native report completion to the exact executing attempt and server-supplied frozen scope. A same-session confirmed Codex continuation may link by an unambiguous root turn to the executing batch. A same-run manual turn or another lead cannot inherit it. Run the REPORT callback inside acceptance's transaction, compare frozen observation IDs/versions, revision, parent/hash, disposition version, exact assigned run/lead/native turns and one assessment per distinct discussion including every explicitly linked finding ID. Update active finding links only if the monitor still has the same assigned run and generation. A missing assessment, changed manifest or stale context preserves the candidate for reconciliation and leaves current accepted findings readable. Final/unchanged records exact coverage and advances completed observations. Needs-input persists the question and leaves the batch held. Notification deliverability, results viewed and next action stay independent.
- [ ] At startup and after stop/close/approval, reconcile durable frozen and executing work before new claims. Preserve binding for unknown outcomes and still-running private work. A confirmed ended, ineligible archival attempt cancels without marking its observations assessed. For an ended eligible attempt requiring reconciliation, carry only still-selected observations, original IDs and exact predecessor lineage. A split retry can retire a retained candidate only after accepted groups collectively cover all its original observation/version/discussion tuples and identify the candidate receipt. An explicit resumed question requires the exact bound ancestor and active monitor. Actual unanswered native permissions still hold.
- [ ] Integrate the results/history and paged unseen-assessments through REPORT's displayed receipt and through-batch high-water mark. The browser acknowledges only completely rendered assessment pages for that report. New arrivals after capture stay unseen. Preserve old outstanding `nextAction:review` across later waiting-author outcomes for unrelated threads. Relevant published handoff can return the review to Waiting without marking results/notifications read.
