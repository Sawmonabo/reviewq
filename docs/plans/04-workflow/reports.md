# REPORT · Accept the lead's report and route version-bound feedback

**Start after HOST, HISTORY and SOURCES.** Deliver an immutable accepted report, exact review coverage, a distinct handoff status and feedback to the originating lead. Preserve historical versions and user decisions during failure and reconciliation. Use the [workflow and wire contract](../../specs/review-workflow.md#report-acceptance-and-continuity), [worked review set](../01-foundation/fixtures.md#worked-review-set), [native evidence reader](../02-sessions/history.md) and [native entry points](../02-sessions/entrypoints.md).

Use the existing SHA-256 implementation and `pulldown-cmark` to obtain source intervals from parsed CommonMark events with the report's GFM extensions. Disable unused rendering/features. Hash the original file bytes and preserve them. Section hashes mirror the accepted source extraction rules (original Markdown sliced at the next heading of the relevant level, trailing whitespace trimmed for the section hash only). Canonical document hash includes every original byte. Store only the indexes needed to identify findings/sections plus the report artifact; keep provider transcript bodies in their native source. ## Implementation

- [ ] Port the two native helper payloads, required argument exclusions, exact report declaration identity and limits. Verify Codex file vs response, reviewed-sha vs unknown-revision, allowed verdicts and bounded assessment file. Claude's active native tool may supply a file without hash for the server to bind at that call. Establish the original declaration's hash with the [worked native receipt](../../specs/review-workflow.md#worked-native-receipt) and input fixtures, including follow-up fields after server binding. Bind a native receipt to one original run/lead/turn/call; strict replay of the same content returns its stored state. The helper prints the compact receipt to the native tool output, including Codex stderr for stdout-redirection cases. A lost POST response gets status lookup, never a blind repeat.
- [ ] Stage metadata and pinned acceptance context in one transaction as pending_completion. After commit subscribe to bounded HISTORY invalidations for that lead and arrange startup wake/tail reconciliation of already pending rows. Keep one active reconciler per run, bounded in total. Prioritize current work, retain durable pending rows if all slots are busy, and release subscriptions on completion/close. Keep marker/source-item ID, source generation and order, provider normal-completion proof when required. Reject superseded turn/call/source identity. Require new proof of order before applying observations from a changed source generation. A final-file handoff may survive a later native failure; a response, unchanged or question needs normal completion. Use the original source's terminal outcome and complete call identity at reconciliation.
- [ ] Read a native-authorized path outside SQLite, check canonical absolute path and regular file identity, hash through one descriptor and recheck metadata/digest before accepting. For response mode require complete final result content across native pages, fixed generation and advancing cursors. Stream file capture through bounded buffers. Bound concurrent captures and keep one verified working artifact per attempt. Compute byte/line/max-line/scalar statistics during capture and store them with the artifact. Coordinate the same statistics with TRANSFER. Never clip a new accepted report to fit a metadata, transcript or MCP response budget. Preserve a legacy previously_clipped marker on import. Reject invalid UTF-8 or empty Markdown without changing the previous accepted version.
- [ ] Implement accepted report continuity using `report_evidence.rs`. Parse the whole authored document once. Recognize real level-three F-number headings; reject duplicate IDs, exclude fenced pseudo-headings, and distinguish explicit blocking metadata from evidence or a quote. Preserve unrecognized legacy sections, standalone questions, qualifications and unrelated cards. Validate selected finding changes and explicit scoped section replacements/removals. For corrections verify current parent, referenced hashes, affected IDs, exact checked revision, unchanged evidence body for presentation and per-finding change for evidence. Only a full review advances fullMrReviewedSha. Use actual latest complete ancestor and cumulative subsequent outcomes for card presentation.
- [ ] Accept through a single store write. Check pending native identity/order, base receipt/hash, disposition version and scoped batch ownership. Insert immutable version, advance current pointer, update semantic attention, save exact batch completion/covered observations when present, resolve only source-proven failures, and call STORE's transaction-local `insert_notification(NotificationObservation) -> NotificationId` for the appropriate deduplicated occurrence with the matching invalidation. Unchanged verifies original source and records outcome against the same accepted version. Needs-input records reason and scoped question without closing the batch. Refresh the relevant published MR outside SQLite for amendments or unchanged processing. A failed CAS/continuity check captures the private conflict artifact and reason in a separate guarded write. Present it as unaccepted. A replayer of an older failure cannot overwrite a newer capture.
- [ ] Reserve a repair request once for a missing/invalid active-turn handoff, then ask HOST to deliver it to that active native context. On uncertainty record the attempt and expose it for reconciliation. Historical turns remain passive. Reopen a pending or verifiable final-file handoff after restart, including an exact file tool succeeding before a later quota interruption. If normal completion/source proof never materializes, persist the explanatory failure, keep previous findings readable and release the reader subscription.
- [ ] Implement metadata-first current/version reads, bounded summary history, section/candidate scalar reads, the exact immutable source attachment, preserved section hashes and disposition version CAS. Serve explicit view=markdown only at or below every bound of 1 MiB, 10,000 physical lines and 16 KiB maximum line. Reject an over-budget rich request before selecting the body and return the metadata needed for a ranged read. Use STORE's sealed artifact chunks (at most 64 KiB) and indexed offsets. Bind the immutable receipt/hash/length and stream bounded batches from the shared dedicated reader, ending each short read snapshot before waiting for network backpressure. Release the artifact stream on cancellation. Use a browser-native download without creating a JS Blob. Unicode code-point offsets count scalars, separate from internal UTF-8 byte offsets and browser UTF-16 indices. Validate receipt and run every time. Keep per-run report viewing monotone; mark only the rendered batch of assessments after its actual pages render. Emit transactional change events for each affected scope, publishing them only after commit.
- [ ] Feedback requires exact displayed receipt and digest, exact quote from an accepted source range with matching Unicode scalar bounds (empty for whole-report feedback), nonempty text, registered originating lead and immutable submission ID. For historical MCP clients that supply only a hash, resolve only their selected run's current matching receipt; ambiguity/stale context requests an explicit receipt. In one transaction enqueue the HOST user message with reportRef including originally displayed and current receipt at send. Identical retry reads the existing delivery receipt. Wake HOST after commit, let it correlate the native input, keep the browser draft on unresolved or failed sends. Decision and publication labels cannot grant external write permission.
