# REPORT · Keep the findings ledger, publish versions and route version-bound feedback

**Start after HOST, HISTORY and SOURCES.** Deliver the findings ledger, the immutable composed report versions, exact review coverage, the unfinished-review state and feedback to the originating lead. Preserve historical versions and user decisions during failure and reconciliation. Use the [workflow and wire contract](../../specs/review-workflow.md#findings-ledger-and-report-versions), [worked review set](../01-foundation/fixtures.md#worked-review-set), [native evidence reader](../02-sessions/history.md) and [native entry points](../02-sessions/entrypoints.md).

**The specification is ahead of the code.** The checkout still implements the earlier single hand-over call that pointed at a finished report. Every item under Implementation is open. The [build plan](findings-ledger-build.md) orders them as tasks: the earlier path is removed first, then the contract, storage and app are built, then the hosts.

## Implementation

- [ ] **Contract.** Generate the six tool inputs, their results and the field limits from Rust. Check the generated schema and the filled example into `contracts/` and `fixtures/contracts/`, and move `make contracts-check` to them. Remove summary fields that only described a captured source.
- [ ] **Storage.** Add the ledger tables, the per-run ledger sequence and the pass table. Keep artifacts, chunks, versions, heads, dispositions and reads. A fresh installation creates the new schema only.
- [ ] **Write tools.** Implement `record_finding`, `assess_finding`, `record_note` and `review_ledger` as one short transaction each. Assign IDs, check the expected revision, apply the three duplicate rules and the stand-alone Markdown rule, and return every field error while the call is open. Bind the caller from what the call carries. Read no transcript and resume no thread on this path.
- [ ] **Passes.** Open a pass from a launch Start, from a delivered selected-thread batch and from the first record on a run with no version. Settle a run from its state: with the lead and every known child idle and no recovery pending, an open pass that is not waiting is unfinished. Report it through delivery, and write its failure row and notification once. Reopen a pass held by `needs_input` when the lead's next turn starts. Record and resolve the failure rows as the specification states.
- [ ] **Compose and publish.** Compose the fixed layout from the records and record each card's and section's offsets. Run the closing-call checks, then publish in one conditional transaction with the bounded recompose on a changed ledger sequence. Publish an update when a settled run has unpublished records and no open pass, and run that check on idle, on a record written while idle, after recovery and at startup. Compare the composed text of the worked review set byte for byte against a checked-in expected file.
- [ ] **Rule, gate and read-back.** Write the rule text once and use it in every launch path, the terminal link, the selected-thread prompt and the read-back. Serve the gate decision with its two-block limit per session and turn. Serve the read-back within 4,000 characters.
- [ ] **Claude host.** Register the tools in the plugin, accept subagent calls for the record tools, and wire turn end, the `Stop` gate and the `SessionStart` read-back.
- [ ] **Codex host.** Serve the tools from the MCP server and bind each call from the request's thread, call, item and turn metadata. Before relying on it, confirm with a live subagent call on the pinned Codex version that the request names the subagent's own thread, and keep refusing a closing tool from any thread but the lead's. Install the `Stop` and `SessionStart` user hooks, and say in the installer and `reviewq link` output while the stop hook has never reported on this installation. Settle runs from the stored session states so an unfinished review shows without the hooks.
- [ ] **Follow-up binding.** Complete FOLLOW's batch inside the publish transaction with the assessments, and record `unchanged` when the pass changed nothing.
- [ ] **Reads.** Serve summaries, history, context pages, sections, the source download and the display window from published versions and their rows. Serve explicit `view=markdown` only at or below every bound of 1 MiB, 10,000 physical lines and 16 KiB maximum line. Keep per-run report viewing monotone and emit change events after commit.
- [ ] **Feedback.** Feedback requires the exact displayed receipt and digest, an exact quote from a published version with matching Unicode scalar bounds (empty for whole-report feedback), nonempty text, the registered originating lead and an immutable submission ID. In one transaction enqueue the HOST user message with its reportRef. An identical retry reads the existing delivery receipt.
- [ ] **Remove the earlier path.** Delete the hand-over tool, its schema and fixture, the report CLI helpers, file and response capture, the source witness, the readback worker, correction requests, heading parsing, the candidate read and the `preparing` and `saving` delivery states. REVIEWUI removes the cards drawn from context rows, the source-only state and the hand-over reason texts. Update the README's Codex hook note for the two hooks.
