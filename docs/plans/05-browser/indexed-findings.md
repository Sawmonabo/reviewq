# Indexed Markdown for accepted Findings

**Proposed design.** Opening Findings should display the correct, selectable report at the reader’s saved position. Rust indexes each eligible, immutable artifact once per index format. The first read carries formatted-view inputs for the destination. React prepares the visible content and a short distance ahead, and releases content the reader has passed. Scrolling, quoting, opening a diagram and switching reports keep the same controls and appearance.

Today the browser admits a report by size, fetches its entire Markdown and runs the Markdown parser. Only then does the virtualizer decide which groups to mount. Hiding off-screen groups saves DOM elements but still charges the opening click for parsing and retaining the whole document. The change below replaces that path for indexed reports. Its scope is the accepted Findings reader. Live Agent transcripts have a different lifecycle, including an unsettled final block. ## Capture, storage and recovery

1. Feed valid UTF-8 chunks in original order to the finished-body cutter during an eligible capture. Finalize at end of input and bind the result to the verified artifact digest. The existing rich limits are inclusive at 1 MiB, 10,000 physical lines and 16 KiB per line. Bound the cutter’s expanding window by the document envelope and stop allocating index work if admission fails. Run parser CPU work outside the SQLite writer and HTTP executor.
2. Store derived metadata under the sealed artifact identity, digest and index-format version. The store owns the index header, ordered block spans, definition lookups and row boundaries for large tables. Store coordinates and compact structural facts. Read bodies from the existing indexed artifact chunks. Repeated receipts for the same artifact share the display index. Every read still verifies the requesting actor, run and accepted receipt. Delete derived entries with their artifact. [Artifact storage](../../../crates/reviewq-store/src/schema/reports.sql) · [Report reads](../../../crates/reviewq-store/src/reports.rs)
3. Compute outside the write transaction, batch index inserts, and publish a ready header only when every entry is complete and matches the sealed digest. Readers see one complete index version. A failed optional index must leave report acceptance, attention, historical reads and feedback available. If indexing fails while capturing, complete the existing acceptance independently. Record the failed format and reason to prevent a new parse on every open.
4. For already accepted artifacts, build on demand from their sealed chunks under one bounded background worker. Coalesce duplicate requests per artifact/version. Do not scan the database on startup. A crash leaves the last ready version usable and incomplete entries reclaimable. Rebuild only on a format change, interrupted build or a deliberate retry of a transient failure. Use the existing admitted rich reader while a compatible index is unavailable. Existing source-only documents retain their paged source reader.

## What a block means

Use half-open intervals with explicit units. A block’s stable identity within one index is its original UTF-8 start byte and its kind. Record its end byte and starting Unicode scalar offset. Convert a browser text node’s local UTF-16 position against the decoded original span before producing a report-wide quote. Preserve CRLF, non-BMP characters, combining marks and identical passages at distinct locations. Generated badges, repeated table headers and injected definitions have no selectable *source* coordinates.

The index supplies structural information the visible window cannot discover on its own.

| Input | Required treatment |
| --- | --- |
| Reference links, images, footnotes and backlinks | Resolve document-wide definitions with the same label normalization, duplicate precedence, footnote numbering and IDs as the existing renderer. Attach only dependencies needed for the window, with bounded size and their original ranges. Feed definitions into the existing parsing pipeline before reference resolution. Keep synthetic context outside the visible tree and quote mapping. A first-screen link must work even when its definition is on the last page. |
| Nested lists, blockquotes, fences, raw HTML and disclosures | Emit complete Markdown units with their enclosing context. Coalesce spans whose HTML tree or list semantics cross a cut. If equivalence to whole-document parsing is uncertain, select the existing admitted whole-document path for that artifact. Record the reason. Preserve final sanitization, URI policy, evidence-link base and attachment handling on every path. |
| Report cover, verdict, counts, sections and finding cards | Rust records source-level heading hierarchy, spans and the neighboring context needed for presentation. React’s existing report presentation module is the single owner of styling, verdict/count synthesis, card grouping and retired-finding placement. Adapt it to consume compact document facts and bounded authored groups. Include enough cover facts to identify a late authored verdict or count before synthesizing one. Associate each finding’s accepted outcome with the version being read. Never run the complete-document presentation routine independently on each page. ## Read contract

Extend the existing versioned report route family and its generated TypeScript validators. The names below are proposed contract shapes. Keep one report reader in the app, one SQLite range query path, and one mapping in transport. [Rust protocol](../../../crates/reviewq-protocol/src/reports.rs) · [HTTP mapping](../../../crates/reviewq-transport/src/entry/features/reports.rs) · [Browser adapter](../../../web/src/api/reports.ts)

| Operation | Result |
| --- | --- |
| Open indexed view on a confirmed run and receipt, optionally at a saved source anchor | Return the receipt, SHA-256, index-format version, summary, compact outline and first **batch of source blocks** in one response. Include document counts, range anchors, required references, relevant accepted outcomes and previous/next cursors. An outline has section/finding anchors and enough structure for jumps. Bound its bytes and page additional descriptors when needed. A saved anchor resolves directly, without walking from block zero. |
| Read neighboring blocks or table rows in either direction | Accept an opaque cursor bound to run, receipt, digest, index version, range kind and direction. Alternatively accept a validated source anchor for a jump. Return ordered whole units under server-enforced item and encoded-byte ceilings. Coalesce neighboring ranges into a small number of chunk reads, closing the read transaction before sending the response. A large table returns its header and a bounded batch of rows. |
| Resolve or verify an exact passage | A selection with known endpoints reads only that scalar range. For pasted text without endpoints, the service searches the authorized immutable artifact incrementally, carries matches across chunks and stops after the second occurrence. Return absent, unique with absolute scalar range, or ambiguous, preserving the existing choice of occurrence. Limit the input to the existing 12,000-scalar quote ceiling. Actual feedback submission rechecks the exact receipt, range and text. |

Reject wrong-run receipts, stale or mismatched cursors and out-of-range coordinates. Validate receipt, digest, index version and current navigation generation after decoding each result. Cancel obsolete reads on run/version changes, close and unmount. A revision announcement leaves the selected receipt and any quote draft in place. Only visible, correctly identified content may trigger the existing viewed acknowledgement. The whole-source download stays an authenticated streaming attachment.

For example, opening a bookmark halfway through a report should read the stored index and the source chunks containing that section. React receives the section with its presentation context and nearby content, then prepares the next batch while the reviewer reads. Opening an ordinary small report may finish in one batch. Neither case needs an extra request just to locate the first visible paragraph.

## Scrolling and one unusually large block

Use the existing drawer scroller and TanStack Virtual. Render the first batch immediately. Prepare the next contiguous batch in the scroll direction while the current content is readable. Schedule viewport misses ahead of speculative work and cancel discarded directions. Start with one pending look-ahead batch per active report. Use measured visible height, scroll velocity and observed fetch/prepare time to size the lead within the byte cap. Three extra blocks was an experiment setting. It is not a bound on the height or time required for a real viewport.

Keep a measured-height cache keyed by stable authored identity and layout width. Anchor by source position plus pixel inset across resize, font settlement, disclosure changes and late diagram sizing. On a same-report refresh retain visible nodes until the replacement is ready. On a different report never paint the old receipt under the new header. Preserve source order separately from display order for retired findings. Release report text, parsed trees, diagrams, observers, requests and any worker on exit. Store only the small bookmark in browser preferences.

Bound both prepared bytes and mounted nodes. Evict farthest unused decoded batches and trees first. Preserve keyboard focus, active selection and disclosure state. For extended selections represent the contiguous source range independently of off-screen nodes. Native copy must retain the expected rendered text, line breaks and table separators, including a selection across a virtual edge. Check keyboard selection, accessibility reading order and the existing browser Find behavior in a real browser. If a bounded strategy cannot preserve an existing interaction, use the admitted rich path for that document shape until parity is demonstrated.

For a long GFM table, Rust indexes **parser-recognized rows** and records header, alignment and source coordinates. Fetch and parse a group of complete rows with its column context before the group enters view. Keep one semantic table, column widths stable across batches, a single visible header, correct row order and identical copy behavior. Honor escaped pipes, inline code, wide cells, wrapping, and the report’s special presentation for outcomes tables. Native table auto-layout can change widths when a previously unseen value arrives. Supply bounded document-wide width hints where appropriate, then verify appearance with the widest value deliberately placed last. Use the admitted rich path if faithful stable sizing cannot be shown.

A fence, paragraph, diagram, table row or HTML disclosure may itself exceed a normal batch. Represent it explicitly as one unit and let the server grant a bounded oversized read within the rich envelope. Prepare costly indivisible units off the input thread only where timings justify it. Keep at most one active preparation job, cancel it on exit and account for transferred bytes and retained parser memory. Compact oversized table-row batches before resorting to this path. Never truncate authored content or publish partially parsed markup as finished.

## Implementation order

| Step | Deliverable | Depends on |
| --- | --- | --- |
| 1. Capture and contract | Specify units, index identity, readiness states, wire ceilings and fallbacks. Adapt and pin the cutter in the existing app reports module. Feed the existing semantic fixture through both coordinate paths. | Existing report capture and source reader |
| 2. Durable reads | Publish/read the derived index, coalesce builds, resolve quote ranges, expose first and continuation batches, and generate browser validators. Show a direct jump on a report accepted before the index existed. | Step 1 |
| 3. Visible reader | Adapt the current reader, virtualizer and presentation to consume the agreed window contract. Reuse the fixture for cover, cards, links, draft/quote and scroll handling. | Step 1 for fixture work, step 2 for real reads |
| 4. Long table and qualification | Integrate row-window reads and table rendering. Recheck real Findings through the Rust service. Keep the full-reader fallback available for unsupported shapes and rollback. | Steps 2 and 3 |

One writer owns the shared contract and generated bindings. Once the contract is fixed, a second writer can work on the React reader using the same fixture. Integrate against the real backend before tuning. Follow the repository limits on worktrees, file length and first-party tests. Reuse one mixed fixture and existing accepted reports. Add a permanent case only for a specific regression that existing checks miss.

## How to decide whether to ship

| Observe on the same build inputs and browser | Acceptance |
| --- | --- |
| First open and return to a bookmark, cold and warm | Compare the current and indexed builds on small, typical, largest and long-table reports. Measure click to first **painted, selectable, correct** content with usable controls, plus transferred bytes, requests and main-thread parse time. Show a repeatable end-to-end improvement on large reports and no repeatable small-report regression. Separate normal indexed opens, first open during index build, and fallbacks. |
| Wheel and physical trackpad in both directions, fast fling, scrollbar jump, keyboard and split-pane resize | Inspect presented frames and filmstrip at native refresh. Apply the existing FRAME budget of p95 at most two display periods and at most 1% compositor-classified janky scroll frames. Visible gaps, reproducible stutter, flicker or a shifted reading anchor fail regardless of the median. Check the coldest table window and a jump to an uncached location. |
| Output and interaction | Compare at the same report, receipt, width and scroll position. Include verdict/counts, finding cards and retired findings, links defined later, nested markup, diagrams, table alignment and statuses, native selection/copy, repeated Unicode quotes, keyboard focus, original source/download and an update during an unsent quote. Compare values/offsets as well as screenshots. |
| RAM during sustained use | Record Chrome’s displayed tab memory, active renderer working set, JS heap, retained DOM/decoded bytes and Rust RSS separately. Measure the peak and the same quiet return while repeatedly switching reports over 30–60 minutes. Show a reproducible reduction for large Findings and release of inactive content, with no continuing per-cycle growth. The existing absolute patch RAM budgets apply to Changes. No everyday Findings tab ceiling has been agreed. |
| Cost shifted to capture or storage | Measure capture latency, index bytes per source byte, SQLite write duration/queue wait and concurrent read latency while saving reports. Count fallbacks by reason. A lingering request per block, silent whole-report reads on the indexed opening path, or recurring rebuild on each open requires a fix. |

The component benchmark supports trying this architecture. Production claims about opening speed, scroll smoothness and tab RAM require the integrated reader on real reports.
