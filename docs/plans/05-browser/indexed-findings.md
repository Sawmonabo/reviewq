# Indexed Markdown for accepted Findings

**Implementation in progress.** Opening Findings should display the correct, selectable report at the reader’s saved position. Rust reuses an index for an eligible immutable artifact while that format is cached. The first read carries formatted-view inputs for the destination. React prepares the visible content and a short distance ahead, and releases content the reader has passed. Scrolling, quoting, opening a diagram and switching reports keep the same controls and appearance.

The accepted Findings reader prepares the destination and nearby authored groups from indexed source windows. It uses the admitted whole-document reader when the report is small, its index is unavailable, or its document structure needs full context. Live Agent transcripts have a different lifecycle, including an unsettled final block. ### Implemented scope

When a version is published, the Rust publisher passes the composed text to the pinned display parser. It cuts it in whole-line windows and stores kinds, original UTF-8 byte ranges, Unicode scalar and UTF-16 starts, and bounded heading snippets in a derived sidecar. The stored composed text and the version's finding and section rows remain authoritative. A failed cache write leaves the accepted report readable. [Publisher](../../../crates/reviewq-app/src/ledger/publish.rs) · [Cutter](../../../crates/reviewq-app/src/reports/display/cutter.rs) · [Cache](../../../crates/reviewq-store/src/connection/display_cache.rs)

The version-bound window API serves bounded source blocks, a verified report summary and an optional directory for opening the indexed reader. The directory contains source and layout inputs. The browser owns the verdict, count and finding-card presentation. Read accepted outcomes through the existing receipt-bound context operation. Cache misses schedule one on-demand build at a time from eligible sealed chunks. A capture and an opening request for the same artifact share a build claim. The cutter records a fallback for reference definitions, raw HTML and ambiguous list boundaries. Moving a line containing only `*` into its own browser parse can turn paragraph text into an empty list. The whole-document reader preserves that context. Tables already outside the native rich budget can open bounded row groups when the server can verify their top-level structure. Documents that need full context still use the existing reader.

The browser requests the layout on opening reports of at least 64 KiB, or at least 24 KiB with accepted changes. Reports that fit the existing nonvirtual reader keep that presentation. Larger virtualized reports use the same cover, cards, outcomes, table formatting and section controls with bounded authored groups. A group can combine several native reads up to 128 KiB. The reader reserves up to 320 KiB of decoded source for the visible groups, nearby source and recently prepared groups. An active native selection or keyboard focus can retain additional previously rendered groups from the same admitted report until released. Bookmarks retain the source coordinate and the position of that group in the drawer. Native selection supplies an absolute Unicode scalar range. Pasted text uses the receipt-bound resolver. ## Capture, storage and recovery

1. Feed valid UTF-8 chunks in original order to the finished-body cutter when a version is published. Finalize at end of input and bind the result to the verified artifact digest. The existing rich limits are inclusive at 1 MiB, 10,000 physical lines and 16 KiB per line. Bound the cutter’s expanding window by the document envelope and stop allocating index work if admission fails. Run parser CPU work outside the SQLite writer and HTTP executor.
2. Store derived metadata under the sealed artifact identity, digest and index-format version. The store owns the index header, ordered block spans, definition lookups and row boundaries for large tables. Store coordinates and compact structural facts. Read bodies from the existing indexed artifact chunks. Repeated receipts for the same artifact share the display index. Every read still verifies the requesting actor, run and accepted receipt. Authorize against the sealed source on every read even if cached entries outlive an artifact. Retire unreachable entries under the cache retention bounds. [Artifact storage](../../../crates/reviewq-store/src/schema/reports.sql) · [Report reads](../../../crates/reviewq-store/src/reports.rs)
3. Compute outside the write transaction, batch index inserts, and publish a ready header only when every entry is complete and matches the sealed digest. Readers see one complete index version. A failed optional index must leave publishing, attention, historical reads and feedback available. If indexing fails while publishing, complete the publish independently. Record the failed format and reason to prevent a new parse on every open.
4. For an index miss, including on an already accepted or evicted artifact, build on demand from the artifact’s sealed chunks under one bounded background worker. Coalesce duplicate requests per artifact/version. Do not scan the database on startup. A crash leaves the last ready version usable and incomplete entries reclaimable. Rebuild after eviction, a format change, an interrupted build or a deliberate retry of a transient failure. Use the existing admitted rich reader while a compatible index is unavailable. Existing source-only documents retain their paged source reader.

## What a block means

Use half-open intervals with explicit units. A block’s stable identity within one index is its original UTF-8 start byte and its kind. Record its end byte and starting Unicode scalar and UTF-16 offsets. Convert a browser text node’s local UTF-16 position against the decoded original span before producing a report-wide quote. Preserve CRLF, non-BMP characters, combining marks and identical passages at distinct locations. Generated badges, repeated table headers and injected definitions have no selectable *source* coordinates.

The index supplies structural information the visible window cannot discover on its own.

## Read contract

### Source block windows

Use `GET /api/v1/runs/{runId}/report/versions/{receiptId}/window?sha256={digest}` for the first batch. Supply either `byteOffset` for an original UTF-8 byte position or a returned `cursor` for an adjacent batch. Byte ranges are half-open. An anchor in leading blank space resolves to the first authored block, exactly the document byte length resolves to the final block, and an anchor past the document returns a range error. The original block interval includes its indentation and intervening whitespace. Use the source reader for leading blank bytes before the first authored block.

The response carries the report summary, index format and result state. A ready format 2 result includes the total number of blocks and an ascending batch of up to 32 blocks and 64 KiB of source. Each block carries its original byte start and end, starting Unicode scalar and UTF-16 offsets, kind, optional heading level and exact Markdown. JSON is capped at 640 KiB. Previous and next cursors bind the run, receipt, digest, format, source-block anchor and direction. Cache eviction may temporarily return a building state for a continuation.

Pass `layout=true` on an opening request or an anchored read to return the source-ordered directory with that batch. The directory gives total byte, scalar and UTF-16 lengths and the coordinate, kind and heading-level records for up to 512 authored blocks. Top-level H1–H3 entries include exact heading Markdown, with at most 1 KiB per heading and 16 KiB in total. The header and cached span coordinates are checked against the sealed source during range reads. Ordinary requests query only their bounded span range and neighboring endpoints.

Pass `byteOffset` and exclusive `byteEnd` together to read a precise range between indexed block boundaries. The document end is a valid `byteEnd`. A range that splits a block or exceeds the batch limits returns a range error. A presentation group can combine adjacent bounded reads using the directory. Exact reads and cursor requests omit the directory. Byte positions in leading blank space resolve to the first authored block for anchored reads. Exact reads use the first authored block’s actual start.

Format 2 admits complete tables that fit a bounded block and contain at most 128 body rows. It uses the existing rich source limits and a conservative additional admission budget for native events, nesting, literal links and ragged table padding. Unsupported documents or blocks that exceed these limits use the existing fallback. The browser still validates and sanitizes every rendered group.

Use `GET /api/v1/runs/{runId}/report/versions/{receiptId}/table?sha256={digest}&byteOffset={byte}` to page the table under the same receipt and digest. Each table page carries up to 48 authored rows and their original byte and scalar starts, plus the header and stable column widths. The same reader opens before the rows when the document has an introduction and continues to any authored content after the table. Later groups repeat the header without assigning it new source coordinates. Offset jumps re-seek the sealed chunks after authorization. The original Markdown and attachment remain available.

A building result lets the reader retry the same bounds. A known unsupported document or unavailable cache returns a fallback reason. A cache miss for another artifact can return busy while the single worker is occupied. The existing report context endpoints supply semantic findings and dispositions. [Window handler](../../../crates/reviewq-transport/src/entry/features/reports/window.rs) · [Window store](../../../crates/reviewq-store/src/connection/display_cache/window.rs)

### Resolve a pasted passage

Send `POST /api/v1/runs/{runId}/report/versions/{receiptId}/quote/resolve` with the browser write proof and with `sha256` and exact `text` in the JSON body. The read-only operation checks the accepted version and the 12,000-scalar quote limit. It scans the sealed source within the rich source envelope and carries a bounded UTF-8 suffix across chunk boundaries. It stops after the second match, including an overlap with the first. The result binds the receipt and digest and returns `missing`, `ambiguous`, or `unique` with the absolute `offset`, `length` and `unicode_codepoints` unit. Feedback submission still verifies the supplied source text and range against the same version.

For example, opening a bookmark halfway through a report should read the stored index and the source chunks containing that section. React receives the section with its presentation context and nearby content, then prepares the next batch while the reviewer reads. Opening an ordinary small report may finish in one batch. Neither case needs an extra request just to locate the first visible paragraph.

## Scrolling and one unusually large block

Use the existing drawer scroller and TanStack Virtual. Render the first batch immediately. Prepare the next contiguous batch in the scroll direction while the current content is readable. Schedule viewport misses ahead of speculative work and cancel discarded directions. Start with one pending look-ahead batch per active report. Use measured visible height, scroll velocity and observed fetch/prepare time to size the lead within the byte cap. Three extra blocks was an experiment setting. It is not a bound on the height or time required for a real viewport.

Keep a measured-height cache keyed by stable authored identity and layout width. Anchor by source position plus pixel inset across resize, font settlement, disclosure changes and late diagram sizing. On a same-report refresh retain visible nodes until the replacement is ready. On a different report never paint the old receipt under the new header. Preserve source order separately from display order for retired findings. Release report text, parsed trees, diagrams, observers, requests and any worker on exit. Store only the small bookmark in browser preferences.

Bound both prepared bytes and mounted nodes. Evict farthest unused decoded batches and trees first. Preserve keyboard focus, active selection and disclosure state. For extended selections represent the contiguous source range independently of off-screen nodes. Native copy must retain the expected rendered text, line breaks and table separators, including a selection across a virtual edge. Check keyboard selection, accessibility reading order and the existing browser Find behavior in a real browser. If a bounded strategy cannot preserve an existing interaction, use the admitted rich path for that document shape until parity is demonstrated.

For a completed, admitted expensive GFM table, Rust projects parser-recognized cells, headers, alignment and original source positions into a validated packet delivered with its source window. Render the entire admitted semantic native table. Charge the source, packet, decoding in flight and DOM to the same budget. Keep unsupported syntax on the canonical whole-table path. Verify distant-row native Find, exact native text/plain and text/html clipboard, quote coordinates, accessible row/header/link counts and the true column widths with the widest value last. Only a table already outside the native document envelope uses bounded row groups with a stable header, width hints and exact source access.

A fence, paragraph, diagram, table row or HTML disclosure may itself exceed a normal batch. Represent it explicitly as one unit and let the server grant a bounded oversized read within the rich envelope. Prepare costly indivisible units off the input thread only where timings justify it. Keep at most one active preparation job, cancel it on exit and account for transferred bytes and retained parser memory. Compact oversized table-row batches before resorting to this path. Never truncate authored content or publish partially parsed markup as finished.

## How to decide whether to ship

| Observe on the same build inputs and browser | Acceptance |
| --- | --- |
| First open and return to a bookmark, cold and warm | Compare the current and indexed builds on small, typical, largest and long-table reports. Measure click to first **painted, selectable, correct** content with usable controls, plus transferred bytes, requests and main-thread parse time. Show a repeatable end-to-end improvement on large reports and no repeatable small-report regression. Separate normal indexed opens, first open during index build, and fallbacks. |
| Wheel and physical trackpad in both directions, fast fling, scrollbar jump, keyboard and split-pane resize | Inspect presented frames and filmstrip at native refresh. Apply the existing FRAME budget of p95 at most two display periods and at most 1% compositor-classified janky scroll frames. Visible gaps, reproducible stutter, flicker or a shifted reading anchor fail regardless of the median. Check the coldest table window and a jump to an uncached location. |
| Output and interaction | Compare at the same report, receipt, width and scroll position. Include verdict/counts, finding cards and retired findings, links defined later, nested markup, diagrams, table alignment and statuses, native selection/copy, repeated Unicode quotes, keyboard focus, original source/download and an update during an unsent quote. Compare values/offsets as well as screenshots. |
| RAM during sustained use | Record Chrome’s displayed tab memory, active renderer working set, JS heap, retained DOM/decoded bytes and Rust RSS separately. Measure the peak and the same quiet return while repeatedly switching reports over 30–60 minutes. Show a reproducible reduction for large Findings and release of inactive content, with no continuing per-cycle growth. The existing absolute patch RAM budgets apply to Changes. No everyday Findings tab ceiling has been agreed. |
| Cost shifted to capture or storage | Measure capture latency, index bytes per source byte, SQLite write duration/queue wait and concurrent read latency while saving reports. Count fallbacks by reason. A lingering request per block, silent whole-report reads on the indexed opening path, or recurring rebuild on each open requires a fix. |
