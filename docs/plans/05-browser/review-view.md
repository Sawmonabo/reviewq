# REVIEWUI · Inspect the ticket, code and accepted findings

**Start after CHATUI and FOLLOW.** SHELL supplies the shared entry point. Use the accepted CHATUI composer for the end-to-end quoted feedback check. Extend the working [first review](../01-foundation/first-review.md) using SHELL’s confirmed run and the shared fixture. Integrate with the [queue and source contracts](../../specs/queue-and-settings.md) and [review workflow](../../specs/review-workflow.md). **Outcome** is one review drawer with a readable ticket, revision-bound Changes, accepted findings and the exact delegated Agent conversation. [Browser experience](../../specs/browser-experience.md)

## Files and contracts

The proposed [indexed Findings reader](indexed-findings.md) replaces the whole-document opening path described below for eligible indexed reports. It defines opening at a bookmark, fetching nearby content, displaying long tables and qualifying the integrated reader. The whole-document path remains the reference for formatting and interaction parity.

Extend `web/src/features/review/ReviewDrawer.tsx` and `review/changes/{Changes.tsx,patch-document.ts}` under `features/`. Own `features/review/{Findings,Followups,DiscussionThread}.tsx`, `features/Tickets.tsx`, their private styles, and typed review/ticket read adapters under `web/src/api/`. SHELL composes `Tickets` into the review drawer and the standalone unmatched-ticket place. Within review, Changes and Followups share DiscussionThread. CHATUI supplies AgentPanel and the report-aware Composer. Consume their accepted props.

| Consumer | Input and behavior |
| --- | --- |
| ReviewDrawer | Confirmed MR, optional selected lead and child, tab, navigation callbacks, ticket content slot and terminal/menu commands. MR-scoped resources survive a run change. Select a different lead to change metadata, history, report and action target together. Present a missing/removed target explicitly. |
| Tickets | Qualified ticket keys, selected ticket and service’s detail projection for the selected key. Fetch detail and comments only when visible. When paging the same ticket, consume the comment-only continuation described in [SOURCES](../03-workspace/sources.md#build-the-reads). Render one ticket at a time with source URL. A ticket-only queue row supplies the same component. |
| Changes | `GET /api/v1/reviews/{reviewId}/changes/files` gives revision identities, opaque file IDs, paths, counts/status. Load `discussions` and `approvals` separately. A signed file-page continuation may request original text at the incoming edge (`previewEdge=start|end`). Rust can return up to three verified complete patches from that scan, each at most 32 KiB and together at most 64 KiB. An initial read, jump or restoration with `includeSelectedPreview=1` may instead receive one verified selected patch of up to 128 KiB. The browser consumes each body once under its file identity and SHA-256. Other admitted files use the revision-bound raw patch route. Walk the signed page cursors as the user scrolls and resolve distant path jumps with the pinned file index. Validate response file, ETag/revision and request generation before mounting. Never accept a patch or thread result keyed by display path alone. |
| Findings | `GET /api/v1/runs/{runId}/report` selects the current accepted report. `history`, `versions/{receiptId}`, `section` and `context` address the exact content/version. Bind `POST …/report/feedback` to the displayed accepted receipt/hash, optional quote and lead. Bind `…/report/viewed` to the actually displayed receipt and exact batch where applicable. A background refresh does not mark a newly announced version viewed. Maintain a separate draft when changing version. |

## Build the drawer

- [ ] Header shows ticket/MR breadcrumb, title, Runs selector, persistent action menu and explicit Close. Opening an MR lands on **Overview**. The other lead tabs are **Agent, Findings, Changes**. The shell passes the ticket, Agent and composer into the drawer through the existing slots. Preserve the tab and validated run on direct links and reload. With a child selected show lead breadcrumb and **Conversation, Result**. When a pending load finishes, never steer an old-history link to the newest run or reset the active child.
- [ ] In Overview, lead with the full selected Jira ticket. Keep status, type and external Jira link on one line when space permits. Wrap Priority, Story Points, Assignee and Reporter as compact aligned label/value pairs. Preserve zero points, unestimated and unavailable as distinct values. Use the Jira wiki normalizer for ticket descriptions and comment bodies. Keep code literal, map headings, lists, tables and labeled links, and display unfamiliar macros intact. Include key selector for multiple tickets, priority, labels/components, description, warnings, sorted comments with author/time/permalink and long-comment expansion. Below, show actual MR title, registration/run/session identity, source and reviewed revisions, discussion/review state, real cwd, requested/reported model/effort, skill, original request and reported plan when present. One readable outer scroll area. With no registered lead, offer Prepare review and Register run.
- [ ] In the persistent menu, expose Open in terminal, Copy terminal command, Open MR in GitLab, eligible cancel-auto-resume, enabled/paused monitoring and thread configuration, and locally applicable Follow-up handled, Review complete, Waiting on author and Clear local review record. Capture the observed MR revision and checkpoint, guard duplicate requests, then render the resulting status or stale-head rejection by the original MR after menu close and tab changes. Reading a report or thread does not mark it handled. Keep settings for monitored threads on their named lead, selected discussion IDs, frozen original note IDs and specific save result. Confirm a bulk-monitor preview for each affected MR.
- [ ] In Changes, keep the file chooser/search and previous/next reachable above the continuous list of actual patches. Implement [filename and code search](../../specs/browser-experience.md#search-in-changes) against the shared Rust reader. Track the visible file and restore its saved position on return. List all files with paths, statuses, counts and renamed source, including binary, generated, deleted, empty, unavailable or provider-limited entries. Provide Files, General comments, All conversations, Involving you and Any/Open/Resolved. Conversation totals count whole threads after filters and accessibly report zero. File counts remain stable. An earlier-revision thread links to the actual original placement. A truly empty section and a filtered-empty section have distinct actions. One Filters button opens both participant and status choices. Reset returns focus to Filters and preserves file search and review selection. Display MR approval requirements as a compact, independently loaded disclosure with applicable rules, progress, approvers, optional rules, last checked time and unavailable state. The personal approval badge has its own provenance.
- [ ] Before rich rendering, check the exact size, row count and maximum line length from the selected index/report summary. Apply all inclusive limits in [Full document and bounded source modes](../../specs/browser-experience.md#full-document-and-bounded-source-modes). Guard the ordinary body reader while reading the stream as well, before concatenating text. If declared size/rows are missing or actual bytes exceed the budget, cancel, release tentative data and switch to the source reader. Do not mount a partial DOM marked complete. Invalidate the old range when the review, revision or file changes. Identical file bytes can retain the same ETag across revisions.
- [ ] Build the patch source reader against the same exact patch URL. If the file entry has a strong `patchETag`, send it as `If-Match` on the first range. If it is unknown, request one unconditional range at the exact review/revision/file URL. Check the 206 response’s three identity headers, Content-Range and strong whole-content ETag before displaying it. All later requests use that ETag with `If-Match`. Request at most 64 KiB per range and reach the last range via suffix. A new revision invalidates old anchors and range state even when its bytes and ETag are identical. Scroll through adjacent ranges in the outer file stream. Retain at most three displayed ranges and one in-flight request per admitted source file. Restore the same byte and its wrapping context on return. Decode contiguous text across boundaries or show explicit byte continuation at arbitrary seeks. Keep selection and exact text while same-revision updates arrive. A 412 prompts a fresh version choice, 416 refreshes length/coverage, and a 200 response to a range request must be canceled before decoding an oversized body. Do not place current inline threads against guessed line numbers in a source excerpt. Use a direct authenticated download link to the raw patch with `download=1` only for a complete source. Give an omitted/upstream-limited file its source link and explicit limit.
- [ ] Keep `patch-document.ts` free of React. Each mounted handle owns compact searchable native text, a keyed lookup for anchors and an explicit release. Add rich decorations to visible and nearby blocks and retain active selections, focus and open threads. Reuse the underlying text when decorations mount or leave. Preserve hunk headers, tabs/whitespace, old/new numbers, typed additions, removals and context. Advance both counters correctly across hunks and the no-newline marker. Preserve syntax styling, line/source links, native clipboard ordering and natural text wrapping. Keep gutters and discussion widgets out of code copied across lines. Expose stable containers for relevant thread IDs. React portals render discussion UI. A same-revision event adds or updates only the affected discussion. A metadata refresh must neither refetch the patch nor replace code text nodes. A revision change prompts the reader before replacing a selected passage, then discards incompatible anchors. Avoid retaining both a parsed array of code strings and a mounted DOM long-term. Release old raw data, portal roots, code nodes, observers and pending requests on exit. [React portal API](https://react.dev/reference/react-dom/createPortal) · [GitHub diff engineering](https://github.blog/engineering/architecture-optimization/the-uphill-climb-of-making-diff-lines-performant/)
- [ ] Display accepted Findings with a readable verdict/header, section links, principal flow/diagram, before/after rows, finding groups, prior-thread outcomes and verification limits. Preserve original order, links and evidence for unsupported formats. Render outstanding, carried and rechecked findings with their actual severity, blocking disposition, evidence, location, why it matters and proposed comment. Fixed/withdrawn/superseded items can be summarized only as established by the report. A scoped recheck keeps unassessed findings visible at their own checked revision. Separate “fixed in code” and “resolved in GitLab.” Distinguish no accepted report yet, retained version plus failed new handoff, pending completion, report history and unchanged follow-up result. A new accepted version offers **Updated findings available**. Switching is explicit. Show failed delivery beside the retained accepted version.
- [ ] Read `report?view=summary` or `versions/{receiptId}?view=summary` first. Read structured findings/changes from receipt-pinned context pages on demand. For `semanticIndex=source_only`, show the original version in the source reader with an indexing status and keep its quote/download controls available. Only an admitted rich document requests `view=markdown`. Perform bounded input checks before parsing and count retained nodes/depth before passing the parsed tree to React. If the parser/formatter cannot stay within the rich envelope, release the result and show source mode. For a large report call `report/section` with the exact receipt ID, offset and up to 12,000 Unicode scalar values. Jump to End with `max(0,totalCodePoints-12000)`, display visible range/total, and offer explicit Previous/Next and streaming `report/versions/{receiptId}/source?download=1`. Keep only one source window. For verbatim text, anchor the selected source node, map its UTF-16 offsets to document Unicode scalars and verify the exact immutable substring. For a selection crossing Markdown styling, entities or generated nodes where visible text differs from raw source, open the pinned source at the authored section, preserve the draft and let the user confirm or adjust the exact excerpt. Submit a `quoteRef` containing offset, length, unit `unicode_codepoints` plus the accepted receipt/hash and exact text. The service verifies the range, including at duplicate passages and after a newer acceptance. A stale response cannot relabel the selected text. The whole-document report hash always refers to original UTF-8 bytes.
- [ ] For an identified finding on the *current* accepted report, open **Edit disposition** beside its existing local disposition. Show original severity/evidence and current choices. Let the user change blocking and/or recorded publication status (withheld, authorized, published), require a reason, then explicitly **Save disposition**. Capture `{submissionId,expectedVersion,receiptId,findingId,disposition:{blocking?,publication?,reason}}` from the displayed report/context. Submit `PUT /api/v1/runs/{runId}/report/dispositions` once and read back the edited finding and new disposition revision before showing Saved. For a conflict retain the draft, reload current report/dispositions, show what changed and require explicit review before a new save. A changed report receipt cannot reuse the old submission or silently move the edit. Historical versions show read-only dispositions at supersession. Preserve unedited findings, private quoted drafts and independent publication receipts. Saving a local disposition has no GitLab side effect.

- [ ] Reuse `lib/parse-markdown.ts` and `components/markdown/{MarkdownContent,MermaidDiagram}.tsx` across report, discussion, tickets and native text. Coordinate with SHELL for these shared files. Parse whole-document Markdown semantics once for the active version, preserving offsets for quotable source and section targets. Use measured semantic blocks for long report rendering, avoid splitting a table row, disclosure or code fence, and scroll headings in the same drawer. Safely allow known GFM/Markdown and supported HTML details through a final sanitizer. Resolve evidence links with the source base and allowed protocols. Display attachment images as links. Lazy diagrams use strict Mermaid, stable IDs, keyboard zoom/Fit, pointer-centered zoom/pan, source fallback and complete graph fit in their panel. Preserve diagram source for text-only access. A malformed block should affect only that block.
- [ ] Pass the exact captured accepted receipt/hash and optional authored reference/quote to CHATUI for report feedback. A report update during editing does not relabel the quote. Keep the original source as the authority for feedback and do not use rendered text’s transformed offsets to recompute its hash. Each tab uses the shell’s initial-busy and local retry states, retains the readable current resource on a transient refresh and tears down its heavy readers when hidden.

## Prove the result

Use the worked Active and Large files for raw digest, Find at last line and cross-line copy. While reading a wrapped Unicode line and selecting across neighboring lines, add a discussion below, then above. Confirm same node/selection, viewport offset, focus, unchanged file request count and stable scroll during a fast gesture. Change revision while feedback/selection is active. Inspect an old-side deletion, rename, missing/binary patch and earlier thread. Open ticket 0 points and an unknown estimate. Read a long report with a table, diagram and a carried finding, capture an earlier-version quote and receive an updated version before sending. Verify the source receipt in the actual submission. Show the visible stale-revision outcome of a local decision. Record populated desktop/narrow/touch views, bytes retained on exit, and enough context to repeat any visual regression. Include a generated oversized single Unicode line and one over-limit report containing the same quote twice. Observe the last text through End, verify bounded network reads and exact second-quote source coordinates, and compare a streamed download’s hash to the original fixture. Against real handlers after FOLLOW and before PACK, save one disposition on the current receipt and force a second-tab conflict. Verify its reason/version on reopen, zero GitLab mutations, unchanged sibling findings and read-only historical view. Verify quote receipt, bound file bytes and ticket through the ordinary client. Run `make web-check`, `make web-build`, `make web-test`. Use [browser qualification](../06-release/browser-qualification.md) for filmstrips, device and memory checks.
