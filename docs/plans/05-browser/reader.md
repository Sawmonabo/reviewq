# Reader delivery graph

Implement the [reader design](../../specs/review-reader.md) through the production Rust and React entry points. Reuse the existing review drawer, native readers, patch lease, report preparation, generated contracts and fixture generator. Each row owns a vertical change through its first real caller. Shared router registration, schema generation and lockfiles have one writer at a time. Generate from Rust via `make contracts`. Regenerate after integrating a predecessor when both changes touch the schema. Generated output is reviewed with its consumer.

Use the [dispatch and cleanup procedure](../roadmap.md#dispatch-and-merge). Run two independent writers only when ownership permits, in the primary checkout and one temporary worktree. Each writer returns the candidate SHA, caller, commands, observed result and outstanding obligations. The independent reviewer checks the exact candidate. Merge locally, push main and verify the remote SHA, remove the consumed worktree and branch, then base the next writer on current main. Run focused checks per slice and `make check`, `make web-build` and `make web-test` at integration. Do not count a research prototype or a mock response as shipped behavior.

## Integration sequence

Start Navigation in the primary checkout and Source ranges in the temporary worktree. Merge the first accepted candidate immediately; update the other writer from that revision. Live Markdown and Ticket paging have no dependency on the patch wire format. When Source ranges lands, prefer Rich diffs for the second slot. MR notes and Transcript Find each need a protocol export: serialize their registration and regeneration, or land the first complete route before assigning the second. Coordinate edits in the diagram component between Navigation and Diagrams. Settled documents and Diagrams share report window metadata; integrate that field once through the first consumer and rebase the other. The lead owns combined qualification and promotion of the exact accepted bundle.

## Qualification handoff

For Changes, use a multi-hunk old/new rename, a 30,000-line file with comments and a dense Unicode line returning a short byte-capped page. Load the second discussion page, then edit, resolve or delete a note without changing head. Verify code under filtering, displayed inline replies, original source copy in both directions, keyboard and pointer access, and the final resting line after deliberately reordered responses.

For Agent and Findings, run one Claude and one Codex conversation containing an oversized tool body, a message with late definitions, duplicate folded occurrences, mixed prose and streaming diagrams, and a saved table with a quote target. Type while a previous result is pending, visit a distant occurrence, switch between lead and child and return. Recheck displayed text, tooltip, source, outline, focus, draft, quote and accessible control roles in the ordinary and narrowed drawer. For drawings compare the actual original and cached output, including labels, fitted font size, edges and manual zoom. Exercise known miss, evicted hint and absent producer. Capture cold and warm numbers separately and test the installed fallback on a clean profile.

For sustained use, keep each headless browser process and shared service alive, replay alternating navigation, read/idle periods and simultaneous tabs, and record peak, settled and final values without forcing garbage collection. Also compare foreground-read latency during a derivative build, open the same artifact from two tabs, cancel one reader, then exit and restart with a half-built artifact. The inactive view must release its subscriptions, source buffers and DOM. The retained durable review state and native transcripts stay intact.
