# SHELL · Keep the workspace and selected review stable

**Needs** the accepted [first review](../01-foundation/first-review.md), its generated wire types and the [worked fixture](../01-foundation/fixtures.md). **Outcome** is one working browser entry with navigation, a resizable detail pane, confirmed selection and recoverable reads. Hand the working queue, Changes and Agent implementations from SLICE to their feature owners. The [browser experience](../../specs/browser-experience.md) defines the user-facing behavior.

## Ownership and interfaces

Own `web/src/{main.tsx,app/App.tsx,app/selection.ts,api/client.ts,api/events.ts}`, shared view preferences and scroll logic in `lib/view-preferences.ts` and `hooks/useScrollPosition.ts`, shared controls and `styles/{base,tokens}.css`. Keep a single writer for shared package/lockfile, route composition and tokens through the screen wave. Feature owners own feature styles and their API operation modules. They request dependency additions and submit their real component exports to the shell owner for registration. Keep generated files in `api/generated/contracts.ts` under CONTRACT ownership. No source file imports sideways between features. [Web rules](../../../web/AGENTS.md) · [Import boundaries](../../../web/dependency-cruiser.mjs)

| Consumer | Interface |
| --- | --- |
| Routes | `App` owns a confirmed target with MR key, run ID, native lead key, optional child key, active tab and selection generation. Keep the requested route separate while detail is loading. Only a matching service response confirms the lead/child relationship. Pass these keys as read-only props and use shell callbacks for user navigation. |
| Queue, Runs, Notifications | Compose `app/views/{QueueView,RunsView,AttentionView}.tsx` in `App`. Each receives its current criteria and callbacks to open a qualified MR, exact run or ticket. QUEUEUI owns the screen contents. |
| Review drawer | Mount `features/review/ReviewDrawer.tsx` with confirmed selection, requested tab, close/resize/navigation callbacks and slots for the linked ticket, Agent and report composer. The drawer composes Findings and Changes with those slots. Supply a sibling ticket-only pane and the Settings dialog from the app. |
| API | A typed operation supplies path, verb, request parameters, generated standalone runtime validator and AbortSignal. JSON reads decode `{data,cursor}` and failures decode `{error:{code,message,retryable},cursor}`. Use CONTRACT’s generated TS/validators from the Rust schema. The selected raw patch has its own content type, ETag and checked identity. One global EventSource at `/api/v1/events` consumes `invalidate` with a decimal-string ID and `{resources:[{kind,id?}]}`. On `reset`, discard the obsolete cursor, read a fresh snapshot and reconnect. CHATUI alone opens the scoped native-history stream for the visible Agent. [Wire contract](../../specs/data-contracts.md) |

## Build and verify

- [ ] Promote the existing M1 entry in place. Consume real M1 data all the way through queue → run → diff → agent → send. Keep startup JS limited to shell and visible controls. Register lazy bodies only with their working caller. Compose the accepted screen exports through typed props and slots. Use the shared seeded service for ordinary browser checks. For a delayed or failed response the driver cannot reproduce, intercept just that request through Playwright’s route API and preserve the production client and contract validator. Verify the feature against its real handlers before PACK. [Task prerequisites](../roadmap.md) Check a production cold page makes no remote asset requests and a queue visit loads neither Mermaid nor a diff/report/transcript body.
- [ ] Provide shared action menus when their first roster of real actions is available. Add `@radix-ui/react-dropdown-menu` through the one manifest owner, style it to match the toolbar and attach portals to the correct active dialog container. Support arrow keys, typeahead, keyboard dismissal, viewport collisions and restored opener focus. Use native selects and dialogs for ordinary controls. [Radix Dropdown Menu](https://www.radix-ui.com/primitives/docs/components/dropdown-menu)
- [ ] Implement route parsing and History API navigation for the query parameters in the spec. For a bookmarked MR/run pair, call `GET /api/v1/reviews/resolve` with the opaque `reviewId` and optional `runId` from the URL. Confirm `{reviewId,runId,leadSessionKey}` before enabling actions. Resolve a saved link or notification directly without enumerating queue pages. Keep an unavailable/mismatched explicit target visible with a picker and actions disabled. Validate supported view/tab values, handle an invalid or mismatched explicit run, client-rendered direct loads, Back/Forward and reload. Clamp restored panel width to the current viewport. Store only small presentation preferences and bookmarks per tab. On a second tab selecting the other `!41`, neither tab may inherit the other's child, draft or selected run. Browser storage denied or malformed must still open the workspace.
- [ ] Own the shared memory-only draft store, admissions and named draft overflow list. Supply scoped methods to CHATUI/REVIEWUI through props. Charge all dirty/in-flight revisions and shared quotes against the exact count and byte policy in the [workspace state contract](../../specs/browser-experience.md#opening-and-restoring-a-review). Use service-returned per-field protocol limits when validating sends. Copying a saved draft or changing routes must not dispatch it.

- [ ] Lay out sidebar, independently scrolling workspace and labeled review aside. At desktop start with 47% for the list and 53% for the review after the sidebar and use a focusable vertical separator with its min/max/value. Arrow keys adjust 20px, Shift+Arrow 50px, Home/End reach limits and double-click restores equal widths. Provide a compact sidebar, a mobile return control and readable focused titles when collapsed. Prevent wheel chaining over headings, empty panes and scroller edges. Scope focus and restoration by view and opener. Retain scroll bookmarks through resize and background reads.
- [ ] Implement initial loading, empty, stale, offline, unauthorized, partial and retry presentations with localized error boundaries. Recover an unsuccessful lazy import with a bounded retry or visible Reload control. Avoid automatic reload loops. Release listeners, observers, pending reads and scoped subscriptions on navigation and page hide. Keep a last good same-target snapshot visible during transient refresh while preserving focus and selection.
- [ ] Use one event cursor per global feed and a cursor per active authoritative read. Start snapshot/subscription in the order prescribed by the wire contract, detect cursor expiry/reset, coalesce invalidations, and refresh only visible projections. Check identity/epoch after each await. A stale response for the previous MR never changes the selected state. The browser can retry bounded idempotent reads. A failed command is reconciled by its submission ID. Return a local failure and a Retry control when recovery is exhausted.
- [ ] Verify normal keyboard traversal (rail → queue → divider → tab list → selected document → actions), focus return on close, ARIA labels and reduced motion. Inspect the worked state at 1440px, a 360px drawer and a 390px phone at normal and enlarged text. Trigger a read failure under Findings while the sidebar and other tabs stay usable. Record screenshot/trace locations privately against the fixture revision.

Run `make web-check`, `make web-build` and `make web-test`. Hand the feature owners a stable App composition, operation decoder and active run identity, plus the bounded state/teardown contract. Use the real M1 page and fixture boot paths for feature work. Run the integrated `make check` after wiring returned screen exports. Browser dependency additions belong to the first production consumer and the [resource checks](../../specs/acceptance.md#browser-budgets).
