# PREFUI · Configure connections, scope and automation

**Start after SHELL and ENTRY.** Use the [settings contract](../../specs/queue-and-settings.md) with SHELL’s dialog and selection. Verify the form against the [preferences service](../03-workspace/preferences.md) and [native setup](../../specs/agent-sessions.md). **Outcome** is a first-use setup and editable personal configuration that preserve review history, report exact save results and return the operator to their previous work.

Own `web/src/features/SettingsPane.tsx`, its local editor functions and styling, and typed operations in `web/src/api/settings.ts`. If separate settings editor modules become necessary, move the pane and those private modules together under one settings feature directory and update the shell import in its owner’s handoff. The app mounts the pane with opener/focus return, close and settings-committed callbacks. On successful save notify the shell of the new revision, invalidate affected projections and let the original form refresh any stale launch preview. A settings read has no launch, discovery enrollment or external write side effect.

## Dialog and operations

| Operation under `/api/v1` | Presentation and identity |
| --- | --- |
| `GET /settings` | Load the redacted settings revision, setup/connected/disconnected mode, credential presence, connection/account metadata, boards, repositories and reviewer IDs. Keep the draft separate from this snapshot. |
| `POST /settings/test`, `POST /settings/catalog` | Test only the selected provider/draft. Browse/search its scoped results using an opaque page continuation. Scope each reply to its provider, current connection epoch, query, catalog kind and request sequence. Mark the verified identity only while its inputs still match. |
| `PUT /settings` | Send the whole validated configuration draft, expected revision and explicit secret operations. A blank token means keep when permitted. Display provider/field/setup errors inline, retain dirty edits and offer a deliberate review of newer settings on version conflict. Reopen from the returned saved revision. |
| `POST /settings/disconnect` | Name the provider and effect, ask for an explicit confirmation, then submit with expected revision. Show that future reads pause while registered history remains accessible. Do not request or redisplay a saved secret. |
| Agent preferences | Display current recovery, automatic follow-up and follow-up concurrency from their workflow preference resources. Use `GET/PUT /followups/preferences` for follow-up enablement and concurrency (default 2, valid 1–8) and `GET/PUT /settings/agents/recovery` for `autoResumeCodexReviews` with its own revision precondition and default off. Each change has its own save/acknowledgement independent of connection/scope edits. Show validation errors, actual saved value and effects on existing queued/working reviews. |

## Build and verify

- [ ] Use a labeled native modal dialog with header and close control, one scrollable body and a persistent Cancel / Save changes footer. Open it from the sidebar or a launch/setup issue. Preserve the invoking workspace/draft. Focus the relevant section/field, place errors beside their controls and focus the first invalid field or summary. Escape, Cancel, Close and a genuine backdrop click dismiss cleanly outside a commit. Dismissing discards uncommitted Settings edits and sensitive inputs. A drag that began inside the dialog must not count as a backdrop click. During an in-flight Save or Disconnect, expose busy state and prevent conflicting submit/dismiss. Return focus to the exact opener or surviving workspace heading.
- [ ] Group **Connections**, **Agents**, **Team boards**, **Repositories & agents**, and optional **Additional reviewers** into clear sections. Align provider cards in two columns where space permits and stack on phones. Keep Jira token/type controls together. Show GitLab origin, Jira site/email and scoped/unscoped token type. Render initial empty fields for new tokens and an accessible saved indicator. Changing provider parameters invalidates any prior “Connected as” feedback and pending suggestions. Entry values stay only in the current form. Do not include credentials in browser storage, URL, validation logs, error text or fixture screenshots.
- [ ] Add keyboard-accessible Browse and searchable pickers for boards, repositories and saved filters. After two typed characters debounce 300ms, with Enter for explicit lookup. ArrowDown moves into the results and Escape returns to its search field. Show distinct busy/empty/no matches/denied/partial/error and next-page states. Show full paths for similarly named repos. Exclude existing selections and restore focus on removal. Adding a repository opens/focuses that specific draft editor.
- [ ] For each team board, show enabled/paused state. Resolve Scrum, Kanban and team-managed sprint behavior from the actual catalog. Edit review status IDs, repository associations, optional Jira project/team saved-filter restrictions and estimate field. Require valid review statuses and at least one repository for an enabled board. For each repository allow Selected boards or Any tracked board, local review checkout and separate Claude/Codex default skills found for that checkout. A change of checkout clears incompatible skill choices. Keep additional reviewer identities explicit. Save validates directly. A connection check alone cannot mark incomplete scope saved.
- [ ] Show **Automatically resume interrupted reviews**, **Automatically review replies to my review comments** and the separate follow-up concurrency Save. Explain which selected/queued work is affected by changes, retain a working run on a lower concurrency limit and show exact backend bounds. Turning off auto-resume must reflect durable service state on reopen. Preserve independently saved agent preferences even if the unsaved connection draft is later discarded.
- [ ] In setup, show connection/scope actions and keep local history accessible. On a stale save show the saved revision and a way to reload/review the conflict without silent resubmission or overwriting another tab. On successful save, clear secrets, reflect the returned version across workspace filters, and display any private host setup/cleanup warning separately from the successful settings outcome. Reconcile registered access without changing review identity. Test/discovery errors must not erase other fields.
