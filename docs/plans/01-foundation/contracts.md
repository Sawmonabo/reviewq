# CONTRACT · Share one review contract across service and browser

**Outcome.** Rust can serialize a first-review response, and the browser-targeted decoder can validate and consume those exact bytes. A review, run, native session, source revision, submission and replay cursor remain distinct from construction through the wire. Start from the checked-in scaffold. STORE and the first review consume the accepted contract revision. [Wire specification and route registry](../../specs/data-contracts.md) · [Crate boundaries](../../../crates/AGENTS.md) · [Generator decision](../../dependency-decisions.md#rust-to-browser-contract)

## Owned files and interfaces

| File | First consumer and deliverable |
| --- | --- |
| `crates/reviewq-domain/src/identity.rs` | `ReviewId,RunId,SessionKey,SubmissionId,ActionId,ReceiptId,ReportHash,GitSha,Revision,EventCursor`. Use distinct newtypes, private internals, checked `TryFrom`/`FromStr` and borrowed accessors. Domain stays dependency-free. A verified `MrIdentity` contains canonical origin, bounded project ID and IID. Canonicalization at adapter entry uses the maintained URL parser; domain accepts a validated canonical value. |
| `crates/reviewq-app/src/{access,events}.rs` | `Actor` and validated target/scope; `Snapshot<T> { value: T, cursor: EventCursor }`, `Invalidation`, `ResourceKey`, `Replay::{Batch,Reset}`, `AppError` (place in `access.rs` until a split is warranted). Typed `EventLog: Send + Sync` supports `fn replay(&self, after: EventCursor, limit: u16) -> Pin<Box<dyn Future<Output=Result<Replay,AppError>> + Send + '_>>` for the shared transport-facing trait object. The app needs only standard-library future types here. Replay includes floor/head and ascending cursor/resource tuples. App imports domain only. Transport derives actor scope from trusted credentials. The typed actor is never deserialized from a public request. |
| `crates/reviewq-protocol/src/{common,events}.rs` | Serde DTOs and JSON schemas for scalar representations, success/error envelope, `Page<T>`, event/reset messages and shared error codes. Implement compatibility and serialization independently of app/domain. Consumers map each wire value explicitly into a checked app/domain value. |
| `crates/reviewq-protocol/src/bin/export-schema.rs`, `contracts/v1.schema.json` | Development-only binary emits a stable local draft-07 schema from protocol roots. Register the concrete operation request/success/error shapes that have a caller. Use an optional `schema` feature with the bin target’s `required-features=["schema"]`. Feature-gate JsonSchema derives and schema-only dependencies. An ordinary domain build never invokes web tools. |
| `web/tools/generate-contracts.mjs`, `contracts/generated/{contracts.ts,validators.mjs,validators.d.mts}` → `web/src/api/generated/` at SLICE | Node reads the checked schema and writes TS DTOs plus named ESM, ahead-of-time operation validators and generated type-predicate declarations. At CONTRACT the Node fixture decoder imports these outputs from the development folder with the same ES module resolution used by browser tooling. At SLICE move the generated directory, including its internal modules, to the final browser folder, switch the one Make generator destination and import a type and runtime predicate from the real HTTP client. Remove the temporary output directory. Keep production Knip reachability enabled. |
| `fixtures/contracts/` | A small v1 source fixture carrying a cursor above JavaScript's safe-integer limit, one historical valid v1 plus an additive response-field example. Capture actual Serde output for representative success, failure and event during the verify command. FIXTURE owns scenario data elsewhere. |
| Workspace registrations and commands | The generator uses `cargo run --locked -p reviewq-protocol --features schema --bin export-schema` from the root, then `node web/tools/generate-contracts.mjs --schema <schema-path> --out <active-output-directory>`. Supply manifest dependencies/features, schema exporter root entries, module declarations and `make contracts` / `make contracts-check` to the integration writer. The lead registers the operation and regenerates checked outputs on the accepted base. Future feature owners add their named leaf DTO with their first caller. |

## Implement and prove

- [ ] Enforce distinct domain IDs. Service-issued review IDs are path-safe ASCII. Preserve transferred native/run/receipt values as distinct validated ID types, bounded at 512 UTF-8 bytes at public entry, with no control characters. Validate positive external identities, Git SHA lengths, decimal strings and signed-SQLite upper bound; reject leading zeroes except `"0"`. Use `checked_add` for counters. An immutable `LeadTarget` carries review/run/session and verified provider binding. Keep URL/auth resolution outside domain.
- [ ] Define the concrete `Success<T>{data:T,cursor:EventCursorDto}`, `Failure{error:ErrorDto,cursor:Option<EventCursorDto>}` and `Page<T>{items:Vec<T>,next_cursor:Option<PageCursorDto>}` with lowercase/enum conventions from the spec. Make numeric-string restrictions machine-readable in the schema. Mark null-vs-absent explicitly. Distinguish deserialization constraints on privileged inputs from additive response-field compatibility. For fields with custom Serde behavior, supply a matching Schemars representation and a serialization fixture.
- [ ] Define SLICE’s small protocol leaves `queue.rs,hosts.rs,changes.rs,history.rs` together with its implementers. Freeze only actual first reads/sends: queue page, review overview with run identities and checkpoint, run detail with selected lead, patch file index, scoped native page, delivery receipt. Use the spec’s canonical paths and bounds. The raw patch stays outside JSON. Register the index entry’s nullable strong `patchETag` alongside its own review/revision/file tuple; fixtures cover a missing initial digest and identical bytes on two revisions with distinct anchors. SLICE takes these leaf files at handoff; later worker directories acquire their own sibling modules. Write the normalized target fields, typed actor and stored receipt used by STORE in the handoff.
- [ ] Emit one local-schema artifact with stable definition names and fixed operation-root registry (separate request/response contracts where they differ). Use `SchemaSettings::draft07()`, generate inbound roots for deserialize and outbound roots for serialize. Reconcile shared names explicitly; fail on incompatible duplicate definitions. Keep schema references local, deterministic and content-versioned. Use named concrete envelopes per operation. Publish the exporter's stdout with a trailing LF, stable key order and no path/time stamps. [Schemars settings](https://docs.rs/schemars/latest/schemars/generate/struct.SchemaSettings.html)
- [ ] Compile types via `json-schema-to-typescript` with reachable named definitions, and named validation functions via Ajv draft-07 standalone in ESM mode. Validate actual response envelopes, keeping a safe failure path for unknown variants. Crucial identity and byte checks remain in their owning adapters. Emit one narrow generated predicate declaration per concrete root, e.g. `isDeliveryReceiptResponse(value: unknown): value is DeliveryReceiptResponse`. Place generation dependencies in web devDependencies. Use the pinned Vite library build to resolve emitted runtime helpers. Keep the three named public entry files stable. Emit readable ESM with local relative imports and shared helpers. When output approaches the [code-file limit](../../../AGENTS.md), split by schema resource at generation time and re-export the same names. Verify the generated directory runs in Node and the browser without a global require, runtime schema compilation or undeclared node_modules resolution. Exercise the same byte-bound string validator in both environments. [Vite library mode](https://vite.dev/guide/build#library-mode) [TS generation](https://github.com/bcherny/json-schema-to-typescript) · [Standalone validators](https://ajv.js.org/standalone.html)
- [ ] `make contracts` runs the locked exporter with the schema feature, then the frozen Node generator. `make contracts-check` runs the same pipeline in a clean temp directory and compares **all relative file names and bytes** to tracked schema and generated artifacts, including stale extra files. Check the physical line count of each emitted source file in that same pass. Leave the checkout untouched on drift. Integrate the latter into `make check` via the lead. A feature proposal includes the leaf path, concrete registry symbol, auth class and real payload fixture. Merge/register/generate once on the integrated tree.

## Acceptance

From the repo root run `make web-install`, `make contracts`, `make contracts-check`, `make crate-deps`, `cargo check --locked -p reviewq-domain -p reviewq-protocol -p reviewq-app` and `make check`. Repeat generation after committing/staging the intended output and inspect for added/changed/deleted files under both generated roots. Copy only the generated artifacts to a task-owned temporary directory. Change or add one output there and run the same file comparison against the copy. Expect the changed path to fail, then remove that directory.

Feed actual Rust response bytes to the generated browser predicate. Import the generated DTO and predicate into the development fixture decoder and verify the built module with Node under the locked web toolchain. At SLICE repeat through the production Vite entry. The large cursor survives byte-for-byte, an additive v1 field remains readable, null and absent differ as specified, an unknown mandatory variant fails, and a numeric or overflow cursor fails. Run the scoped Cargo/Node checks as one small cross-language regression if existing tests miss this failure. New generated schemas and fixture rows are data. Do not generate a test per type, route or enum value. The repo-wide cap is 500 first-party test cases counting parameterized examples individually. [Test policy](../../../AGENTS.md)
