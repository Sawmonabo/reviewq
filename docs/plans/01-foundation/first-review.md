# SLICE · Run and independently review the first review

**Outcome.** In an ordinary Codex terminal, link the current conversation to a merge request. A second native chat can find it over MCP. In the browser, read its patch and live transcript, send feedback to that same terminal and reopen the file at the saved line. Deliver this on the production entry points as the first integrated milestone.

## Reproduce from a clean checkout

Use a disposable Linux/WSL user or VM, an independently signed-in task-owned Codex profile, two empty Git checkouts and a fresh desktop browser profile. Pin the selected Codex executable/root and service address for the three terminals. One account runs ordinary foreground `reviewq serve` with its own data, Rust binary and web assets. The production validation mode disables sends. Keep it for read-only visual fixtures. Before PACK is available, the development helper stages the same asset/skill layout and private project MCP grant inside the disposable account. Run only the synthetic GitLab/Jira source for this exercise. Write no settings into an everyday account.

After SLICE is implemented, run in terminal A from the repository root. The implementation must provide the two development helpers used here. Register the temporary root and its two synthetic Git repositories as fixture output in the lead’s cleanup record. `isolated-service` takes absolute file paths, configures only this disposable user's foreground profile and checkout, binds an available loopback port pair, starts the fixture source and prints the dashboard address and readiness identity. It launches the supplied binary with `serve` and arranges PATH for the matching `reviewq link`. It must support Ctrl-C cleanup and reuse of the same profile on restart.
