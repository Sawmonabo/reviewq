# ENTRY · Command line, ordinary-chat management and transport boot

Deliver the operator commands, private checkout setup and seven public management tools. One running service serves the browser, terminal helpers, native hosts and MCP. Each entry calls the same application operation used by its other clients. Start with the first vertical slice's real Codex link and MCP discovery/list/get/read/send. Add the remaining tools and feature commands as their owner contracts land. Keep the initial slice executable while adding them.

**Write** `crates/reviewq/src/cli.rs` (clap parser and routing), `crates/reviewq/src/checkout_setup.rs` (host-local setup, owned file transaction and Git hook), `crates/reviewq/src/native_client.rs` (bounded private HTTP client), `crates/reviewq-transport/src/{entry,mcp}.rs` (guarded listener router and MCP tool adapters), `crates/reviewq-protocol/src/mcp.rs` (typed public tool bindings). Feature modules own their HTTP handlers. The integration owner mounts the router, instantiates services, updates manifests and registers private modules in the binary. [HOST](hosts.md) owns native events/managed skills, [HISTORY](history.md) owns native content access, and [PACK](../06-release/packaging.md) owns release and lifecycle operations.

The delegated contracts are [queue decisions and notifications](../03-workspace/queue.md), [private settings and grants](../03-workspace/preferences.md), [report handoff and evidence](../04-workflow/reports.md), [publication actions](../04-workflow/actions.md) and [monitored follow-ups](../04-workflow/followups.md). The [first review](../01-foundation/first-review.md) exercises the early subset through these same entry points.

## CLI command registry

Retain the working invocations and machine-readable output. Parse all flags/operands before effects. Return 0 for an accepted operation, 2 for usage errors and 1 for an operational failure. ACTION and REPORT implement their first-use CLI adapters in crates/reviewq/src/cli/{action,report}.rs and register them through the SLICE dispatcher as their features land. ENTRY adopts those modules and verifies the complete catalog. JSON commands emit a single payload to stdout. Native report helpers emit the service’s structured handoff acknowledgement on the captured command stream for source verification. Sanitize diagnostics and print the verified run/receipt identity on an uncertain operation. Avoid replaying mutating POSTs on transport failures.

| Invocation | Dispatch and observable result |
| --- | --- |
| `reviewq`, `reviewq open`, `start`, `stop` | PACK starts/reuses the owned user service, waits for readiness, and opens/prints the dashboard for bare/open. Start and stop report the actual service state. Native review jobs survive a ReviewQ stop. |
| `serve [--port N]`, `serve --validation --runtime-root ABS [--port N]` | Installed foreground server (port override applies to this process) or disposable runtime. Validation root must be separate from installed roots, default validation port 8768. Gate all real external writes, native dispatch, notifications and remote polling. No fallback to installed data or credentials. A live-host qualification uses an isolated **installed-mode** test account/profile or explicitly provisioned effect-capable test instance. |
| `status`, `refresh`, `logs`, `notify-test` | Shared queue/status and refresh operations report last success/attempt, error, sprint/queue counts, unread and completion/timeout. Refresh waits for the precise coalesced operation. PACK reads bounded redacted recent UI/service diagnostics and sends one OS notification, returning the actual result. |
| `link TARGET` | HOST reads the validated provider-supplied `CODEX_THREAD_ID`, starts/reuses only the owned service, waits for authenticated readiness without opening the browser, then registers that exact conversation against the configured MR key, URL or unique ticket via the native bridge, and prints its dashboard/run and handoff guidance. Terminal-only identity failure explicitly instructs execution inside that Codex conversation. `$reviewq` invokes this command, and Claude's `/reviewq` sends its own native identity directly. |
| `review KEY SHA reviewed\|waiting_author\|needs_review`, `ack ID...` | Queue decision operation revalidates exact configured MR head then records only the requested local disposition. The CLI omits checkpointId and preserves the prior handled frontier. Notification operation marks the supplied valid IDs seen, preserving pending review work. Validate every ID before changing any. |
| `report complete (--file PATH \| --response) (--reviewed-sha SHA \| --unknown-revision REASON) --verdict VALUE [--assessment-file PATH] [--amend-current]` | REPORT service. Parse source exclusivity, signed-in native lead thread + `CODEX_TOOL_CALL_ID`, canonical regular file or current final response, approved verdict (`approve`, `request_changes`, `blocked`, `not_specified`). Hash file bytes by streaming. Amendment looks up current accepted receipt/hash. Bounded assessment file carries exact thread assessments, changes, section changes, correction/reconciliation evidence, as applicable. Submit once. Print handoff receipt with status and distinct acceptance lookup. |
| `report unchanged [--assessment-file PATH]`, `report needs-input --reason TEXT [--assessment-file PATH]` | REPORT unchanged binds exact accepted receipt/hash/source. Needs-input records the reason. Enforce supported flags and native proof for each outcome. Preserve pending/recorded/failed distinction and previous accepted result. |
| `action declare --intent comments\|approval\|both\|cancel --reviewed-sha SHA [--comments-file JSON]`, `action reconcile` | Publication owner verifies registered lead and native call. Bounded file (≤64 KiB) supplies SHA-256 of each exact body and optional discussion ID. Record explicit user authority at one SHA. Reconcile reads remote note and authenticated personal approval evidence. No repost from an unknown result. Output the typed action receipt/state. |
| `install --from ABS_BUNDLE`, `uninstall` | PACK owns checked placement/host integrations, retained data and rollback. The installer emits the installed build and endpoint. |
| `internal setup-worktree --settings ABS --common-dir ABS`, `internal claude-hook` | Private installed helpers. First checks current checkout plus recorded common-dir and settings binding then reconciles that worktree. Second consumes bounded native hook JSON on stdin with active bound context, returning Claude's hook-format reply. Both work from the stable installed launcher. |
| `--version`, `--help`, `-h`, `help [COMMAND]` | Keep the scaffold version output and ordinary per-command help, with short examples. Hide internal helper commands from normal help. |

Retain isolated `--runtime-root ABS [--port N]` for native report/action helpers, as supported by their source contract. A port override for a helper requires an explicit isolated root and uses only that profile's guarded native transport. In validation mode explicit native evidence fixtures can exercise report parsing and acknowledgement. Live dispatch capability remains disabled.

Native helper mappings are `link → POST /api/v1/native/codex/link`, accepted receipt lookup → `POST /api/v1/native/reports/accepted`, handoff → `POST /api/v1/native/reports/handoff`, recovery of its original acknowledgement → `POST /api/v1/native/reports/handoff-status`, declare/reconcile → `POST /api/v1/native/actions/{declare,reconcile}`. Authenticated Claude `/api/v1/native/actions/input` tells ACTION that a newer real instruction supersedes the previous intent. [HOST route ownership](hosts.md#public-and-native-routing)

## Shared MCP service

Mount **one** `rmcp::transport::StreamableHttpService` at `/mcp` on the existing ReviewQ Tower router. All Claude/Codex management chats use that same endpoint. IPv4/IPv6 loopback bindings route to the same process, application graph and tool catalog. Pin `rmcp 3.11.0`. Use the SDK's stateless Streamable HTTP service with JSON responses. Verify authenticated discovery and tool calls through the installed Codex and Claude clients, and record the negotiated protocol for each. Exercise direct requests with their required metadata and separate server discovery. [MCP versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning.md) Management clients use bounded replies. They do not subscribe a management chat to dashboard SSE or a native history feed. A transport response may temporarily use a request-scoped stream where negotiated by the SDK. [Pinned SDK source](https://github.com/modelcontextprotocol/rust-sdk/blob/165f8fd514afb8f6d1be3e86260ee9abfce58541/crates/rmcp/src/transport/streamable_http_server/tower.rs) · [Official stateless setup](https://github.com/modelcontextprotocol/rust-sdk#stateless-streamable-http)

- Construct one immutable seven-tool definition/route table, one shared store with one reader and one writer and one shared set of provider adapters at boot. The SDK factory may create a lightweight handler **per request**. It clones an `Arc` to the shared application/catalog. Each call authenticates a fresh bearer and carries its own principal/grant epoch, target, deadline and cancellation. Credentials, selected target and native identities stay request-local. Discovery reads only the static tool metadata after authentication. Read committed queue/run summaries through the service's bounded indexed projections. A history read resolves one selected native source and releases its one-shot read lease at completion.
- An idle chat owns zero ReviewQ MCP sessions, per-chat tasks, watchers, polling loops, database connections or provider clients. An HTTP keep-alive socket has ordinary finite transport cost and idle timeout. A registered lead/child is durable workflow identity in SQLite and can outlive every socket. There is no fixed lifetime limit on how many chats/sessions can use the service. Bound **active work** with a fair gate (initial setting 32 concurrent tool calls overall, maximum eight per grant), with at most 64 waiting overall and eight waiting per grant. Queue wait ≤2 seconds and idle HTTP timeout 30 seconds. Bound admitted reads to 30 seconds and mutations to 60 seconds, then reconcile any committed intent through its receipt. Overload returns a retryable busy result. Cancel pending reads when the client disconnects and preserve any already committed mutation receipt. A client can resume inspecting a saved receipt with the same ID. Never carry a previous request's authority on a reused connection.
- Measure 1/16/64 concurrent native-equivalent clients, a burst of 32 mixed operations and ≥10,000 short-lived operations at concurrency 16 including 1,000 reconnect cycles. Keep the normal dashboard open. With two grants, revoke one during activity and show only that grant fails. Observe one PID/listener pair, baseline configured provider/pool/observer counts, bounded active work, reclaimed file descriptors/tasks and a memory plateau after drain. Then run the same endpoint from real Codex and Claude management clients, interleave target-specific submissions, and check distinct native receipts and no cross-chat binding. Document measured headroom and overload behavior. [Shared MCP capacity and thresholds](../../specs/acceptance.md#shared-mcp-capacity)

## Public management tool registry

Use `rmcp` (official Rust SDK, Apache-2.0) with its server/schema and Streamable HTTP server features. Mount its Tower service at `/mcp`, using the existing HTTP executor and shared app services. Use stateless mode, bounded JSON tool replies and the SDK’s protocol negotiation with the installed Codex and Claude clients. Dispatch via `ManagementTools::call(ctx: AuthenticatedChat, tool: ManagementCall, cancellation) → ToolResult`. Each variant below has its own strict DTO in `reviewq-protocol`. Reuse the common input DTO fields where identical. Return standard MCP `content:[{type:"text",text:<bounded JSON>}]` or SDK tool error. HTTP auth errors stay HTTP errors. Do not wrap these answers in dashboard's HTTP envelope. Clap provides its maintained command/help/validation machinery in the binary only. Pin direct versions at first use and record selected features in the workspace lockfile. [Rust MCP SDK transport configuration](https://github.com/modelcontextprotocol/rust-sdk#stateless-streamable-http) · [MCP transport](https://modelcontextprotocol.io/specification/latest/basic/transports) · [clap, license and features](https://github.com/clap-rs/clap)

| Tool and key arguments | Shared responsibility and response |
| --- | --- |
| `ListReviews(filter?,offset=0,limit=25)` | Queue projection over the **configured workspace** including tracked/registered history and current eligible scope. Default `needs_input` selects the dashboard's Awaiting input stage. `agent_questions` includes pending nonblocking questions on Working. Also support `all,working,waiting,archived,unstarted`. Unstarted requires an open MR. Return reason/stage, actual approval, full-MR reviewed SHA, leads, counts, dashboard URL, last sync facts, total and nextOffset. |
| `GetReview(target,sessionKey?,offset?,limit?,report?,questionId?,launchSubmissionId?)` | Resolve a configured ticket, MR key/URL or exact registration. Return MR, lead/child run choices with capabilities/readiness, accepted receipt/coverage, delivery/action/recovery status, pending questions and follow-up monitor/batches. Read bounded report section by source and continuation. Candidate requires exact receipt ID. Accepted and candidate stay labeled. A question detail names the exact Codex request. Optional launchSubmissionId reads the initiating actor’s review-scoped attempt with HOST’s receipt shape even while runId/nativeId remain null. Unknown or unauthorized attempts return scoped not_found. |
| `ReadTranscript(target,sessionKey?,read)` | HISTORY membership check on every page/chunk. `read.kind=page` takes cursor/direction/aroundId and MCP bounds. `read.kind=content` takes the server-returned ref and optional continuation. Returns canonical source generation, entries/chunk, availability and continuation. Exact child targets are readable. |
| `SendReviewMessage(target,sessionKey?,submissionId,text,finding?)` | HOST one durable lead delivery. Optional finding supplies the immutable receiptId and reportHash, with the exact source range and text for a quoted passage. Validate selected report belongs to lead/run. Return submissionId, target, runId, state, attachment ref/hash, timestamps, dashboard. For Claude include companion readiness. Text 1–12,000 chars. An ordinary chat is not linked by issuing this operation. |
| `StartReview(target,submissionId,provider,expectedSha?,invocation?,context?,model?,effort?)` | HOST uses prepared launch and a stable request ID. Invocation discriminates `skill{name,path?,args?}` or `custom{prompt}`. Recheck checkout/source SHA and catalog at confirm, return exact new native session/run and URL. Require explicit launch request. Reconcile the saved attempt before deciding if a new create is eligible. |
| `AnswerReviewQuestion(target,sessionKey?,requestId,submissionId,answers)` | HOST accepts supported Codex asynchronous answers from this management tool. For a live interactive clarification, the operator uses the dashboard or its native terminal. Use a map of question ID to `{answers:[...]}`. Validate the question owner (lead or child matching the target), option rules and native availability, return the same typed receipt/state as browser. Offer the selected session’s terminal for unsupported forms and expired handles. |
| `ConfigureFollowups(target,sessionKey?,action,submissionId,expectedGeneration,...)` | FOLLOWUP coordinator. For `configure` resolve the exact registered lead, list of up to 500 discussion/original note ID selections and `enabled\|paused`. Also accept `pause`, `resume`, `review_now`. Return saved monitor/batch state and dashboard. Use observed discussion and note identities. Callers send a stable submissionId and expectedGeneration (null on first enrollment). Replay with the same fields after a lost acknowledgement. Only explicit instruction changes enrollment. Monitoring authorizes private assessment only. |

Use these bounded MCP tool results. At ENTRY extend the worked fixture with one synthetic seven-call exchange against the shared service. Replay it through the native MCP clients and check the consumed keys and value types.

| Call | JSON result |
| --- | --- |
| ListReviews | `{lastSyncAt,lastSyncAttemptAt,syncFailed,reviews,total,nextOffset}`. |
| GetReview | `{review,runs,total,nextOffset,lastSyncAt,syncFailed}`, plus requested `report`, `questions` and available `followups`. Launch-attempt readback is additive. |
| ReadTranscript | Return the page or content-chunk shape selected by `read.kind`, including its continuation fields. |
| SendReviewMessage | `{receipt,companion?,dashboard}`. Keep submission, run, session, state, reportHash/reportRef and timestamps inside the receipt. |
| StartReview | On confirmed success keep `{session,dashboard}` and expose the launch receipt additively. Pending/uncertain replies identify the saved attempt and contain only proven handles. |
| AnswerReviewQuestion | Return the native question projection for that request, including its resulting status. |
| ConfigureFollowups | Accept the `threads` array and default `state=enabled`. If runId is omitted use the explicitly selected or sole matching lead. Return bounded choices on ambiguity. Return `{followups,dashboard,submissionId}` for keyed readback. |

`target` lookups stay within the current connected service configuration. If multiple MRs or possible leads fit, return bounded exact choices and pagination before mutation. Enforce exact agreement when target and sessionKey both designate a session. MCP list/run results use the existing offset/limit/nextOffset convention, stop at 512 KiB serialized tool result and advance by actual returned count. Reject a single oversized entry explicitly. Use a stable order with identity tie-breakers. Section queries keep the report owner's Unicode-codepoint continuation, separate from transcript byte cursors. Public MCP body cap is 64 KiB and oversized results fail before emission. Avoid hidden refresh, registration, provider process or history watch on `tools/list` and snapshot reads.

## Service boot and repository provisioning

1. `EntryRouter::new(services: AppServices, auth: LocalAuth, runtime: RuntimeMode) → Router` installs the core prefix `/api/v1`, the browser assets and `/mcp`. One process binds exact IPv4 loopback (`127.0.0.1:8766` installed default) for the browser and IPv6 loopback (`[::1]:8767` when available) for native clients. Set IPv6-only socket mode. Pin both actual endpoints and installation identity in private runtime metadata. On IPv4-only hosts use the same verified IPv4 endpoint for native clients. Fail atomically when an expected listener is occupied. Do not follow redirects or forward credentials to unverified origins. Validate Host, supplied Origin and accepted content type before routing. Serve runtime reads with no-store, size/deadline/in-flight bounds and safe error detail. Release handles readiness, lifecycle and static asset fallback.
2. Use the [authenticated readiness and browser bootstrap](../../specs/data-contracts.md#browser-launch-and-service-readiness), including nonce-bound proof over the returned status bytes, before trusting status or sending secrets. Preserve the selected deep-link query through ticket redemption. Use the core browser session/CSRF grant for browser routes and SSE, private service control access for CLI, dedicated installed native bridge for `/api/v1/native/...`, separate repository bearer for **every** `/mcp` request. Read bridge locator/credential from PACK's installation-private `$XDG_CONFIG_HOME/reviewq/bridge.json`, validated ownership/mode (0600), exact installation and verified loopback endpoint. Keep the bridge out of browser/MCP settings. Native provenance separately binds the registered provider, exact lead/parent, turn, call and source for privileged operations. Bearer grants are 32 random bytes, checked in constant time with active settings/binding rechecked just before tool execution. Return 401 with bearer challenge for missing/revoked MCP credentials. Reject disallowed origins. A valid grant permits management of all **currently configured** repositories. Client cwd is a discovery input. The grant authenticates the issuing checkout binding. Never return secrets or native transport errors that include credentials.
3. Implement the PREFS port `RepositoryChatProjection::reconcile(settings_revision)`. PREFS atomically commits the desired checkout bindings, active private grant/epoch and revocations on save. ENTRY reads that committed revision, prepares and applies only owned file changes, then reports applied/pending/cleanup-conflict against the same revision. A newer edit supersedes stale projection, which must reconcile forward or roll back only its unchanged writes. PACK install/update invokes the same adapter, and the Git hook and linked-worktree observer schedule the same projector. File writes and Git processes run outside SQLite writes. Resolve Git top-level and `rev-parse --git-common-dir` canonically, enumerate `git worktree list --porcelain -z`. PREFS binds the grant to the installation, configured origin/project, canonical checkout/common-dir and settings revision. Verify the token hash in the active grant row. Keep provisioning material in private credential storage and a bounded ownership inventory, with a generation check before activating any file replacement. Reuse only the unchanged binding. Configure all existing linked worktrees. Sibling clones/nested independent repositories require their own binding. Revocation takes effect server-side even when cleanup of a modified host config fails. Access reduction works offline.
4. Edit only the private Claude **local/project-specific** MCP entry for the canonical main checkout in its selected `.claude.json` and link its `.claude/skills/reviewq-manage` skill. Configure each Codex checkout's private `.codex/config.toml` `[mcp_servers.reviewq]` block and `.agents/skills/reviewq-manage`. Install the same shared management SKILL.md. Place exclusions in Git common-dir's local exclude file. Detect tracked paths, conflicting MCP names or skill files, foreign symlinks and effective hook overrides before installing private files. Preserve user config, unrelated TOML comments/sections and Claude project settings. Stage same-filesystem replacements, verify expected bytes immediately before replace, rollback only owned unchanged writes. Persist grant/epoch and projection inventory in the private store under PREFS ownership. Export the issuing bearer only into the managed private native client configuration, never diagnostics, ordinary HTTP responses, version control or the hook argv. Normal provider trust remains with its host. [Codex MCP settings](https://developers.openai.com/codex/mcp/) · [Claude local/project MCP scope](https://code.claude.com/docs/en/mcp)
5. Install an owned post-checkout in an empty standard Git hook slot. The branch-checkout callback validates the current common directory and settings revision and requests projection for new worktrees. ENTRY also observes the canonical worktree metadata of configured checkouts through one bounded service watcher and a 30-second fallback scan. This covers existing or changed hook layouts and worktree materialization by Git commands that skip post-checkout. Git continues to execute its hooks and apply its built-in defaults. The hook and observer coalesce requests for the same materialized worktree set. Observer-driven projection is asynchronous after index materialization. The observer uses the materialized worktree as evidence, so it cannot report an independent hook's exit status. Startup reconciles materialized worktrees, and a `--no-checkout` registration waits for an index. An ordinary branch switch preserves the same worktree membership. Revocation releases the watch and removes only unchanged owned files. Report cleanup conflicts by path and redact secret bytes. [Git hooks](https://git-scm.com/docs/githooks) · [Git worktree](https://git-scm.com/docs/git-worktree)
