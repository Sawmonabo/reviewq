# HOST · Native leads, descendants and terminal handoff

Complete the [session contract](../../specs/agent-sessions.md) for terminal-started and dashboard-started Claude Code and Codex. Start with the accepted core identity, storage, app port and first vertical slice revisions. Extend the slice's Codex registration, send and observation path in place. Full MCP, presentation, packaging and publication/follow-up policy have their own owners. HOST implements the opt-in Codex interruption recovery policy. Use the registered native source to establish success for each handoff.

[SLICE](../01-foundation/first-review.md) owns the initial real Codex round trip. Use SLICE’s accepted checkout context and STORE’s persisted settings read to drive the host catalog, launch preparation and recovery eligibility. For HOST qualification, seed a disposable profile with a checkout and each recovery preference value. [PREFS](../03-workspace/preferences.md) then connects its settings editor and post-commit notification to these working operations. [REPORT](../04-workflow/reports.md), [ACTION](../04-workflow/actions.md) and [FOLLOW](../04-workflow/followups.md) compose the store’s shared enqueue operation in their own transactions and wake HOST by the committed outbox delivery UUID. [CHATUI](../05-browser/conversation.md) consumes this API.

The app exposes `register(ReviewTarget, NativeIdentity, RegistrationOrigin) → RegisteredRun`, `prepare(LaunchDraft) → LaunchPreview`, `start(ConfirmedLaunch) → LaunchReceipt`, `send(LeadTarget, SubmissionId, MessageBody) → DeliveryReceipt`, `answer(SessionTarget, RequestId, SubmissionId, Answers) → QuestionState`, `observe(HostObservation) → ObservationOutcome` and `terminal(SessionTarget, OpenOrCopy) → TerminalResult`. Commands accept stable IDs, selected run/session, current ownership and expected revision where relevant. The durable store guarantees idempotent binding, a unique (actor scope, operation, client submission ID) plus matching immutable request digest, atomic claim and compare-and-set completion. Report/follow-up/action services enqueue through the same delivery port. Replaying a UUID with changed target or body is a conflict. Integration owns root/module/manifest edits.

The `NativeHost` port exposes `catalog(HostContext, Checkout) → Catalog`, `inspect(HostContext, NativeId) → NativeSession`, `start(LaunchIntent, LaunchProgressSink) → HostOutcome`, `deliver(ClaimedDelivery, Guard) → HostOutcome`, `interrupt(RegisteredSession, ExpectedTurn?) → HostOutcome`, `terminal_spec(RegisteredSession) → ArgvPlan | ForegroundInstruction`. A progress sink records each proven intermediate ID before the next side effect. A host outcome names observed identity, turn/job and exactly one of accepted, definitely rejected, deferred-before-send or uncertain-after-attempt. Each native event carries provider/session, optional parent, turn, item/call, occurrence ID and native time. An older poll may update availability but cannot replace later lifecycle state. Mark baseline imports so reopen does not generate old alerts.

## Public and native routing

Mount browser operations behind the core browser guard. Use the core `ReviewId` to identify a configured MR. Its canonical GitLab origin/projectId/IID triple is separately validated. All feature JSON uses the core envelope. A positive result must include the target IDs to let the caller discard a response after navigation.

| Route | Input and result |
| --- | --- |
| `POST /api/v1/sessions/register` | Advanced exact `reviewId,provider,nativeId` → registered run. Native link uses target resolution with host-supplied identity. |
| `POST /api/v1/runs/catalog`, `/api/v1/runs/prepare`, `/api/v1/runs/start` | Verify checkout belongs to the selected review. Catalog scopes skill/model discovery. Prepare produces the editable invocation and pinned head/checkout/settings. Start accepts an explicit immutable launch with submissionId, returns its linked run/host status and actual native ID if known. Existing IDs on retry are reconciled first. Batch launch calls this same operation per confirmed MR. |
| `POST /api/v1/runs/{runId}/sessions/{sessionKey}/messages` | Lead only, exact `submissionId,text` (plus immutable finding receipt/quote when applicable) → `DeliveryReceipt{submissionId,runId,sessionKey,state,observedInput,createdAt,updatedAt}`. On `started`, report the confirmed native `{turnId,entryId}` from that exact session. Other states return `observedInput:null`. Read a lost submission response using GET under the original stable actor and operation. Check the exact run/session before returning the receipt. |
| GET /api/v1/reviews/{reviewId}/launches/{submissionId} | Before native creation, persist actor scope, selected review, immutable request digest and submission ID in one transaction. Lookup returns {reviewId,submissionId,state,runId,nativeId,createdAt,updatedAt}. States are pending (durable, effect unsettled), confirmed (native proof), rejected (definitely never created), uncertain (effect may have occurred). Unknown handles are null. After losing a response, query this receipt. An absent/wrong-scope receipt returns not_found and supplies no proof of native creation. Resolve known handles through exact host readback, otherwise retain uncertainty. Same-ID retry returns the existing attempt. |
| Under the same scoped session URL, `GET terminal`, `POST terminal/open`, `POST interrupt`, `GET questions[?requestId=...]`, `POST questions/{requestId}/answer`, `POST recovery/cancel` | Return exact copy command or foreground instruction, open that terminal, interrupt that managed job/turn, read current question state, answer one exact question, or durably cancel this lead's recovery episode. The browser handles unsupported callbacks with terminal guidance. |
| `POST /api/v1/native/codex/link` and `POST /api/v1/native/claude/{registration,link,heartbeat,delivery-check,hook}` | Native installation grant. Validate current profile and source identity. Claude registration looks up existing status, link explicitly writes, heartbeat observes/claims, delivery-check rechecks claim and hook accepts only allowlisted bound input. Include provider protocol version and capabilities. Reject an outdated helper with actionable reload instructions. |
| `POST /api/v1/native/ledger/{record-finding,assess-finding,record-note,list,finish,needs-input,turn-end,readback}`, `POST /api/v1/native/actions/{input,declare,reconcile}` | REPORT/ACTION own handlers. HOST provides exact native tool identity including the calling subagent, the turn-end signal and authenticated event. Superseding actual user input invalidates prior action authority before an automatic continuation. |

Expose `eligibility(LeadTarget, Purpose, ExpectedHead?, ExpectedTurn?) → Eligible | Hold{reason} | Cancel{reason}` and `dispatch(ClaimedDelivery, Guard) → HostOutcome` for the shared queue. Recheck guards immediately before native submission as well as during claim. History's `NativeEvidenceQuery` returns `VerifiedEvidence | Unavailable` for final responses, tool output and user submission observations. Preserve a cancellation that wins before the native send. If a send may already have occurred, mark uncertainty and inspect the same native ID before reconciliation.

## Implementation

1. Resolve the configured provider executable once per operation. Keep its canonical path, selected provider config root (`CODEX_HOME` or `CLAUDE_CONFIG_DIR` with provider defaults), WSL distribution, launch checkout, observed cwd, Git common directory, actual native ID and optional Claude job ID. Store only normalized paths/identity and use the selected root consistently for catalog, socket/job lookup, process environment, history and terminal argv. A management grant checks its issuing repository. A linked review can have a different cwd. Fail on ambiguous profile/socket or deprecated capabilities with targeted native instructions. Run provider binaries with argv, deadline, bounded stdout/stderr, minimal environment and the user's native sign-in. Preserve normal permission and repository-trust prompts.
2. Use one launch-input builder for single, batch and MCP launch. Preserve the original skill path and arguments or custom prompt, user context, output path/format and model/effort. Append the shared [ledger rule](../../specs/review-workflow.md#rule-read-back-and-gate) after that content. Preview the final content sent to the host. This instruction confers no external-write authority. Explicit terminal registration returns the same rule as text the model reads, without starting a turn. Resolve a configured MR by canonical instance/project/IID, URL or unique ticket. For a terminal link validate the host-issued identity first. Start/reuse only the owned service and wait for authenticated readiness without opening a browser. For advanced manual input inspect that exact ID. For managed launch claim its stable actor/operation/submission binding before any native calls, validate current SHA/settings/catalog, then record `pending`, intermediate native IDs, confirmed/failure/uncertain receipt and the link. Check existing receipt before current-head validation on a retry. If creation may have happened without an ID, inspect the attempt and require explicit reconciliation. Never create another thread on that evidence. Reject rebind of an already linked identity. Admit children only through a verified parent in the same run. Never infer an MR from directory, recent history or process name.
3. For Codex use the installed host's `codex app-server daemon version` discovery. Validate bounded JSON, the running provider-owned Unix socket and selected profile. Connect using WebSocket over `UnixStream`, issue `initialize` with advertised supported capabilities, wait for a successful reply then `initialized`. One reconnecting connection per active provider profile dispatches request IDs, server requests and lifecycle events. Use Tokio plus `tokio-tungstenite` without network/TLS convenience features for the local socket. This supplies framing, close and message limits without another native daemon. Pin the crate and verify accepted schema against the exact packaged host version (`codex app-server generate-json-schema --help`). Bound pending requests, deadlines, frame size and decoded bodies. Register cancellation and reject outstanding requests on disconnect. Give HISTORY a read-only method set (`thread/read`, `thread/turns/list`, `thread/items/list`). [App Server protocol](https://developers.openai.com/codex/app-server/) · [Tokio Tungstenite, MIT license](https://github.com/snapview/tokio-tungstenite)
4. Discover Codex skills via `skills/list` in the selected cwd, enabled entries only, preserving name/scope/path. Read `model/list` pages and each model’s native efforts. Distinguish default from explicitly selected. Start with `thread/start`, record the returned exact thread, name it, then `turn/start` with a structured skill item and text/context or the custom prompt. Record requested settings separately from returned settings. For an active eligible turn use `turn/steer` with `expectedTurnId` and the durable outbox delivery UUID as `clientUserMessageId`. For idle/saved use exact `thread/resume` with bounded turns excluded, recheck ownership/eligibility, then `turn/start` with that same delivery UUID as the native input correlation. Ordinary input and automatic actions have different priorities. Hold through native approval/blocking flags. Use `turn/interrupt` only against a known managed active turn. Record the native outcome when it arrives. A disconnected read retries with backoff. An ambiguous mutation moves to reconciliation through native observations.
5. Correlate Codex blocking `item/tool/requestUserInput` to this connection's single-use request handle and exact session/turn/item. Render supported fields. Validate complete supplied question IDs, option labels, choice cardinality, “Other” and secret flags. An accepted socket write is `submitting` until matching native resolution. Distinguish answered, closed, unavailable and uncertain. Disconnect/restart invalidates all live handles. Recognize supported asynchronous user-input tool records from verified source fields. Permit a correlated human reply only while still pending. Store ref/flags and submission ID. Secret async responses and unsupported/native approval methods stay in the CLI. A request with the shape of a form can still be an approval. Use verified request kind/origin and fail closed on ambiguity. Preserve original labels including nonblocking questions while work continues. [Codex form and approval semantics](https://developers.openai.com/codex/app-server/)

Stale receipts/denials cannot shadow a newer native event. Verify child ownership before forwarding deltas. Forward an exact registered `AskUserQuestion` through the shared question interface. For Codex, install the `Stop` and `SessionStart` user hooks, leave their trust to the user and name a hook that has not reported. ## Interruption recovery

Implement the recovery consumer for **Automatically resume interrupted reviews** in HOST. PREFS subsequently implements and verifies its public settings route. GET/PUT /api/v1/settings/agents/recovery returns {autoResumeCodexReviews,revision} in the core envelope. PUT accepts the new value and the independent preference expectedRevision. After commit PREFS notifies HOST to cancel or wake eligible episodes. Default off. Only a confirmed terminal Codex failure of the registered lead, classified by structured error as usage limit, model capacity or access interruption, starts an episode. Persist failed turn, observed MR head, account/model/effort/provider, episode, previous capacity boundary, next attempt, last dispatch/submission, status and cancellation reason. A plain disconnect stays a read/connection problem. Human-visible waiting labels distinguish Usage limit, Model busy and Reconnecting. Disabled/cancelled recovery offers an explicit manual continuation.

- Fetch one shared, fresh native `account/rateLimits/read` after the failure. Validate account, explicit ordinary usage allowance, matching model bucket, spend controls and reset state. Missing fields, elapsed estimates, old cached allowances or a changed account read racing disconnect provide no proof. Usage/access grant a single continuation for the verified allowance boundary. A second such failure waits for a newly proven account/access/reset boundary. Model capacity retries with increasing persisted delays from 30 seconds capped at five minutes, while still checking fresh allowance. Limit new automatic starts across runs and prioritize human deliveries.
- Before claim **and** immediately before `turn/start`, re-read open MR/head, lead ownership, failure turn, absence of newer work, native inactive flags, effective resumed model/provider/effort, permission/question state, pending/manual/uncertain messages, report receipts and competing follow-up/publication work. Preserve prior authorization unchanged. Cancel on disable, explicit stop/cancel, new user work, newer run/turn, closed/changed MR or completed report. Hold on unresolved metadata/receipts. All sends use the same outbox submission identity and inspect the native client marker after restart. Claude host usage policy remains native.
