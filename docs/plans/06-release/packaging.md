# PACK · Install and update one local ReviewQ service

**Goal.** A user can install from a built directory, leave the source checkout, open the dashboard, close the terminal and continue using both native hosts. Updating a release preserves the active profile and outstanding work. [Operations contract](../../specs/operations.md)

**Needs.** ENTRY, QUEUEUI, REVIEWUI, CHATUI and PREFUI. Consume ENTRY's command dispatcher and checkout-grant reconciler, HOST's two working native integrations, the integrated production web build and STORE's supported-format probe. PACK may assemble a development bundle earlier. Installation acceptance uses the complete product. Exercise a fresh install and a same-schema update using separate disposable profiles.

## Ownership and build

| File | Implement |
|---|---|
| `tools/package/assemble.mjs`, root `Makefile` integration patch | Supply the integration writer with `make package` and its build prerequisites. Build with the workspace lock and the locked Vite toolchain. Stage the directory below into a private temporary sibling and publish it only after manifest validation. Accept an already built web directory from `make web-build`. |
| `crates/reviewq/src/install.rs` | `install(bundle: &Path, paths: &InstallPaths) -> Result<InstallReceipt>`, `uninstall(paths: &InstallPaths) -> Result<RemovalReceipt>`. Own inventory, durable activation journal, host activation, in-flight rollback and retirement of prior releases. |
| `crates/reviewq/src/service.rs` | `start`, `stop`, `open`, `logs` and readiness checks for this systemd user service. Consume the same local profile resolver used by the foreground executable. Implement the six-key [startup configuration](../../specs/operations.md#configure-the-local-runtime), its default/override rules, owner-private installation and verified endpoint handoff. Emit the resolved `runtime.json` path in install/status. ENTRY wires the commands once. |
| `crates/reviewq/src/install/start_door.rs`, `crates/reviewq/src/start_door.rs` | `reviewq-start.socket` with `Accept=yes` and its per-connection template `reviewq-start@.service`, rendered by the installer from the current browser port and installed executable rather than shipped as templates, so `reviewq start`, `reviewq open` and the running service can re-render them to repair the start door. ReviewQ owns a file when its first line is the fixed start door marker. The hidden `reviewq start-door` command answers one connection and starts the service on a valid start. [Start door](../../specs/operations.md#start-door) |
| `packaging/reviewq.service.in` | Per-user unit, absolute installed executable plus `serve`, escaped as a systemd argument, `Restart=on-failure`, five-second restart delay, private umask, `WantedBy=default.target`. Supply absolute XDG/profile locations used at installation so the user manager and terminal resolve the same profile. |
| `hosts/`, `web/dist/` | Copy HOST's staged files and WEB's production output. Host code, project MCP grants, web rendering, store initialization and shell argument parsing stay with their respective implementation owners. |

Run `make web-install`, `make web-build` and `cargo build --locked --release -p reviewq` from the root (the package target calls the latter two). Determine version from Cargo metadata, architecture/OS from the actual target, and revision from the source build. A candidate for qualification must identify the exact source tree. No dependency install occurs on the user's machine. Packaged contents:

```text
target/package/reviewq-<version>-<target>/
  manifest.json                 # format, version, target, source, protocol and current store format, files
  bin/reviewq
  web/index.html, web/assets/…  # also copy every referenced public file
  web/manifest.webmanifest, web/icon-192.png, web/icon-512.png
  web/worker.js, web/stopped.html  # one service worker; the page it shows when ReviewQ is stopped
  hosts/claude/.claude-plugin/marketplace.json
  hosts/claude/plugin/.claude-plugin/plugin.json
  hosts/claude/plugin/hooks/{hooks.json,register.jsx}
  hosts/codex/skills/reviewq/{SKILL.md,agents/openai.yaml}
  hosts/shared/skills/reviewq-manage/SKILL.md
  packaging/reviewq.service.in
  licenses/…
```

The marketplace entry points to `./plugin`. Include each additional host-required asset referenced by the manifests. Use the same deterministic host plugin and marketplace version for those bytes. A changed host bundle needs a new host version to invalidate Claude's cache. A rebuilt candidate at an occupied version/target path with different bytes reports conflict. Generate hashes over sorted relative paths, modes, sizes and SHA-256 file digests in canonical UTF-8 JSON. Compute the bundle ID from the manifest bytes, excluding the manifest from its file list. Reject symlinks, duplicate entries, absolute or escaping paths, unknown required format, omitted/extra files and mismatched bytes. Run the staged executable's version/help, resolve the web entry and lazy asset references, validate the Claude plugin and marketplace with the selected host. Record the host version and platform loader. ## Implement the activation

- [ ] Preflight the managed launcher, service unit, installation root, current link, skills, plugin/marketplace origin, settings-controlled grants, OS notification registration and supported store format. A pre-existing unrelated entry returns its path and exits before switching anything. Verify the current schema before changing a retained store or switching an installed release. Capture reversible portions, before/after digests and the prior service enabled/running state in the private journal. Host config changes must use the host or ENTRY's ownership-aware edits.
- [ ] Take the per-installation OS file lock. Serialize every mutation through one persistent lock file outside replaceable releases. Never remove that file while another process may hold/open it. Revalidate preflight under the lock. Stage into a unique directory on the installation filesystem. Sync and verify copied bytes and publish the directory by digest. Keep the prior complete bundle until operational readiness, then remove verified inactive bundles and obsolete owned copies. Serve the active assets directly. Stage old-only fingerprinted files for the preceding distinct web build before switching HTML, and keep that same set across byte-identical web updates. A fingerprinted path shared by both builds must match the complete bytes. A tab from the preceding build can fetch an unloaded chunk after an upgrade.
- [ ] Quiesce the owned service for the switch, finish or record outstanding local writes and let unknown external outcomes retain their identities. Verify the quiesced profile still matches the candidate's store schema. Journal each effect before issuing it, including intended previous and new targets. Use atomic same-directory replacement for pointers and private config files, then sync their parent. Prevent a second daemon from opening this profile, even if it requests a different port. Refuse an occupied listener without sending credentials or signaling its owner.
- [ ] Install the stable launcher and user unit, then create HOST's private bridge locator/credential for this installation as needed. Expose the explicit Codex skill from the active `hosts/codex/skills/reviewq` directory under the selected Codex user's skill directory. Preserve the skill's explicit-invocation metadata. Install Claude with `claude plugin install reviewq --marketplace <absolute-current>/hosts/claude --scope user`, update on a version change using the same managed marketplace and `claude plugin update reviewq@reviewq --scope user`, and read back the loaded source/version. Use `claude plugin list --json` for installed version/scope and the host marketplace inventory for its source. Change only the marketplace and skill link whose recorded owner, path and target still match. If the host cache keeps another managed version on rollback, uninstall that package with `--keep-data`, install from the restored known source and recheck. A provider capability missing on this machine is reported by name. Reload existing Claude sessions with the host's `/reload-plugins` to load updated code. [Claude plugin commands](https://code.claude.com/docs/en/plugins/cli-reference) · [Claude manifest paths](https://code.claude.com/docs/en/plugins-reference)
- [ ] Call ENTRY's implementation of `RepositoryChatProjection::reconcile(settings_revision)` for configured local checkouts after Claude changes its settings. Use the stable shared management skill path under current. Keep native project configuration, existing worktrees and future-worktree setup private and scoped. Install WSL's owned per-user `Personal.ReviewQ` notification identity/icon when WSL interop is present. The Linux desktop sender reports unavailable when the session notification service is absent. Start the owned unit. Use the active private descriptor and challenge-authenticated `GET /api/v1/status`, then verify the response proof, installation identity, build digest and store readiness. [Startup handshake](../../specs/data-contracts.md#browser-launch-and-service-readiness) Release operational writes only after the activation identity and current store have been accepted. Print the dashboard URL, active build and any host reload needed, without credentials.
- [ ] Recover an interrupted install on the next explicit installation invocation under the same lock. Compare actual and journaled values. An already-applied step with the expected digest is complete. An unapplied step can proceed. A third value is a conflict that must preserve the newer value. A failed same-schema switch can restore the previous binary against current data only after verifying that binary's exact store schema and host assets. Restore only the entries this activation still owns, and retire the verified failed candidate once rollback has completed. A rollback retires the start door socket and removes both door files; a previous release that has the door puts it back once its service is up, and the install record gains no field an older release could refuse. [Recovery table](../../specs/operations.md#recovery-and-removal)
- [ ] Uninstall through the current launcher. Stop the start socket and any running door, and disable the socket, first, record the removal, then stop/disable the unit, verify the retained store, revoke managed repository grants, remove the owned Codex hooks and exact Codex link, uninstall only the matching user-scoped Claude package using its keep-data option, remove the owned marketplace and bridge, remove verified release, current-link and launcher entries individually, remove both start door files and reload the user manager. Recheck each before deleting. Preserve user-edited collisions, report them, and allow a second run, or the next install, to finish. Then reset the install record. Without `--delete-data`, the shared data root keeps the retained workflow database, and state, settings, private reports, backup generations and native histories stay. With it, delete only the [owned data](../../specs/operations.md#owned-data), marking the record only once the deletion's checks pass, and delete the record last. Exit with an error only when a removal failed; entries kept by rule are listed with exit status 0. Remove the WSL notification identity last of all, so the failure notice can still use it; one Windows cannot remove is kept in the record for the next uninstall or install. Native histories and `install.lock` always stay.

Use the standard Rust file-lock, exclusive-create, sync and rename operations on these Unix targets. The service manager handles supervision and reboot behavior. SHA-256 can reuse RustCrypto `sha2` (MIT/Apache-2.0) in Rust and Node's built-in crypto when assembling. These choices add no runtime package manager. Compare installed bytes, runtime dependencies and update cost on the actual target. [Rust file APIs](https://doc.rust-lang.org/std/fs/struct.File.html) · [RustCrypto SHA-2](https://docs.rs/sha2/latest/sha2/) · [systemd service lifecycle](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)

## Verify

In a disposable Linux/WSL account with its own user manager, run the packaged `bin/reviewq install --from <absolute-bundle>` from outside the checkout. Repeat concurrently. Expect one active digest, one daemon, one enabled unit and one managed entry per host. Use `reviewq`, `status`, `stop`, `start`, `logs` and `notify-test`. Reopen an ordinary and a registered session on both hosts. From the installed ordinary MCP clients, start the first native Claude and Codex reviews on their separate eligible targets. Check emitted receipts and identical-request replay against the native leads using the [ordinary-chat start procedure](release-check.md#start-a-new-review-from-an-ordinary-management-chat). This also verifies that scoped MCP configuration and the shared management skill survived installation. After switching to a distinct web build, use a pre-upgrade tab to load a previously unopened lazy view before reloading it. Repeat with an identical-web update and verify the preceding asset set survives. Check for one complete bundle and no duplicate current assets. Record file digests, actual PIDs, qualified host versions, URL, observed notification and release readbacks. Interrupt the installer on both sides of the pointer switch and after a host update. Retry, then run uninstall twice including a user-edited unrelated entry. Check the data independently before and after. Use the release binary for a repeat uninstall after the launcher is gone. A CLI flag or host/desktop result unavailable on this host stays unverified in the [release record](release-check.md).
