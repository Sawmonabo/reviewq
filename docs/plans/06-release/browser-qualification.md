# BROWSERQA · Qualify a working review on the desktop

**Outcome.** A reviewer can tell, from the candidate's actual controls and measurements, whether it opens promptly, scrolls without flicker, stays within its resource budgets and delivers feedback to the right agent. Qualify the integrated bundle after PACK, with all feature/host paths active. Earlier measurements begin on SLICE. A `gpt-6.2-sol` worker at `xhigh` runs the repeatable harness. An independent `gpt-6.2-astra` reviewer at `xhigh` repeats the desktop workflow and hands the exact bundle's results to RELEASE. The physical-device check needs an operator at that device.

Use [acceptance](../../specs/acceptance.md), [browser behavior](../../specs/browser-experience.md) and the [portable workload](../01-foundation/fixtures.md). The builder supplies the tested bundle and the manifest generated from the checked-in fixture. A separate reviewer operates the actual browser and one real native session, checks input/source identities independently, and reviews the worst trace before recording the outcome.

## Workload

| Path | What to do and inspect |
| --- | --- |
| Cold open | Start at a blank tab, visit the queue, then open an MR from a clean workspace. Separately use a deep link directly into Changes for Quiet, Active and Large. Read the first correct row/thread, use a real control and Find the offscreen tail. Measure queue and direct-open boundaries separately. A cached bundle or service patch makes a warm sample. |
| Switch and return | In one tab cycle **Active → Quiet → Large → Active** from the real queue. Each MR opens on Overview. Time the row click to confirmed Overview, then activate Changes and independently time the selected patch. On Active keep a draft in Agent and a known reading position in both Agent and Changes. Measure **Agent → Changes** until the file/line is restored and **Changes → Agent** until the native message and loaded body return. Switch back to a lead after visiting its child. Check selected run, preserved logical anchor, draft, focus destination and the first painted target. Delay one completed read past the next selection. No late title/body, agent message or draft may leak across projects. |
| Fast and slow scrolling | Use 1,200 and 12,000 lines with 2 initial discussions, then the rich/wrapped/dense-discussion preset and a 10,000-item transcript. Scroll during an unchanged notification and during same-revision insertions below and above the selection. Expand/collapse a long thread or tool and load a diagram above the viewport. Use a fast wheel/trackpad fling, thumb jump, PageDown, arrows, Home/End, touch on a touch target, reverse direction and return. Check filmstrip for blank stripes, all-white frames, old/mixed content, jumps and motion stalls. |
| Text and controls | Use browser Ctrl+F near the unvisited end, select three mixed lines across a wrap, copy and compare actual clipboard text/order. Check line number and link, code styling, tabs, Unicode/bidi, zoom and narrow wrap. Inspect accessible tree/order and activate the same controls with a screen reader and keyboard. Use IME composition, Shift+Enter, Enter and the send button. Follow a safe link and inspect a malformed diagram’s fallback. Test a viewport of 1440 × 1000, a 360 px drawer, a 390 px phone, browser zoom 200% and reduced motion. |
| Live reading and delivery | In the selected Agent pane, stay above the tail while a native reply arrives. Page older data, select an excerpt, expand tool output, edit the draft and navigate away/back. Return to tail. Disconnect the event stream, change the source, restore it, send one ordinary message and one quoted, receipt-bound finding to a task-owned lead. Verify the source/correlation ID after the native turn; inspect a second run for zero copies. An old report opens against its own hash. Repeat the browser side with a request accepted but its reply lost. |
| Whole product | Work from the busy queue, ticket, overview, findings, notifications and settings into the same Agent/Changes path. Exercise a missing source, an initial empty screen, a current head change, a stale provider read, partial results and a failed/retried lookup. Check desktop/phone layouts including clipped titles, focus/escape, keyboard-only filtering and scroll containment. Open a second tab on the lookalike MR; each keeps its own selected run/draft. |
| At the data limits | Pin a transcript range and focused control that fully occupy the six-page/8 MiB budget, trigger a seventh page and multiple live events. Verify the existing text/focus, same retained-byte/page count, zero excess body fetches and one deferred invalidation. Clear selection or jump to latest. Only then may the reader evict and fetch, and it must land at the correct native marker. Open an over-limit patch, long single line and over-limit report/diagram, using the [source-mode contract](../../specs/browser-experience.md#full-document-and-bounded-source-modes). Check the declared reduced Find scope, byte-bounded ranges and exact tail marker/clipboard. Quote a bounded source range against its actual receipt/hash, stream a complete download and compare its digest. Publish a different revision with identical patch bytes/ETag but changed thread anchors. Check revision-specific thread placement. For an unknown patch ETag, validate identity/headers on the first selected range, then require If-Match for subsequent ranges. A 412 reloads the file index. Close/switch during transfer. Verify only admitted ranges or streaming buffers were retained and canceled sources release credit. |
| Link and receipt recovery | Open a notification link with its reviewId, runId and `tab=agent`. Track the same MR by its GitLab URL and open the same registered conversation. Pair the other project's same-IID review with this run and verify the invalid-target view. Lose a real MCP `StartReview` acknowledgement after admission; read its pending or uncertain receipt with `GetReview(target,launchSubmissionId)` under the initiating grant. Use the HTTP lookup for a browser-initiated launch with the same client ID and verify that each surface recovers its own attempt. Confirm one native launch. [Wire contract](../../specs/data-contracts.md) |
| Concurrent clients | Have 16 then 64 clients discover/read via the real MCP listener as two real agent terminals and a headed browser remain in use. Measure the browser switches and typing during the [MCP capacity workload](../../specs/acceptance.md#shared-mcp-capacity). Inspect the busy fixture with 506 registrations for zero transcript hydration from queue/Changes, shared active readers and released leases. ## Measurement recipe

1. **Identify the experiment.** Record source revision, Rust executable and web asset digests, fixture preset/version/digest and output path, OS/build, CPU/RAM, available RAM, browser/version/profile, GPU mode, device scale, viewport/zoom, panel width, input device, display refresh rate, thermal/power mode and relevant extensions. Run the candidate with identical data and production assets for each repeat. The primary physical setup is headed Windows Chrome reading the WSL service. Use the same-machine, same-profile blank tab as an overhead control. Headless CI is a separately labeled reproducibility check.
2. **Get actual transaction boundaries.** Use monotonic browser marks around navigation/user input, network timings and the first correct presented frame. Require the right MR/run/revision, first selectable line, expected thread where present, loaded fonts, enabled controls and a working click. For cross-MR switches record two independent spans. Start the first at the MR row click and stop at the first frame showing that MR’s confirmed Overview and operable tabs. Start the second at the Changes activation and stop at the first frame meeting the selected patch criteria, including the correct thread or Quiet’s loaded empty discussion state. Apply SWITCH’s ordinary/Large thresholds only to the latter span. If recording an end-to-end total, fix and report the interval between those two actions. For Agent → Changes also require the restored file, logical line and offset. For Changes → Agent require the restored native entry with its loaded body and offset, or the correct tail when following. Mark service event publication, event receipt, DOM update and first presented frame with a common event ID. For cross-process clocks establish the monotonic offset/uncertainty with repeated local round trips or report each stage on its own clock. For user input, mark the input event and presentation of the committed character, selection or disclosure. Record view, bytes/hashes, status/ETag, queue delay, DB/provider/service time when available and cache state. A spinner, response completion, title alone or a second animation callback cannot establish the end point.
3. **Repeat.** On the standard fixture collect 20 cold observations per review size, fresh browser process/profile and a freshly restarted application with empty application caches each time. Retain the same persisted fixture. Record OS file-cache state without claiming disk coldness. Rotate Quiet/Active/Large order across repetitions. For each directed switch/local input/live update collect at least 30 samples in a full working tab, including first return after eviction. Keep idle and streaming runs distinct. Report raw samples, sample count, median, nearest-rank p95 and maximum per workload/direction. Preserve failed or timed-out runs with their bound. Isolate traces/filmstrips in additional passes so instrumentation cost is visible. Run one observed representative session as well as the deterministic fixtures.
4. **Inspect presented frames.** In the fixed scrolling pane start at scrollTop 6,500 CSS px and make a 9,500 px gesture at 8,500 px/s if the document permits. Verify final position and at least one known visible row. Repeat against ordinary, large and rich inputs, first without a change, then trigger a real same-revision discussion invalidation during the gesture. Trace the gesture and the publication/DOM application separately. Confirm the refresh mark occurred between gesture marks, with at least one presented frame on either side. Keep native-format Chromium traces with compositor, input, latency, frame presentation, user timing and frame screenshots. Use Perfetto's Chrome Scroll Jank V4 metric restricted to the gesture, with presented and janky frame counts, missed vsyncs, durations, dropped/partial frames, frame intervals and pipeline reasons. Reject empty traces, wrong scrollers, lost events or unmatched IDs. Repeat at least five gestures per size/input/refresh condition. Compare intervals with the real display period. Inspect the filmstrip at the worst stall plus the beginning/end of each switch. A frame counter alone can look regular while text is blank.
5. **Verify the physical interaction.** On the user's representative screen, perform normal and rapid trackpad scrolling during live output. Inspect at native display refresh, including a high-refresh pass when qualifying high-refresh use. Use the real browser's Find, clipboard, text selection and accessibility tools. Record any reproducible flicker or stutter with the review, line, direction, event and timestamp. Include snapshots at the top, selected line, wrapped/zoomed and returned states. Compare known text, alignment and controls against the fixture and [screen contract](../../specs/browser-experience.md). Measure motion with compositor traces/filmstrip; a static image can only verify its captured position.
6. **Attribute RAM and retained work.** Use Chrome's visible per-tab memory display on the representative profile and note its displayed unit and update cadence. Associate the active main frame with its renderer PID via CDP/trace. On Windows record working set and private working set in MiB. On Linux record RSS and private/PSS when available. Record Rust daemon RSS/peak, GPU process/allocation if attributable, JS heap, DOM count, active subscriptions and decoded/retained bytes independently. Sample process counters at 250 ms through navigation, at 5.5 s after usable content, at 30 s idle, and after returning to Quiet. Mark the closest displayed tab-counter samples as such, with timestamp. Do not substitute forced GC or add shared memory across processes. Retain idle queue, active native session, quiet return and selected 12k document as distinct rows.
7. **Check sustained use.** For 30–60 minutes cycle all three reviews, active/quiet transcripts, report/diagram, differing revisions and run switches, covering at least 30 complete cycles. Include normal pauses for reading and typing, a disconnected interval, resumed live updates, two busy-queue refreshes and closing/opening the panel. Every five minutes sample the same Quiet state at 30 s idle and record tab/process counters, retained data, request counts/bytes and subscription count. Inspect the final quiet return and the post-warmup trend alongside absolute peaks. A freshly reopened browser does not exercise retention. In the network log confirm zero inactive patch fetches, scrolling alone fetches no extra patch, and a same-revision discussion update retains its original patch bytes/text nodes. Bounded history loads on paging are expected.

**Controlled renderer RAM.** Use Windows Chrome headless at 1440 × 1000, standard scaling, the production bundle and the worked Active and Large fixtures with two initial discussions. Record machine and Chrome build, fix them across all repetitions, use a fresh browser process and profile for each cold open, and leave garbage collection at its default. Mark readiness at the first correct selectable patch with the expected inline thread, loaded fonts and operable controls. Sample the active main-frame renderer’s working set in MiB 5.5 seconds later. Publish all 20 samples per size, the median and range, and compare each median with its absolute [RAM budget](../../specs/acceptance.md#browser-budgets). Separately perform the real headed scroll, reconnect and send exercises on the representative desktop.

For **continuous** wheel/trackpad scrolling, apply Scroll Jank V4 only to actual scroll updates in the marked gesture. Log its eligible denominator, NULL/unavailable or inferred presentation rows and the metric version. Exclude no-update frames from the denominator. A missing/lost trace or zero eligible frames leaves the metric unverified. Use actual presented damaging-frame timestamps and the filmstrip for key jumps, discrete thumb drops, switches and other discrete changes. For headed motion, observe any real flicker between frames present in the filmstrip. Document sampling gaps. A script mark proves request timing; it cannot certify a rendered/presented frame.

## Decide

Compare every scenario with the [budget table](../../specs/acceptance.md#browser-budgets). Record sample values against the threshold, including the slowest input, affected file/line and exact run. An observed wrong-target send, missing native search result, clipboard mismatch, unstable reading anchor, repeated flicker, blank frame or persistent new stutter fails its workflow even when median RAM or latency improves. A repeatable missed numerical budget requires triage on the same build/fixture. Separate environmental noise from a product issue using an independent repeat and trace. Report unsupported/high-refresh hardware, actual tab counter, real-host or accessibility proof still outstanding as unverified for the affected claim. Save this run's metrics and recordings to a caller-chosen output directory. The operator’s absolute everyday tab RAM limit is a separate open decision. Give RELEASE the exact artifact qualification and concrete results for that decision.
